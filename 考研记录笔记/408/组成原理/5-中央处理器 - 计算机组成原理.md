# 中央处理器【\*非重点；※重点】

# 一、 CPU的功能和基本结构

## 1.1. CPU的功能

由控制器实现：
- 指令控制：
	- 完成取指令、分析指令和执行指令的操作，即程序的顺序控制。
- 操作控制：
	- 管理闭关产生由内存取出的每条指令的操作信号；
	- 把各种操作信号送往相应的部件，从而控制这些部件按指令的要求进行动作。
- 时间控制：
	- 对各种操作进行时间上的控制。
- 中断处理：
	- 对计算机运行过程中出现的异常情况和特殊请求进行处理。

由运算器实现：
- 数据加工：
	- 对数据进行算术和逻辑运算。
> **注意**：PSW程序状态字属于运算器的组成部分。
> PSW两个部分：状态标志(进位、零等)、控制标志(中断、陷阱标志)。

## 1.2. CPU的基本结构

**CPU = 运算器 + 控制器**

### 1.2.1. CPU寄存器的分类

#### （一） 用户可见的寄存器

用户可对这类寄存器 **编程**。
> **如：通用寄存器，PSW，基址寄存器(用于实现多道程序设计或者编制浮动程序)，状态/标志寄存器。**

#### （二） 用户不可见的寄存器

**特点**：
- 对用户透明；
- 保留各种状态信息(*溢出标志OF、符号标志SF、零标志ZF、进位标志CF*);
- PSW中的这些位参与并决定微操作的形成；
- 不可对这类寄存器编程。
> **如：MAR、MDR、IR、微程序控制器CM。**


### 1.2.2. CPU易混淆点

**转移指令**时：需要判别转移是否成功。若成功则PC修改为转移指令的目标地址；否则下一条指令的地址仍然是PC自增后的地址。
**计算机分两大部分**：**控制部件和执行部件**
- 控制器就是控制部件。(指令寄存器、操作控制器、程序计数器都是控制部件)
- 运算器、存储器、外围设备就是执行部件。
**各寄存器的位数等于什么？**【和 *地址* 有关的就取决于机器字长；和 *数据大小*  有关的就取决于容量】

| 通用寄存器 | PC    | IR   | MAR  | MDR         |
| ----- | ----- | ---- | ---- | ----------- |
| 机器字长  | 存储器容量 | 指令字长 | 指令字长 | 机器字长=CPU的位数 |

## 1.3. 运算器和控制器对比

### 1.3.1. 运算器

**功能**：
- 接收从控制器送来的命令并执行相应的动作，对数据进行加工和处理；
- 运算器是计算机对数据进行加工处理的中心。

**组成**：
1. **算数逻辑单元(ALU)**：进行算术/逻辑运算；
2. **程序状态字寄存器(PSW)**：
	1. PSW 存放程序状态字，用于保存系统的运行状态；
	2. PSW 包括 **状态标志和控制标志**；
	3. 溢出标志OF，符号标志SF，零标志ZF，进位标志CF；
	4. 中断标志，陷阱标志。
3. **累加寄存器(ACC)**：
	1. 是一个 **通用寄存器**；
	2. 暂放 ALU 运算的结果信息，可作为加法运算的输入端。
4. **通用寄存器组**：
	1. 如 AX，BX，CX，DX，SP；
	2. 用于 **存放操作数和各种地址信息**，所以 **其位数与机器字长相等**；
	3. SP 是堆栈指针，用于指示栈顶的地址。
5. **暂存寄存器**：暂存从主存读来的数据，对应用程序员透明；
6. **移位器**：对操作数或运算结果进行位移运算；
7. **计数器**：控制乘除运算的操作步数。
> **注意**：暂存寄存器可以接收主存/cache传来的数据，是为了让ALU在流水线中能够稳定地拿到操作数，不受上一级访存或写回的延迟影响。

### 1.3.2. 控制器

**功能**：从主存中取出指令，分析指令并产生有关的操作控制信号。

**组成**：
1. **程序计数器(PC)**：
	1. 用于 **指出下一条指令在主存中的存放地址(PC总是存放指令地址)**；
	2. PC有 **自增功能**(增加的是指令长度)；
	3. PC的值会根据 CPU 在执行指令过程中 **自增** 或 **转移到程序的某处([跳转指令](<4-指令系统 - 计算机组成原理.md#### （二） 跳跃寻址>))**；
	4. PC 的 **位数取决于存储器的容量**。
2. **指令寄存器(IR)**：
	1. 用于保存 **当前正在执行** 的那条指令；
	2. IR的 **位数取决于[指令字长](<1-计算机系统概述 - 计算机组成原理.md## 2.1. 机器字长>)**；
3. **指令译码器(ID)**：仅对 **操作码字段进行译码**，以确定指令的操作功能；
4. **存储器地址寄存器(MAR)**：仅存放要访问的主存单元地址【**存地址Memory address**】；
5. **存储器数据寄存器(MDR)**：
	1. 存放向主存写入的信息或从主存读取的信息【**存数据Memory data**】；
	2. n位CPU的n指的是数据总线线数(即：**数据总线的位数=处理器位数**)；
6. **时序系统**：用于产生各种时序信号，都由统一时钟 CLOCK 分频得到；
7. **微操作信号发生器**：
	1. 根据 IR 的内容(指令)，PSW的状态(状态信息)和时序信号，产生控制计算机系统所需的各种控制信号；
	2. 结构有 **组合逻辑型** 和 **存储逻辑型**。

## 1.4. “存储程序”工作方式

当前有一个程序A，总共有两条指令，分别是指令1以及指令2构成，需要处理两个操作数(数据)，分别是数据1以及数据2。

1. 在执行程序A之前，会将程序所含的指令以及所需要的数据 **从外存中读出，送入到内存中**。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤1.png) 
2. 程序计数器(PC)，用来存放当前欲执行指令的地址，具有 **自动加`1`** 的功能(这里`1`指的是一条指令长度)，即可**自动形成下一条指令的地址**，它与MAR之间可以交换信息。执行程序A之前，PC的值会被设置为指令1的地址，即`(PC)=0`。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤2.png) 
3. PC会将保存的内容送给MAR，即`(PC)->MAR`，告知主存访存地址。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤3.png) 
4. 主存获取MAR中的地址后，会将地址为0的存储单元中的内容取出，放进MDR中，即`(M)->MDR`。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤4.png) 
5. 取出指令1后，PC会自动加“1”，变为1，即保存指令2的地址。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤5.png) 
6. 指令寄存器(IR)用来 **存放当前的指令**，其**内容来自主存储器MDR**。MDR获取到指令1后，会将指令送到IR中，即`(MDR)->IR`。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤6.png) 
7. **指令一般由 操作码(OP)和操作数构成**，操作数可以是 **数据** 或 **内存地址**，指令1中 的操作数是一个地址，即数据1的地址，`指令1=操作码(OP)+数据1的地址(Ad(IR))`。而操作码说明这条指令的用途，如加减乘除等。**IR识别出OP后，送给控制单元(CU)分析**，CU会根据OP对各个部件发出相应的控制信号。而Ad(IR)会被送给MAR。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤7.png) 
8. **MAR收到来自IR的地址之后**，主存会根据MAR中的地址将数据1取出，并放入MDR中。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤8.png)
9. 控制单元(CU)分析OP后，得知指令1的作用是将数据1进行自增操作，即`数据1 ++`。因此会将MDR中的数据1读入到通用寄存器组中。**通用寄存器主要用来暂存一些ALU运算需要的数据**。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤9.png) 
10. ALU会在CU的控制下，对数据1进行自增操作，并将结果放回MDR。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤10.png) 
11. 在CU的控制下，主存会根据MAR中的地址，将数据1保存到主存中相应的存储单元。**到此一条指令执行结束**。
	![555](image/5-中央处理器%20-%20计算机组成原理/指令执行步骤11.png) 
12. PC会把保存的地址，送到MAR中，即`(PC)->MAR`，开启新一轮指令执行过程。
	![555](image/5-中央处理器%20-%20计算机组成原理/执行执行步骤12.png) 
> **注意**：ALU需要输入端两个操作数**同时输入时才会运算**。因此首个操作数输入后没有被暂存，在下一个操作数从内存读出到总线时就会被破坏掉。

# 二、 指令执行过程

## 2.1. 一条指令执行的一般流程

1. 首先以 PC 为地址访问主存取指令，同时更新 PC 的值作为后续顺序指令的地址；
2. 通常**指令译码**会**根据指令功能进入不同的执行路径**，此处仅区分分支指令和其他指令：
	1. **分支指令且满足分支条件**：只需要重新修改PC的值作为分支目标地址；
	2. **其他指令**：可能要经历取操作数、执行指令、存操作数的基本过程。
3. **指令执行完毕后**还需要进行 **中断异常判断**，如果不存在中断异常，直接进入取指令、执行指令的循环；
4. 控制器 **检测到中断异常**，处理器就会 **进入中断响应阶段**，此时需要关中断、保存断点、修改PC值作为终端服务程序入口地址，然后转去执行中断服务程序。

> **中断**：**计算机在执行程序的过程中，由于某些紧急事件的发生，使得程序的执行暂时停止，转而去处理这些紧急事件，处理完毕后再返回原来的位置继续执行的过程。**

## 2.2. 指令周期

### 2.2.1. 指令周期概述与易混淆点

**指令周期**：CPU从主存中**取出并执行**一条指令的时间；
指令周期最多由四种机器周期：**取指周期(FE)、间址周期(IND)、执行周期(EX)、中断周期(INT)**(*均有访问主存的操作*)
对应的是标志触发器，`1` 表示有效，如 1 -> FE 表示有取指周期。

![555](image/5-中央处理器%20-%20计算机组成原理/指令周期.png)

#### （一） 易混淆点

1. **指令**：
	1. CPU区分指令和数据的依据是指令周期的不同阶段。(*取指周期取指令；执行周期取数据*)
	2. 不同长度的指令，取指操作可能不同(*双字指令，三字指令和单字指令*)；指令长度相同的情况下，指令的取指操作时相同的。
	3. **指令总是根据PC从主存中读取出**(*无条件转移指令或中断返回指令同理，最终的结果还是根据PC从主存读出*)
2. **取指**：
	1. 取指操作是控制器固有的功能，**不需要操作码的控制**。
	2. 取指操作是 **自动进行** 的，控制器不需要得到相应的指令。
	3. 取指周期相对简单来说是取指，**即从主存中取出指令字**。
3. **字长**：
	1. 为了硬件设计方便，**指令字长一般取存储字长的整数倍**。
	2. 如果指令字长=2倍存储字长，则取一条指令需要访存2次，取指周期是机器周期的2倍。(*指令字长与机器字长无关系。*)
4. **中断**：
	1. CPU在每条指令执行结束前，都要发中断查询信号。
	2. CPU响应中断的时间是一条指令 **执行结束后**。
5. **周期**：
	1. **指令周期**：CPU从主存中取出并执行一条指令的时间，一个指令周期由多个机器周期组成。
	2. **[CPU周期/机器周期](<1-计算机系统概述 - 计算机组成原理.md### 2.4.2. CPU 时钟周期>)**：一个机器周期包含若干时钟周期。
	3. **时钟周期/节拍/T周期**：计算机工作的最小周期时间，是CPU操作的基本单位；一个时钟周期内控制信号不发生改变。
	4. **存取周期**：连续启动两次独立的读/写操作所需要的最短时间。
6. **周期的关系**：
	1. **机器周期通常由存取周期确定**。(*因为存取周期时间最长*)
	2. **执行各条指令的机器周期数可变，各机器周期的长度可变**：
		1. 机器周期是指令执行中每一步操作(*取指令，存储器读/写*)所需要的时间；
		2. 每个机器周期内的节拍数可以不等，因此长度可变；
		3. 各种指令的功能不同，所以指令执行时所需的机器周期数可变。
	3. 采用DMA方式传递数据，每传送一个数据就要占用存取周期。
7. **其他**：
	1. **不采用Cache**表明每次取指令都只是要访问主存一次；
	2. **不采用指令预取技术**表明每个指令周期都需要取指令。

#### （二） 基本工作周期(机器周期)

当CPU采用中断方式实现主机和IO交换信息时，**CPU在每条指令执行结束前，都要发中断查询信号，以检测是否有某个IO提出中断请求**。如果有请求，CPU则要进入中断响应阶段，即 **中断周期**。
> 一个完整的指令周期应包括 **取指、间址、执行和中断四个子周期**。

![555](image/5-中央处理器%20-%20计算机组成原理/带有中断周期的指令.png) 

四个周期也可称为 **CPU 的基本工作周期(机器周期)**，每个周期都有访存操作，但访存的目的不同。

| CPU 工作周期 | 访存目的               |
| -------- | :----------------- |
| 取指周期     | 取指令                |
| 间址周期     | 取操作数有效地址           |
| 执行周期     | 取操作数、存操作数          |
| 中断周期     | 保存断点、执行中断服务程序、恢复断点 |

## 2.3. 指令执行步骤

### 2.3.1. 取指周期

取指令阶段完成的任务是 **将当前指令从主存中取出来并送到指令寄存器中去**。

**数据流**：

1. PC ① MAR ② 地址总线 ③ 存储器；
2. CU发出读命令 ④ 控制总线 ⑤ 存储器；
3. 主存 ⑥ 数据总线 ⑦ MDR ⑧ IR(存放指令)；
4. CU发出控制信号 ⑨ PC内容加1。

![400](image/5-中央处理器%20-%20计算机组成原理/取指周期数据走向.png) 

> 注意：
> 1. **MAR、MDR相当于作为一个缓冲，严格来说是地址锁存器和数据锁存器**，二者都不会长期持有数据。
> 2. CU通过 **预设好的时序和状态机**，即根据时钟周期，判断此时应该令PC+1。若中途数据丢失，存储器会向CU发送等待信号，CU会依此插入多个空转周期，暂停此次流程。

### 2.3.2. 间址周期

在取出指令后，**CU就检查IR中的内容，对IR中的指令字进行指令译码**、识别指令类型、**判断其是否有间址操作**。
取指阶段，IR是从MDR取出，所以如果需要间址操作，可以直接 **将MDR/IR中的形式地址[记作Ad(IR)]送到MAR**，再送到地址总线，此后 **CU通过控制总线像存储器发送读命令**，以获取操作数的有效地址并存至MDR。

**数据流**：
1. Ad(IR)(或MDR) ① MAR ② 地址总线 ③ 存储器；
2. CU发出读命令 ④ 控制总线 ⑤ 存储器；
3. 主存 ⑥ 数据总线 ⑦ MDR(存放有效地址)。

![400](image/5-中央处理器%20-%20计算机组成原理/间址周期数据走向.png)

> **注意**：CU译码后，只有IR需要加上 Ad(IR)，MDR不需要。因为IR内部结构固定，可以直接提取出对应的地址码；而 MDR 中或是指令或是数据或是地址，只有在是地址的时候，才可直接传给MAR，其余均不知具体地址码。

### 2.3.3. 执行周期

在执行周期，控制器向ALU及数据通路中的其他相关部件发出操作控制命令，对取出的操作数进行加工处理，并将处理状态信息记录到PSW中。**由于不同指令在执行周期的的操作不同，因此执行周期也可能不同**。

### 2.3.4. 中断周期

中断周期的主要任务是对异常的事件或者对请求中断的事件进行响应。**通常，在执行周期结束时，CPU会查询当前是否有中断请求，如果有则会进入中断周期(或中断响应周期)**。
中断周期的关键工作：**1.关中断；2.保存断点；3.根据中断源寻找中断程序的入口地址。**

设程序断点保存在堆栈指针所指内存单元，假设SP指针指向栈顶元素，进栈先修改指针，后存入数据。
**数据流**：

1. CU控制将SP减1，SP ① MAR ② 地址总线 ③ 存储器；
2. CU发出写命令 ④ 控制总线 ⑤ 存储器；
3. PC ⑥ MDR ⑦ 数据总线 ⑧ 主存(程序断点存入存储器)；
4. CU(中断服务程序的入口地址) ⑨ PC。

![400](image/5-中央处理器%20-%20计算机组成原理/中断周期数据走向.png)

> **注意**：中断周期 **只在指令执行周期的结束时刻被检查**，不会随时发生。中断本质虽是随机，但CPU内部其响应时机是**固定**的。
> 中断服务程序入口地址的来源依赖于 **硬件向量、软件查询**。

## 2.4. 指令的执行方案

如何安排指令的执行步骤称为 **指令执行方案**。

|       | 特点            | 定义                                                                          |
| :---- | :------------ | :-------------------------------------------------------------------------- |
| 单指令周期 | 串行，**相同**执行时间 | 1.每条指令都在固定的时钟周期内完成，指令之间 **串行执行**；<br>2.指令周期 **取决于执行时间最长的指令的执行时间**。          |
| 多指令周期 | 串行，**不同**执行时间 | 1.指令之间 **串行执行**；<br>2.可以选用不同个数的时钟周期来完成不同指令的执行过程；<br>3.指令需要几个周期就为其分配几个周期。    |
| 流水线方案 | 并行            | 1.力争在每个时间脉冲周期完成一条指令的执行过程(*理想情况*)；<br>2.尽量 **让多条指令同时运行**，但 **各自处在不同的执行步骤中**。 |

# 三、 数据通路的功能和基本结构

**数据通路**：数据在功能部件之间传送的路径，包括数据通路上流经的部件。
> 描述信息从什么地方开始，中间经过哪个寄存器或多路开关，最后传送到哪个寄存器。

**数据通路的功能**：实现CPU内部的 **运算器与寄存器** 及 **寄存器之间** 的 **数据交换**。

**易混淆点**：
1. **数据通路是由控制部件控制**，控制部件根据每条指令功能的不同⽣成对数据通路的控制信号；
2. **单总线数据通路** 将所有寄存器的输⼊输出端都连接在⼀条公共通路上，⼀个时钟内只允许⼀次操作，无法完成指令的所有操作；
3. CPU 的读/写控制信号线决定了是从存储器读还是向存储器写；
4. **内部总线** 是指同一部件之间的线，**系统总线** 是同一台计算机系统各部件之间的线。

> **注意**：CPU 内部线路采用**总线连接方式**时，总线上信号流动原则：
> 每个时刻只有一个器件发出信息；每个时刻有一个或多个器件接收信息。

## 3.1. 数据通路的基本结构

**总线**：指一组信号线，用在计算机的各个组件之间传输数据、地址和控制信号
1. **数据总线**：用于传输实际的数据；
2. **地址总线**：用于指定数据传输的内存地址；
3. **控制总线**：传输控制信号。
**总线的宽度通常以位(bit)** 为单位，如32位，64位总线。

![555](image/5-中央处理器%20-%20计算机组成原理/CPU内部总线.png) 

### 3.1.1. CPU 内部单总线方式

所有寄存器的输入输出端都连接到**一条公共通路**上。
- 结构简单，数据传输过程中，存在较多冲突现象，**性能较低**。

### 3.1.2. CPU 内部三/多总线方式

将所有寄存器的输⼊端与输出端都连接到**多条公共通路**上。
- 较单总线结构，**效率提高**。
> **注意**：如果源总线和目的总线之间的连接通过ALU实现。假定所需操作通过ALU一次就可完成，那么 **该指令可在一个时钟周期内完成**。

### 3.1.3. 专用数据通路方式

根据指令执行过程中的数据和地址的**流动方向**安排连接线路。
- 避免使用共享的总线，**性能较好**，但 **硬件总量大**。

![400](image/5-中央处理器%20-%20计算机组成原理/CPU内部总线的数据通路和控制信号.png) 

## 3.2. 数据传输示例

以上 3.1.3 中的图为例。

### 3.2.1. 寄存器之间的数据传输

寄存器之间的数据传送可以通过CPU内部总线完成。
以 **PC寄存器为例，把PC内容送至MAR**，实现传送操作的流程的控制信号：

| PC->Bus  | PCout有效，PC内容送总线  |
| -------- | ---------------- |
| Bus->MAR | MARin有效，总线内容送MAR |

### 3.2.2. 主存与CPU之间的数据传送

主存与CPU之间的数据传送也要借助CPU内部总线完成。
**以CPU从主存读取指令为例**，实现传送操作的流程的控制信号：

| PC->Bus->MAR  | PCout和MARin有效，现行指令地址->MAR |
| ------------- | ------------------------- |
| 1->R          | CU 发读命令                   |
| MEN(MAR)->MDR | MDRin有效                   |
| MDR->Bus->IR  | MDRout和IRin有效，现行指令->IR    |

### 3.2.3. 执行算术或逻辑运算

以加法运算为例：

| Ad(IR)->Bus->MAR | MDRout和MARin有效                  |
| ---------------- | ------------------------------- |
| 1->R             | CU发出读命令                         |
| MEN->数据线->MDR    | 操作数从存储器->数据线->MDR               |
| MDR->Bus->Y      | MDRout和Yin有效，有效数->Y             |
| (ACC)+(Y)->Z     | ACCout和ALUin有效，CU向ALU发加命令，结果->Z |
| Z->ACC           | Zout和ACCin有效，结果->ACC            |

# 四、 控制器的功能和工作原理

## 4.1. 结构

![555](image/5-中央处理器%20-%20计算机组成原理/09408真题1.png)
![555](image/5-中央处理器%20-%20计算机组成原理/09408真题2.png)

**实现微操作的关键是在正确的时钟周期发出正确的控制信号**，而控制信号实际上是由控制单元发出的。因此，在控制器的组成部件中，**最核心也是最复杂的部分是控制单元(CU)**。

## 4.2. 连接关系

| 器件         | 关系                                                                                    |
| :--------- | :------------------------------------------------------------------------------------ |
| 运算器        | 运算器部件通过数据总线与内存储器、输入设备和输出设备传送数据。                                                       |
| 输入设备和输出设备  | 输入设备和输出设备通过接口电路与总线相连。                                                                 |
| 内存储器、I/O设备 | 1. 内存储器、输⼊设备和输出设备从地址总线接收地址信息；<br>2. 从控制总线得到控制信号，通过数据总线与其他部件传送数据。                      |
| 控制器部件      | 1. 控制器部件从数据总线接受指令信息；<br>2. 从运算器部件接受指令转移地址，送出指令地址到地址总线；<br>3. 还要向系统中的部件提供它们运行所需要的控制信号。 |

**根据控制器产生微操作信号的方式不同，控制器可以分为硬布线控制器和微程序控制器。**

## 4.3. 硬布线和微程序控制器

### 4.3.1. 对比

![](image/5-中央处理器%20-%20计算机组成原理/硬布线与微程序对比.png)

#### （一） 硬布线控制器

**基本原理**：
- 根据指令的要求、当前的时序及外部和内部的状态，**按时间顺序**发送一系列微操作控制信号；
- 是由复杂的组合逻辑门电路和⼀些触发器构成，又称**组合逻辑控制器**。

**硬布线控制单元图**：【**CU的输入信号来源**】
- 经指令编译器译码产生的；
- 时序系统产生的机器周期信号和节拍信号；
- 来自执行单元的反馈信号，即标志。
微操作控制信号的形成主要与指令译码信号和时钟信号有关。

![400](image/5-中央处理器%20-%20计算机组成原理/硬布线控制单元图.png)

**硬布线控制器的时序系统及微操作**：
- **时钟周期**：用时钟信号控制节拍发生器，可以产生节拍，每个节拍的宽度正好对应一个时钟周期；
- **机器周期**：可以视为所有指令执行过程中的一个基准时间；
- **指令周期**：CPU从主存中取出并执行一条指令的时间称为指令周期；
- **微操作命令分析**：控制单元发出各种操作命令序列的功能。

**CPU 的控制方式**：
1. **同步控制方式**：
	1. 系统有一个统一的时钟，所有的控制信号都来源于这个统一的时钟信号；
	2. 通常以最长的微操作序列和最繁琐的微操作作为标准；
	3. 采取完全统一的、具有相同时间间隔和相同数目的节拍作为机器周期来运行不同的指令。
	4. **优点：控制电路简单**；
	5. **缺点：运行速度慢**。
2. **异步控制方式**：
	1. 不存在基准时标信号，各部件按照自身固有的速度工作，通过应答方式进行联络。
	2. **优点：运行速度快**；
	3. **缺点：控制电路较为复杂**。
3. **联合控制方式**：
	1. 介于同步、异步之间的一种折中；
	2. 对大部分采用同步控制，小部分采用异步控制。

#### （二） 微程序控制器

**基本原理**：采用存储逻辑实现，即把 **微操作信号代码话**。
**基本思想**：
- 将每条机器指令编写成一个微程序，每个微程序包含若干微指令，每条微指令对应一个或几个微操作命令；
- **机器指令-> 微程序 -> 微指令 -> 微操作命令**
- 这些微程序可以存到一个控制存储器中，用寻址 **用户程序机器指令**的方法来寻址每个微程序中微指令。
**基本概念**：
1. **微命令与微操作**：
	1. **微命令**是计算机中最基本、不可再分解的操作；微命令执行的操作叫做微操作；
	2. **微操作**将控制部件向执行部件发出的各种控制命令；是构成**控制序列的最小单位**。
2. **微指令与微周期**：
	1. **微指令**是若干微命令的集合；
	2. **微地址**存放微指令的控制存储器的单元地址；
	3. **微周期**指的是从控制存储器中读取一条微指令并执行相应的微操作所需的时间；
	4. **微指令的两个组成部分**：微操作码字段和微地址码字段。
3. **主存储器与控制存储器**：
4. **程序与微程序**：
	1. **程序**是指令的有序集合，用于完成特定的功能；
	2. **微程序**是微指令的有序集合，一条指令的功能由一段微程序实现。
5. **微程序和机器指令**：一般来说，一条机器指令对应一个微程序。

**寄存器分类**

| 类型     | 功能               |
| :----- | :--------------- |
| 地址寄存器  | 存放主存的读写地址        |
| 微地址寄存器 | 存放控制存储器的读写微指令的地址 |
| 指令寄存器  | 存放从主存中读出的指令      |
| 微指令寄存器 | 存放从控制存储器中读出的微指令  |
|        |                  |

**基本组成**：
1. **控制存储器**：核心部件，用于存放个指令对应的微程序，控制存储器可用ROM构成；
2. **微指令寄存器**：存放从CM中取出的微指令，位数与微指令字长相等；
3. **微地址形成部件**：用于产生初始微地址和后继微地址，以保证微指令的连续执行；
4. **微地址寄存器**：接受微地址形成部件送来的微地址，为在CM中读取微指令做准备。

![400](image/5-中央处理器%20-%20计算机组成原理/微程序控制器的基本结构.png)

**工作过程**：
1. 执行取微指令公共操作；
2. 由 **机器指令的操作码字段** 通过微地址形成部件产生该及其指令所对应的微程序的入口地址，并送入CMAR；【**微程序入口地址是机器指令的操作码字段**】
3. 从CM中逐条取出对应的微指令并执行；
4. 执行完对应于一条机器指令的一个微程序后，又回到取指微程序的入口地址，继续第一步。

**编码方式/控制方式**：
1. **目的**：保证速度的情况下，尽量缩短指令字长；
2. **直接编码方式**：
	1. 无需进行译码，微指令的微命令字段中的每一位都代表一个微命令(选用`1`，不选用`0`)；
	2. **优点：简单、直观、执行速度快，操作并行性好**；
	3. **缺点：微指令字长过长，n个微指令就要求微指令的操作字段又n位，造成控制存储器容量极大**。
3. **字段直接编码法**：
	1. 将微命令字段分成若干小字段，将 **互斥性微命令组合在同一字段中**；
	2. 把 **相容性微命令组合在不同字段中**，每个字段独立编码；
	3. 每种编码都代表一个微命令且各字段编码含义单独定义，与其他字段无关；
	4. **优点：可以缩短微指令字长**；
	5. **缺点：要通过译码电路之后再发出微指令，速度慢**；
	6. **分段原则**：
		1. 互斥性微命令组合在同一字段中，把相容性微命令组合在不同字段中；
		2. 每个小段中包含的信息位不能太多，否则将增加译码电路的复杂性和译码时间；
		3. 一般每个小段还要留出一个状态，表示本字段不发出任何微命令。
4. **字段间接编码法**：
	1. 一个字段的某些微命令需由另一个字段中的某些微命令解释；
	2. 由于不是靠字段直接译码发出的微命令，因此称为字段间接编码；
	3. **优点：可进一步缩短微指令字长**；
	4. **缺点：削弱了微指令的并行能力**。

**微指令的格式**：
- 水平型微指令
- 垂直型微指令
- 混合型微指令

**水平型和垂直型对比**：

| 水平型              | 垂直型         |
| :--------------- | :---------- |
| 并行操作能力强，效率高，灵活性强 | 相反          |
| 执行一条指令的时间短       | 相反          |
| 微指令字位数较多，微程序较短   | 相反          |
| 用户难以掌握           | 与指令相似，用户好掌握 |

**动态微程序设计**：
- 能根据用户的要求改变微程序，则其具有动态微程序设计功能；
- 需要可写控制寄存器的支持。可采用[EPROM(可擦除可编程只读存储器)](<3-存储器层次结构 - 计算机组成原理.md#### （一） ROM 的主要类型>)。

**毫微程序设计**：
- 硬件不由微程序直接控制，而是通过存放在第二级控制存储器中的毫微程序来解释的；
- 这个第二级控制存储器就成为毫微存储器，直接控制硬件的就是毫微微指令。

# 七、 多处理器基本概念

## 7.1. SISD、SIMD、MIMD、向量处理器
- **SISD**：单指令单数据流（传统CPU）
- **SIMD**：单指令多数据流（向量处理器、GPU）
- **MIMD**：多指令多数据流（多核CPU、集群）
- **向量处理器**：一次处理一维数组

## 7.2. 硬件多线程
- 细粒度交替
- 粗粒度交替
- 同时多线程（SMT，如Intel超线程）

## 7.3. 多核处理器（multi-core）
- 单芯片集成多个处理核心
- 共享/私有Cache结构
- 核间通信方式

## 7.4. 共享内存多处理器（SMP）
- 多个处理器共享同一物理内存
- UMA（统一内存访问）与NUMA（非统一内存访问）
- 缓存一致性协议（如MESI）
