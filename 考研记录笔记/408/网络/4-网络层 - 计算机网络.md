# 一、 网络层的功能

## 1.1. 网络层概述

**网络层负责分组选择合适的交付路径**。

网络层主要任务是实现 **网络互连**，进而实现 **数据包在各网络之间的传输**。

**网络层任务需要解决的问题**：
- **服务模型问题**：网络层向运输层提供怎样的服务(*可靠传输还是不可靠传输*)；
- **寻址问题**：如何标识网络中的每一台设备(*IP地址体系*)；
- **路由问题**：如何为分组找到从源到目的的最佳路径。

## 1.2. 网络层的主要功能

### 1.2.1. 异构网络互联

**异构网络**：指使用不同通信技术、不同协议、不同硬件的网络。

**网络互联**：将两个或多个异构网络通过中间设备连接起来，使它们能够互相通信。

**中间设备**(*中继系统*)：

| 设备 | 工作层次 | 功能 |
| :--- | :--- | :--- |
| **物理层中继系统** | 物理层 | 转发器、集线器(*仅放大信号，不识别地址*) |
| **数据链路层中继系统** | 数据链路层 | 网桥、交换机(*基于MAC地址转发*) |
| **网络层中继系统** | 网络层 | **路由器**(*基于IP地址转发，可连接异构网络*) |
| **高层中继系统** | 网络层以上 | 网关(*协议转换，连接不同体系结构的网络*) |
> **注意**：只有 **路由器** 和 **网关** 能够连接异构网络(*物理层和数据链路层设备只能连接相同类型的网络*)。

### 1.2.2. 路由与转发

因特网是最大的互联网，由无数局域网、广域网通过连接设备互相连接在一起而形成的。
**这些网络可能有不同的接入技术和通信协议**。

![400](image/4-网络层%20-%20计算机网络/网络层通信结构示例.png)

> **注意**：当中间设备是转发器或网桥时，仅仅是把一个网络扩大了，而从网络层的角度看，这仍然是一个网络，**一般并不称之为网络互连**。

在讨论网络互连时，一般指用 **路由器** 进行网络互连和路由选择。
**路由器(*网关*)**：是一台专用计算机，用来在互联网中进行 **路由选择与分组转发**。

![555](image/4-网络层%20-%20计算机网络/网络层通信过程示例.png)

**路由选择**：确定分组从源到目的地的 **路径**(*控制层面*)。
- 通过路由协议(*RIP、OSPF、BGP*)交换路由信息，构建路由表；
- 路由选择关注的是 **“走哪条路”**。

**分组转发**：将分组从路由器的 **输入端口转移到输出端口**(*数据层面*)。
- 根据转发表(*或路由表*)进行转发；
- 转发关注的是 **“具体怎么走”**。

**路由表与转发表的区别**：

| 对比项      | 路由表            | 转发表              |
| :------- | :------------- | :--------------- |
| **用途**   | 路由选择(*建立路径信息*) | 分组转发(*实际执行转发*)   |
| **内容**   | 目的网络、下一跳、度量值等  | 目的网络、输出端口、MAC地址等 |
| **更新方式** | 动态更新(*通过路由协议*) | 由路由表生成           |
| **实现方式** | 软件             | 硬件(*专用芯片，更快*)    |
> **注意**：在讨论路由原理时，常不严格区分路由表和转发表，笼统称为“路由表”。但在具体考试中，要能区分两者的概念。

### 1.2.3. 网络层提供的两种服务

网络层向运输层提供两种服务模式：**虚电路服务** 和 **数据报服务**。

#### （一） 虚电路服务(面向连接)

**基本思想**：通信前线建立一条逻辑连接(*虚电路*)，所有分组沿同一条虚电路传输。

**特点**：
1. **建立连接**：通信前需建立虚电路，通信结束后释放；
2. **按序到达**：同一虚电路的分组沿相同路径传输，不会乱序；
3. **分组首部开销小**：只需携带虚电路号(*而非完整目的地址*)；
4. **可靠性由网络层保证**。

**应用**：X.25、帧中继、ATM。

![555](image/4-网络层%20-%20计算机网络/虚电路服务示例.png)

> **注意**：虚电路并不是真实的物理连接，但有类似的作用。
>   在虚电路下，即使多站点同时使用一段物理链路实现虚电路交换时，也不会产生冲突，因为每个分组都拥有一个 **虚电路号** 来标识所属的网络。
> **也无需给每条虚电路预分配带宽。**

#### （二） 数据报(无连接)

数据报(*或者 IP 数据报*)，就是常使用的 **分组**。

**基本思想**：每个分组独立选择路径传输，无需事先建立连接。

**特点**：
1. **无需建立连接**：分组直接发送；
2. **独立路由**：每个分组根据当前网络状态独立选择路径；
3. **可能乱序**：不同分组可能走不同路径，到达顺序可能乱序；
4. **分组首部开销大**：需携带完整的目的IP地址；
5. **可靠性由运输层保证**(*网络层只提供尽最大努力交付*)。

**应用**：IP协议(*互联网的核心服务方式*)。

![555](image/4-网络层%20-%20计算机网络/数据报服务示例.png)

#### （三） 两种服务的对比

| 对比项        | 虚电路服务     | 数据报服务     |
| :--------- | :-------- | :-------- |
| **建立连接**   | 需要        | 不需要       |
| **路由选择**   | 建立时确定     | 每个分组独立    |
| **分组顺序**   | 按序到达      | 可能乱序      |
| **可靠性**    | 网络层保证     | 运输层保证     |
| **分组首部**   | 虚电路号(*短*) | 目的地址(*长*) |
| **网络状态维护** | 需维护连接状态   | 无状态       |
| **典型协议**   | X.25、ATM  | IP        |

### 1.2.4. SDN基本概念

**软件定义网络(*SDN，Sofware Defined Network*)**：一种将网络设备的 **控制平面** 和 **数据平面** 分离的网络架构。

**控制平面**：决定“数据包往哪里走”(*路由决策*)，集中在 **SDN控制器** 中实现；
**数据平面**：执行“数据包具体怎么走”(*分组转发*)，由路由器/交换机等设备实现。

![555](image/4-网络层%20-%20计算机网络/SDN层面构成示例.png)

**SDN架构**：
- **应用层**：网络应用(*负载均衡、防火墙等*)；
- **控制层**：SDN控制器(*集中式控制*)；
- **基础设施层**：转发设备(*交换机、路由器*)。

**关键接口**：
- **南向接口**：SDN控制器与转发设备之间的接口(*常用OpenFlow协议*)；
- **北向接口**：SDN控制器与上层应用之间的接口(*编程接口，开放API*)；
- **东西向接口**：多个SDN控制器(*SDN控制器集群内部*)之间的通信接口。

**SDN的优点**：
- **集中控制**：全局视图，优化路由决策；
- **可编程性**：通过编程接口灵活控制网络行为；
- **简化设备**：转发设备只负责转发，降低成本；
- **灵活部署**：易于部署新协议和新功能。

**SDN的缺点**：
- **单点故障风险**：控制器故障可能导致整个网络瘫痪(*可通过集群提高可靠性*)；
- **性能瓶颈**：集中式控制器可能成为大规模网络的瓶颈；
- **安全风险**：控制器被攻击会影响整个网络。

### 1.2.5. 拥塞控制

**拥塞(*Congestion*)**：网络中某个部分出现过量的分组，导致网络性能下降的现象。

**拥塞的表现**：
- 分组丢失率上升；
- 端到端时延增大；
- 网络吞吐量下降。

![555](image/4-网络层%20-%20计算机网络/拥塞控制示例.png)

**拥塞控制与 [流量控制](<3-数据链路层 - 计算机网络.md## 2.1. 流量控制>) 对比**：

| 对比项 | 拥塞控制 | 流量控制 |
| :--- | :--- | :--- |
| **控制对象** | 整个网络 | 单个发送方与接收方 |
| **控制范围** | 全局(*所有节点*) | 局部(*端到端*) |
| **目的** | 防止网络过载 | 防止接收方被淹没 |
| **参与者** | 所有路由器 + 主机 | 发送方 + 接收方 |

**拥塞控制的两种方法**：

1. **开环控制(*预防性控制*)**：
	- 在设计网络时预先考虑拥塞问题；
	- 采用合适的资源分配策略和流量整形措施；
	- 一旦网络运行起来，不再中途调整。
2. **闭环控制(*反馈控制*)**：
	- **监测**：检测网络拥塞的发生；
	- **反馈**：将拥塞信息传递给可采取行动的地方；
	- **调整**：根据反馈信息调整网络运行(*如：降低发送速率、重新路由等*)。

> **注意**：拥塞控制涉及网络中 **所有主机、路由器及导致网络传输能力下降** 的所有因素。

# 二、 IPv4

TCP/IP 体系中，互联网上的 **任何设备** 都有IP地址，否则就无法和网上的其他设备进行通信。

![300](image/4-网络层%20-%20计算机网络/IP通信示例.png)

## 2.1. IP地址概述

### 2.1.1. IP地址的定义

**IP地址**：连接到互联网上的每一台主机(*或路由器*)的每一个接口都有一个全世界范围内唯一的 32 位的标识符。

### 2.1.2. IP地址的表示方法
**二进制表示**：32 位，通常每隔 8 位插入一个空格便于阅读；
**点分十进制表示**：将每 8 位二进制数转换为等效的十进制数字，并用 `.` 分隔。

![555](image/4-网络层%20-%20计算机网络/IP地址表示示例.png)
> **例如**：`10000000 00001011 00000011 00011111` -> `128.11.3.31`.

### 2.1.3. IP地址的结构

32 位的 IP地址采用两级结构，由两个字段组成：

| 字段 | 位数 | 作用 | 特点 |
| :--- | :--- | :--- | :--- |
| **网络号** | 前 n 位 | 标志主机或路由器所连接到的网络 | 每个网络号在整个互联网范围内必须是唯一的 |
| **主机号** | 后 32-n 位 | 标志该主机或路由器 | 在同一网络内必须是唯一的 |
> IP地址可记为：`<网络号>，<主机号>`

![300](image/4-网络层%20-%20计算机网络/IP地址划分示例.png)

> **注意**：
> 1. IP地址标识的是主机(*或路由器*)的**接口**，而非设备本身。一台多网卡的主机拥有多个IP地址。和 [MAC地址](<3-数据链路层 - 计算机网络.md### 4.2.4. MAC地址分类>) 中类似。
> 2. 网络号相同的IP地址属于同一网络。

## 2.2. IP地址的发展

### 2.2.1. 分类IP地址

互联网发展早期采用的是 **分类的IP地址**，即将IP地址分为以下五类，每一类的网络号长度固定。

![555](image/4-网络层%20-%20计算机网络/分类的IP地址.png)
> **注意**：五类IP地址本质上是 **前缀编码**，类似于[计组中](<4-指令系统 - 计算机组成原理.md## 2.3. 指令地址码>)的变长操作码的编码方式。

#### （一） 五类IP地址的划分

| 类别 | 首位比特 | 网络号长度 | 主机号长度 | 地址范围 | 用途 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A类** | 0 | 8位(1字节) | 24位(3字节) | 0.0.0.0 ~ 127.255.255.255 | 单播 |
| **B类** | 10 | 16位(2字节) | 16位(2字节) | 128.0.0.0 ~ 191.255.255.255 | 单播 |
| **C类** | 110 | 24位(3字节) | 8位(1字节) | 192.0.0.0 ~ 223.255.255.255 | 单播 |
| **D类** | 1110 | — | — | 224.0.0.0 ~ 239.255.255.255 | 多播 |
| **E类** | 1111 | — | — | 240.0.0.0 ~ 255.255.255.255 | 保留 |
> **注意**：A、B、C类地址都是 **单播地址**(*一对一通信*)，是最常用的；D类是 **多播地址**(*一对多通信*)；E类是 **保留地址**。

#### （二） 特殊IP地址

| 网络号  | 主机号    | 作为源地址 | 作为目的地址 | 含义                  |
| :--- | :----- | :---- | :----- | :------------------ |
| 全0   | 全0     | 可以    | 不可以    | 本网络上的本主机(*用于DHCP*)  |
| 全0   | 特定值X   | 可以    | 不可以    | 本网络上主机号为X的主机        |
| 全1   | 全1     | 不可以   | 可以     | 本网络上的广播             |
| 特定值Y | 全1     | 不可以   | 可以     | 网络Y上的广播             |
| 127  | 非全0/全1 | 可以    | 可以     | 本地环回测试(*127.0.0.1*) |

#### （三） 分类IP地址的局限性

**地址利用率低**：A类网络(*1677万+地址*)和B类网络(*65534个地址*)对大多数单位而言过大，造成大量浪费。
**地址枯竭问题**：随着互联网发展，可用的网络号逐渐耗尽；
**路由表膨胀**：每个网络号都需要在路由表种占一条记录。

### 2.2.2. 子网划分

#### （一） 划分子网

**基本思想**：从IP地址的 **主机号** 中借用若干位作为 **子网号**，将两级IP地址(*网络号+主机号*)扩展为三级IP地址(*网络号+子网号+主机号*)。
$$IP地址::=\{ <网络号>, <子网号>, <主机号> \}$$

**作用**：
- 提高IP地址的利用率；
- 减小路由表规模(*子网信息仅在内部传播*)；
- 便于网络管理和维护。

> **注意**：子网划分对外部网络是 **透明的**。外部路由器看到的仍是该网络的网络号，子网划分仅在内部有效。

#### （二） 子网掩码

**子网掩码(*Subnet Mask*)**：用于指示IP地址中哪些位标识网络号及子网号，哪些位标识主机号。

**特点**：
- 长度与IP地址相同(*32位*)；
- 由一段连续的 `1` 和一段连续的 `0` 组成；
- `1` 对应网络号+子网号部分，`0` 对应主机号部分。

**计算网络地址**：`IP地址 AND 子网掩码 = 网络地址`

| 地址类别 | 默认子网掩码 | 二进制表示 |
| :--- | :--- | :--- |
| A类 | 255.0.0.0 | 11111111.00000000.00000000.00000000 |
| B类 | 255.255.0.0 | 11111111.11111111.00000000.00000000 |
| C类 | 255.255.255.0 | 11111111.11111111.11111111.00000000 |
> **注意**：子网掩码不能单独存在，必须与IP地址搭配使用。

#### （三） 默认网关

**默认网关(*Default Gateway*)**：连接子网与外部网络的设备(*通常是路由器*)的IP地址。

**作用**：
- 当主机需要发送数据到 **非本网络** 的目的地址时，将数据发送给默认网关；
- 默认网关负责将数据转发到外部网络。

> **注意**：
> 1. 默认网关必须与主机在 **同一子网** 内；
> 2. 主机的IP配置中需指定默认网关的IP地址；
> 3. 若主机所在网络没有默认网关，则无法访问其他网络。

### 2.2.3. 无分类编址(CIDR)

无分类域间路由选择(*Classless Inter-Domain Routing, CIDR*)是一种基于 **可变长子网掩码** 的地址分配与路由聚合机制。

无分类编址(*CIDR*)虽无法根本解决IP地址枯竭的问题，但可以推迟IP地址用尽的时间，目前已经普遍采用这种编址方法。

**核心思想**：不再区分网络类别，而使用 “网络前缀” 来标识网络部分。

#### （一） 网络前缀

**基本概念**：CIDR将IP地址中的网络号改称为 **网络前缀**，取消了传统的A、B、C类分类界限。
**记法**：采用 **斜线记法**，在IP地址后面加上 `/`，后跟网络前缀所占的位数。
$$<网络前缀>/<前缀长度>$$
> **示例**：`128.14.35.11/20` 表示前20位为网络前缀，后12位为主机号。

#### （二） 地址块

**地址块**：网络前缀相同的所有连续IP地址组成一个 **CIDR地址块**。

**关键计算**：
- 地址块大小 = $2^{32 - n}$ 个地址(*n为前缀长度*)；
- 最小地址 = 主机号全为0的地址(*网络地址*)；
- 最大地址 = 主机号全为1的地址(*广播地址*)；
- 有效地址 = 地址块大小 - 2(*排除网络地址和广播地址*)。

> **示例**：`128.14.35.8/20`
>   最小地址：`128.14.32.0` (*主机号全0*)
>   最大地址：`128.14.47.255` (*主机号全1*)
>   地址块大小：$2^{12} = 4096$ 个地址
>   有效地址：$4096 - 2 = 4094$ 个

#### （三） 路由聚合与最长前缀匹配

![300](image/4-网络层%20-%20计算机网络/路由聚合示例.png)

**路由聚合(*Route Aggregation*)**：将多个连续的CIDR地址块合并为一个更大的地址块，减少路由表条目。
> **注意**：题目中多是求多个地址的最长匹配位数。
> **例如**：`35.230.32.0/21`, `35.230.40.0/21`, `35.230.48.0/21`, `35.230.56.0/21`
>   第三个字节不同，其中最长匹配位数是 `001`，那么聚合后目的网路是：`35.230.32.0/19`。

**最长前缀匹配(*Longest Prefix Matching*)**：当一个目的地址匹配多个路由表项时，选择 **前缀最长** 的表项进行转发。

> **注意**：前缀越长，地址块越小，路由越精确。

## 2.3. IP地址与MAC地址

局域网中，MAC地址已经固化在网卡的ROM上，常称为 **硬件地址/物理地址**。
物理地址反过来就是：虚拟地址、软件地址或逻辑地址，即 **IP地址**。

![555](image/4-网络层%20-%20计算机网络/IP地址与MAC地址区别.png)

|          | IP地址           | MAC地址         |
| :------- | :------------- | :------------ |
| **名称**   | 逻辑地址/软件地址      | 物理地址/硬件地址     |
| **层次**   | 网络层(*第三层*)     | 数据链路层(*第二层*)  |
| **长度**   | 32位(*IPv4*)    | 48位           |
| **存储位置** | 计算机存储器         | 网卡ROM         |
| **是否可变** | 可变(*取决于网络连接*)  | 固定(*出厂固化*)    |
| **作用范围** | 全网范围           | 同一局域网内        |
| **作用**   | 标识主机所在的网络及主机身份 | 标识同一局域网内的物理接口 |

### 2.3.1. 数据封装中的地址变化

发送数据时，使用IP地址的IP数据报一旦交给数据链路层，就被 **封装成MAC帧**。

MAC帧在传送时实用的源地址和目的地址都是MAC地址，这两个MAC地址在MAC帧的首部中。

![555](image/4-网络层%20-%20计算机网络/IP地址与MAC地址传输过程中的变化.png)

**特征**：
- IP数据报需要经过路由器 `R1` 和路由器 `R2` 的两次转发，但它的首部中的源地址和目的地址始终分别是 `IP1` 和 `IP2`；
- 虽然IP数据报首部有源站 IP地址，但路由器 **只根据目的站的IP地址进行转发**；
- MAC帧在不同网络上传送时，其MAC帧首部中的源地址和目的地址要发生变化。

![555](image/4-网络层%20-%20计算机网络/IP数据报在网络层和MAC层地址变化示例.png)

> **注意**：IP地址在传输过程中保持不变，MAC地址逐段变化。
> IP地址标识通信的 **终点**；MAC地址标识通信的 **下一跳**。

## 2.4. 虚拟专用网(VPN)与网络地址转换(NAT)

### 2.4.1. 虚拟专用网(VPN)

在 TCP/IP 协议下，机构内部可以自行为其内部的计算机分配其 IP地址，该地址仅在本机构有效(*本地地址*)，不需要申请全球唯一的 IP地址(*全球地址*)。
为了确保本地地址和全球地址不会重合，因此可以限定本地地址只能采用某些专用地址(*私有地址*)。

> **注意**：私有地址只能用作本地地址，只能用于一个机构的内部通信，不能用于和互联网上的主机通信。

互联网中的所有路由器，对目的地址是**私有地址的数据报一律不转发**，地址范围如下：

| 地址类别   | 地址范围                              | CIDR表示           |
| :----- | :-------------------------------- | :--------------- |
| A类私有地址 | `10.0.0.0` ~ `10.255.255.255`     | `10.0.0.0/8`     |
| B类私有地址 | `172.16.0.0` ~ `172.31.255.255`   | `172.16.0.0/12`  |
| C类私有地址 | `192.168.0.0` ~ `192.168.255.255` | `192.168.0.0/16` |
> **注意**：互联网上的路由器**不会转发**目的地址为私有IP地址的数据报。

**VPN(*Virtual Private Network，虚拟专用网*)**：利用公用的互联网作为本机构各专用网之间的通信载体，实现跨地域安全通信的技术。
> **“虚拟”的含义**：效果上等同于专用网，但实际上并未使用真正的物理专线。

#### （一） VPN的工作原理

**IP隧道技术**：将整个内部数据报封装在外部数据报中，通过互联网传输。

![555](image/4-网络层%20-%20计算机网络/IP隧道技术示例.png)

**工作流程**(*以场所A的主机X与场所B的主机Y通信为例*)：
IP数据报源地址：`10.1.0.1`，目的地址：`10.2.0.3`。
1. **封装**：路由器R1将内部数据报(*源IP: 10.1.0.1, 目的IP: 10.2.0.3*)加密，封装为外部数据报(*源IP: R1全球地址, 目的IP: R2全球地址*)；
2. **传输**：外部数据报通过互联网传输；
3. **解封**：路由器R2收到后，解封并解密，恢复内部数据报；
4. **交付**：将内部数据报交付给主机Y。

> **注意**：从逻辑上看，R1到R2之间类似有一条直通的点对点链路，如上图的隧道。

#### （二） VPN的实现方式

| 类型 | 说明 | 适用场景 |
| :--- | :--- | :--- |
| **内联网VPN** | 同一机构内部不同场所之间互联 | 公司总部与分支机构 |
| **外联网VPN** | 不同机构之间的安全连接 | 企业与合作伙伴 |
| **远程接入VPN** | 单个用户远程接入机构网络 | 员工在家办公 |

### 2.4.2. 网络地址转换(NAT)

**NAT(*Network Address Translation，网络地址转换*)**：将私有IP地址转换为全球IP地址的技术，使使用私有IP地址的主机能够访问互联网。

**NAT路由器**：安装在专用网与互联网连接处的路由器，装有NAT软件。

> **注意**：NAT表项需由管理员来添加。

![555](image/4-网络层%20-%20计算机网络/网络地址转化示例.png)

**工作流程**(*以主机A访问互联网主机B为例*)：

1. **内网发往外网**：
    - 主机A发送数据报，源IP为私有地址(*`192.168.0.3`*)，目的IP为B的全球地址(*`213.18.2.4`*)；
    - NAT路由器通过NAT转换表，将其源IP地址(*`192.168.0.3`*)替换为该NAT路由器的全球IP地址(*`172.38.10.5`*)；
    - NAT路由器在**NAT转换表**中记录该映射关系。
2. **外网返回内网**：
    - 主机B返回数据报，目的IP为NAT路由器的全球IP地址；
    - NAT路由器查找转换表，将目的IP替换回主机A的私有IP地址；
    - 将数据报转发给主机A。

**NAPT(*Network Address and Port Translation*)**：利用运输层端口号，使**多个内网主机共用一个全球IP地址**同时访问互联网。将 `(私有IP, 源端口)` 映射为 `(全球IP, 新端口)`。

> **注意**：NAPT实际上修改了运输层的端口号，因此 **没有严格遵守TCP/IP体系结构** 的层次划分。

### 2.4.3. NAT与VPN的对比

| 对比项      | NAT              | VPN             |
| :------- | :--------------- | :-------------- |
| **目的**   | 解决IP地址不足，内网访问外网  | 跨地域安全通信，保护数据隐私  |
| **作用方向** | 内网 -> 外网(*单向发起*) | 双向通信(*对等*)      |
| **核心操作** | IP地址转换           | 数据加密 + 隧道封装     |
| **安全特性** | 提供基本地址隐藏         | 提供加密、认证、完整性保护   |
| **协议层次** | 网络层(*涉及传输层端口*)   | 网络层及以上(*取决于实现*) |

> **注意**：
>   **NAT** 解决 **地址转换** 的问题，让私有网络能够访问公网，通常是内网主动发起单向通信；
>   **VPN** 解决 **安全通信** 的问题，为跨地域的私有网络在公网上建立一条安全的“隧道”，实现双向的、加密的互连。

## 2.5. 地址解析协议(ARP)

网络层使用的是 *IP地址*，但实际网络链路上传送数据帧时需要使用 *MAC地址*。

每台主机都设有一个 **ARP高速缓存**，里面存有本局域网上的各主机和路由器的 *IP地址* 到 *MAC地址* 的映射表，这些都是该主机目前知道的一些 MAC地址。

![555](image/4-网络层%20-%20计算机网络/ARP地址解析协议及ARP缓存表示例.png)

### 2.5.1. ARP的基本概念

**ARP(*Address Resolution Protocol，地址解析协议*)**：用于将 **IP地址** 解析为对应的 **MAC地址**。

**适用场景**：同一个局域网内，已知目标主机的IP地址，需要获取其MAC地址以便封装MAC帧。

**ARP高速缓存**：每一台主机都维护一个ARP高速缓存，存放本局域网上各主机和路由器的 **IP地址到MAC地址的映射表**。

> **注意**：
>   ARP只能在同一局域网内使用。不同网络间的地址解析需要经过路由器逐跳完成。
>   **ARP 请求在局域网内算一次；跳跃网段时，需要路由器重新在新的网段中发送一个 ARP 请求。**

> **例题**：
> ![555](image/4-网络层%20-%20计算机网络/ARP请求例题.png)
> 6次ARP请求。
> 具体是：
>   A在本局域网1 中ARP请求 1次，直至下一个路由器1；
>   路由器1在局域网2 中重新发送 ARP请求 1次，直至下一个路由器2；
>   ……；
>   路由器5，在局域网6 中重新发送 ARP请求1次，主机B收到，并通过ARP请求中的主机A地址信息，单播给主机A ARP响应。
>   一共使用 6 次ARP请求。

### 2.5.2. ARP的工作原理

假设 *主机A* 要向本局域网上的某台 *主机B* 发送 IP数据报时，就先在其 **ARP高速缓存中查看有无 主机B 的IP地址**：
若有：就在 ARP高速缓存中查出其对应的 MAC地址，再将这个MAC地址写入MAC帧，然后通过局域网把该MAC帧发往此MAC地址；
若无：**主机A 就自动运行 ARP，然后按照下述步骤找出 主机B 的MAC地址**。

1. **ARP进程在本局域网上广播一个ARP请求分组**：
   ARP请求分组的主要内容是：
   “我的IP地址是 `209.0.0.5`，MAC地址是 `00-00-C0-15-AD-18`；
   想知道IP地址为 `209.0.0.6` 的主机的 MAC地址。”
   ![555](image/4-网络层%20-%20计算机网络/ARP工作方式广播示例.png)
2. **在本局域网上的所有主机运行的ARP进程都收到此ARP请求分组**；
3. **主机B 的IP地址与 ARP请求分组中要查询的IP地址一致，就收下了这个ARP请求分组，并向 主机A 发送ARP响应分组，其中包含了 主机B 的MAC地址**：
   ARP响应分组的主要内容是：
   “我的IP地址是 `209.0.0.6`，MAC地址是 `08-00-2B-00-EE-0A`。”
   ![555](image/4-网络层%20-%20计算机网络/ARP工作方式响应示例.png)
   > **注意**：虽然ARP请求分组是广播发送的，**但ARP响应分组是普通的单播**，即从一个源地址发送到一个目的地址。
4. 主机A 收到 主机B 的ARP响应分组后，**就在其ARP高速缓存中写入 主机B 的IP地址到MAC地址的映射**。(*同时，主机B 收到 主机A 的ARP请求分组时，也会将 主机A的地址映射写入自己的 ARP高速缓存中*)

### 2.5.3. ARP缓存与生存时间

**生存时间(*TTL*)**：ARP缓存中的每个表项都有生存时间(*通常为10~20分钟*)，超时后自动删除。

**作用**：适应网络中设备MAC地址的变化(*如：网卡更换*)。

> **注意**：
> 1. ARP请求分组是 **广播** 发送的；
> 2. ARP响应分组是 **单播** 发送的；
> 3. 发送ARP请求时，发送方会把自己的IP-MAC映射也写入请求分组，以便接收方更新自己的ARP缓存。

## 2.6. 动态主机配置协议(DHCP)

**任何连接到互联网的计算机需要配置IP地址**。

### 2.6.1. DHCP的基本概念

**DHCP(*Dynamic Host Configuration Protocol，动态主机配置协议*)**：用于给网络中的主机**自动分配IP地址**的协议。

**作用**：省去手动配置IP地址、子网掩码、默认网关、DNS等网络参数的麻烦。

**特点**：
- 是 **应用层** 协议，基于 **UDP**，服务器端使用 `67` 端口，客户端使用 `68` 端口；
- 采用 **服务器/客户** 模式，支持 **中继代理**，可以服务于不同子网的客户；
- 分配的IP地址是**临时**的，有**租用期**限制。

### 2.6.2. DHCP的工作流程

![300](image/4-网络层%20-%20计算机网络/DHCP工作示例.png)

1. **发现(*DISCOVER*)**：
	- DHCP客户(*主机*)启动时，在本地网络广播发送 **DHCP发现报文**；
	- 源IP：`0.0.0.0`，目的IP：`255.255.255.255`；
	- 目的：寻找网络中可用的DHCP服务器。
2. **提供(*OFFER*)**：DHCP 服务器先在其数据库中查找该计算机的配置信息，找到则返回，否则：
	- DHCP服务器收到发现报文后，从地址池中挑选一个可用IP地址；
	- 向客户**单播**或**广播**发送 **DHCP提供报文**；
	- 报文中包含：分配的IP地址、子网掩码、租用期、默认网关等。
3. **请求(*REQUEST*)**：
	- DHCP客户从收到的多个提供报文中**选择一个**；
	- 客户广播发送 **DHCP请求报文**，向服务器正式请求该IP地址。
	- **源地址**：`0.0.0.0`；**目的地址**：`255.255.255.255`。
4. **确认(*ACK*)**：
	- DHCP服务器收到请求后，确认资源可用；
	- 返回 **DHCP确认报文**，正式将IP地址分配给客户；
	- 客户收到确认后，开始使用该IP地址。
	- **源地址**：DHCP服务器地址；**目的地址**：`255.255.255.255`。

### 2.6.3. DHCP的租用期

DHCP服务器分配给DHCP客户的IP地址是临时的，客户使用该IP地址的时间称为 **租用期**。

> **注意**：DHCP报文只是UDP用户数据报的数据，还需要加上 UDP首部、IP数据报首部等。
> 因此，**DHCP是基于UDP的**。

## 2.7. ICMP

**ICMP(*Internet Control Message Protocol，网际控制报文协议*)**：用于在IP网络中传递**控制信息**和**差错报告**的协议。

> **注意**：ICMP报文虽然封装在IP数据报中，但它是 **网络层** 的协议，不是高层协议。

### 2.7.1. ICMP报文的分类

| 类型 | 说明 | 常见示例 |
| :--- | :--- | :--- |
| **差错报告报文** | 报告数据传输中出现的错误 | 终点不可达、时间超过、参数问题、改变路由(重定向) |
| **询问报文** | 主动发起的查询请求 | 回送请求/应答、时间戳请求/应答 |

### 2.7.2. 不应发送ICMP差错报告报文的情况

1. 对ICMP差错报告报文本身，不再发送；
2. 对分片后的**后续分片**，不发送；
3. 对具有**多播地址**的数据报，不发送；
4. 对具有**特殊地址**(*如：`127.0.0.1`、`0.0.0.0`*)的数据报，不发送。

### 2.7.3. ICMP的常见应用

- **ping**：测试两台主机之间的连通性。使用 **回送请求/回送应答** 报文；
- **traceroute**(*Unix/Linux*) / **tracert**(*Windows*)：跟踪分组从源到目的地的路径。使用 **时间超过** 报文。

> **注意**：
>   1. ping是**应用层**直接调用ICMP的例子，不经过传输层；
>   2. 差错报告报文的核心目的是**通知源主机**，而非中间路由器。

## 2.8. IPv4分组

![555](image/4-网络层%20-%20计算机网络/IP数据报格式示例.png)

### 2.8.1. IPv4 分组的格式

一个IP分组(*IP数据报*) 由 **首部** 和 **数据部分** 组成。首部前20字节固定，后面是可变部分(*选项字段*)。

#### （一） 版本

占4位，指协议 IP 的版本。

> **注意**：通信双方使用的协议IP的版本必须一致(*如：IPv4 或 IPv6*)。

#### （二） 首部长度

占4位，可表示的最大十进制数值是15，所表示数的单位是**4字节**，即最大60B。

由于IP首部的固定部分是20字节，因此首部长度字段的最小值是5。

当IP分组的首部长度不是4字节的整数倍时，必须利用最后的填充字段加以填充。

#### （三） 总长度

总长度指首部和数据之和的长度，单位为字节，长16位。因此数据报的最大长度为：$2^{16} - 1 = 65535 字节$。

> **注意**：由于每一种数据链路层协议都规定了一个数据帧中的数据字段的最大长度，即 **[最大传送单元 MTU](<3-数据链路层 - 计算机网络.md### 1.3.1. 组帧(封装成帧)>)**，因此实际很难达到总长度字段的最大值。

当一个IP数据报封装成链路层的帧时，如果数据报总长度超过了规定的 MTU 值，则需要将一个IP数据包拆分成多个IP数据包，即**分片**。

![555](image/4-网络层%20-%20计算机网络/数据报分片示例.png)

#### （四） 标识

占16位。

IP软件在存储器中维持一个计数器，每产生一个数据报，计数器就加1，并将此值赋给标识字段。

当数据报由于长度超过网络的 MTU 而必须分片时，这个标识字段的值就被复制到所有的数据报片的标识字段中。

相同的标识字段的值使分片后的各数据报片最后能正确地重装成为原来的数据报。

#### （五） 标志

占3位，但目前只有两位有意义。

| 标志位 | 名称 | 含义 |
| :--- | :--- | :--- |
| **DF** | 不要分片(*Don't Fragment*) | DF=1时禁止分片；DF=0时才允许分片 |
| **MF** | 更多分片(*More Fragment*) | MF=1表示后面还有分片；MF=0表示这是最后一个分片 |

#### （六） 区分服务

占8位，一般情况下都不使用这个字段。

> **注意**：IPv4中该字段基本未使用，在IPv6中类似的功能由 “通信量类别” 字段实现。

#### （七） 片偏移

占13位。

**片偏移指出**：较长的分组在分片后，某片在原分组中的相对位置，以 **8个字节** 为偏移单位。

![555](image/4-网络层%20-%20计算机网络/数据报分片示例.png)

> **注意**：除最后一个数据报片外，其他每个分片的长度一定是 **8字节(*64位*)的整数倍**。

#### （八） 生存时间

占8位，记为 **TTL(*Time To Live*)**，表明数据报在网络中的寿命。

由发出数据报的源点设置这个字段，用于防止无法交付的数据报无限制地在互联网中传输。

> **注意**：当前使用的TTL字段的单位为 **“跳数限制”**，路由器在每次转发数据报之前就把TTL值减1。若TTL值减小到零，就丢弃这个数据报，不再转发。

#### （九） 协议

占8位。

协议字段指出此数据报携带的数据使用何种协议，以便使目的主机的IP层知道应将数据部分上交给哪个协议进行处理。

| 协议       | 全称                                   | 协议字段值      | 功能                             |
| -------- | ------------------------------------ | ---------- | ------------------------------ |
| **ICMP** | *Internet Control Message Protocol*  | 1          | 传递网络控制信息和差错报告，如ping、traceroute |
| **IGMP** | *Internet Group Management Protocol* | 2          | 管理IP多播组成员关系                    |
| **TCP**  | *Transmission Control Protocol*      | ==**6**==  | 面向连接的可靠传输协议，提供流量控制、拥塞控制、确认重传   |
| **UDP**  | *User Datagram Protocol*             | ==**17**== | 无连接的不可靠传输协议，开销小，实时性高           |
| **OSPF** | *Open Shortest Path First*           | 89         | 内部网关路由协议，基于链路状态，使用洪泛法更新路由信息    |
> **注意**：TCP协议字段值 `6`；UDP协议字段 `17`。较为常见。

#### （十） 源地址

占32位。发送IP数据报的主机的IP地址。

#### （十一） 目的地址

占32位。接收IP数据报的主机的IP地址。

#### （十二） 首部检验和

占16位。

**作用**：只检验数据报的首部，但不包括数据部分。

> **为什么只检验首部？** 
> 不检验数据部分可减少计算的工作量，因为数据报每经过一个路由器，路由器都要重新计算一下首部检验和(*一些字段如生存时间、标志、片偏移等都可能发生变化*)。

![555](image/4-网络层%20-%20计算机网络/首部检验和示例.png)

**计算方法**：
1. **发送方**：先把 *IP数据报* 首部划分位许多 *16位字的序列*，并把检验和字段置零。
   用 **反码算数运算** 把所有 16位字相加后，将得到的 **和的反码** 写入检验和字段；
2. **接收方**：收到数据报后，把首部的所有16位字再使用反码算术运算相加一次，将得到的**和取反码**，即得出接收方检验和的计算结果：
    - 若结果为0 -> 首部无差错，保留数据报；
    - 若结果不为0 -> 首部出差错，丢弃此数据报。

#### （十三） 选项与填充

**选项字段**：长度可变，最长40字节，用于支持排错、测量、安全等功能。实际使用中很少启用。

**填充字段**：用于保证整个IP首部长度是 **4字节的整数倍**，填充内容为全0。

# 三、 IPv6

## 3.1. IPv6的主要特点

![555](image/4-网络层%20-%20计算机网络/IPv6数据报示例.png)

IPv6 数据报由两部分组成：**基本首部** 和 **有效载荷**。
> **注意**：有效载荷允许由 **零个或多个** 扩展首部，在后面是数据部分。

![555](image/4-网络层%20-%20计算机网络/IPv6结构示例.png)


### 3.1.1. IPv6与IPv4的对比

| 对比项 | IPv4 | IPv6 |
| :--- | :--- | :--- |
| **地址长度** | 32位 | **128位** |
| **地址表示** | 点分十进制 | 冒号十六进制 |
| **首部长度** | 可变(20~60B) | **固定40B** |
| **分片** | 路由器支持分片 | **仅源主机分片**，路由器不分片 |
| **校验和** | 有首部校验和 | **取消校验和** |
| **ARP协议** | 有 | **取消ARP**，由ICMPv6邻居发现协议替代 |
| **IPsec** | 可选 | **内置支持** |
| **即插即用** | 需DHCP | **支持自动配置** |

### 3.1.2. IPv6相对于IPv4的主要改进

**1. 更大的地址空间**：128位地址，从根本上解决IP地址枯竭问题。

**2. 简化的首部格式**：
- 首部长度固定为40B；
- 取消首部校验和字段，减少路由器处理开销；
- 取消分片相关字段(*标识、标志、片偏移*)，分片信息移入扩展首部。

**3. 新的字段**：
- **流标号**：用于实时音频/视频等需要特定服务质量的应用。

**4. 即插即用(自动配置)**：支持无状态地址自动配置，无需DHCP即可获得IP地址。

**5. 内置安全**：IPsec成为IPv6的强制组成部分。

**6. 取消ARP和IGMP协议**：由ICMPv6的邻居发现协议和多播侦听发现协议替代。

> **注意**：IPv6取消了首部校验和，因为数据链路层和运输层已有校验机制，避免重复计算。

## 3.2. IPv6地址

一个 IPv6 数据报的目的地址可以是以下三种基本类型地址之一：
1. **单播**：即传统的 **点对点** 的通信；
2. **多播**：是 **一点对多点** 的通信，数据报发送到一组计算机中的每一个。
   > **注意**：IPv6 没有广播的术语，而是将广播看作多播的一个特例。
3. **任播**：任播的终点是一组计算机，但**数据报只交付其中一个**，通常是按照路由算法得出的距离最近的一个。

### 3.2.1. IPv6地址的表示方法

**冒号十六进制表示法**：将128位地址分为8组，每组16位，用冒号分隔。

> **示例**：`0008:0000:0000:0000:0000:0103:CDEF:089A`

**压缩规则**：
1. 每组前导的 `0` 可省略；
2. 连续的 `0` 值域可用 `::` 缩写，**但一个地址中只能出现一次**。

> **示例**：`0008:0000:0000:0000:0000:0103:CDEF:089A` -> `8::103:CDEF:89A`

### 3.2.2. IPv4与IPv6的过渡技术

**1. 双协议栈**：
- 主机同时运行IPv4和IPv6两种协议栈；
- 根据目的地址类型选择使用IPv4或IPv6。

**2. 隧道技术**：
- 将IPv6数据报封装在IPv4数据报中；
- 在IPv4网络中传输IPv6数据报，适用于IPv6孤岛之间的通信。

> **注意**：双协议栈是过渡初期的常用方案，隧道技术用于穿越IPv4网络。

# 四、 路由算法与路由协议

**路由选择协议** 规定了互联网中的路由器应如何相互交换信息，进而生成 **路由表**。

**具体来说**：互联网由路由器连接的多个网络共同构成，分组从源主机到目的主机可能经过多个路由器也存在多条路径，**路由算法可以找到从源主机到目的主机的最佳路径**。

## 4.1. 基本概念

### 4.1.1. 路由算法的分类

路由算法主要分为 **静态** 路由算法和 **动态** 路由算法两大类。

#### （一） 静态路由算法(非自适应路由选择)

由网络管理员手工配置路由表项，当网络拓扑发生变化时，需要人为修改路由表。

![400](image/4-网络层%20-%20计算机网络/静态路由表示例.png)

**优点**：简单和开销较小。
**缺点**：不能及时适应网络状态的变化。

> **注意**：对于很简单的小网络，完全可以采用静态路由选择，人工配置每一条路由。

#### （二） 动态路由选择(自适应路由选择)

根据路由器互相交换的信息自动配置路由表项，及时对网络变化作出修改。

![400](image/4-网络层%20-%20计算机网络/自适应路由选择示例.png)

**优点**：能较好地适应网络状态的变化。
**缺点**：实现起来较为复杂，开销也比较大。

> **注意**：适用于较复杂的大网络。

### 4.1.2. 分层次的路由选择协议

**分层次的路由选择协议**：可以把整个互联网划分为许多较小的 **自治系统**(*AS，autonomous system*)，可以简单理解为划分成多个区域。

> **注意**：一个AS可能由一个或多个局域网构成，目的是为了精简路由表信息。

![555](image/4-网络层%20-%20计算机网络/分层示例.png)

互联网划分成多个 AS，因此可以将了路由选择协议划分为两大类：
1. **内部网关协议**(*IGP，Interior Gateway Protocol*)：
   IGP指在一个自治系统内部使用的路由选择协议(*如：RIP和OSPF协议*)；
2. **外部网关协议**(*EGP，External Gateway Protocol*)：
   若源主机和目的主机处在不同的自治系统中，那么在不同自治系统AS之间的路由选择，就需要使用外部网关协议EGP(*如：BGP-4，BGP的第四个版本*)。

> **注意**：每个自治系统自己决定在本自治系统内部运行哪一个内部路由选择协议。

每个自治系统都有一个或多个路由器，除运行本系统的内部路由选择协议外，还需要运行自治系统之间的路由选择协议(*如：下图R1，R2所示*)。

![555](image/4-网络层%20-%20计算机网络/外部路由协议示例.png)

自治系统之间的路由选择也叫做 **域间路由选择**，而在自治系统内部的路由选择叫做 **域内路由选择**。

![400](image/4-网络层%20-%20计算机网络/多个自治系统结构示例.png)

| 概念             | 范围                  | 作用                |
| -------------- | ------------------- | ----------------- |
| **局域网(*LAN*)** | 同一个广播域              | 解决“同网段内”的设备通信     |
| **自治系统(*AS*)** | 一个或多个局域网(*由同一机构管理*) | 解决“区域内”的路由收敛与规模控制 |
| **互联网**        | 所有AS的集合             | 解决“全球范围”的跨域路由     |

## 4.2. 内部网关协议

### 4.2.1. 内部网关协议RIP

#### （一） RIP的工作原理

**路由信息协议**(*RIP，Routing Inforation Protocol*)：是一种基于 **距离-向量** 的路由选择协议。

**距离(*跳数*)**：从路由器到直接连接的网络的距离为 `1`；到非直接连接的网络的距离为经过的路由器数 `+1`。**最大跳数为 `15`**，`16` 表示不可达。

![555](image/4-网络层%20-%20计算机网络/RIP协议示例.png)
> 上图中，`R1` 经过 3个路由器 连接到 *网络5*，中间经过了 3个路由器或经过3跳。即 `R1` 到网络5 的距离是 `4`。
> **注意**：RIP认为 **好的路由** 就是通过的网络数目少，即 **距离短**。

**更新过程**：
1. 路由器 **刚开始工作时**，路由表中只有几个直接相连的网络距离，可以为 `1`。
   ![555](image/4-网络层%20-%20计算机网络/更新过程示例1.png)
2. 接着，每个路由器 **只和相邻路由器交换并更新路由信息**，不相邻的路由器不交换信息。
   **交换信息** 指：“*我到本自治系统中 **所有** 网络的最短距离，以及每个网络应经过的下一跳路由器*”。
3. 经过若干次的更新后，**所有路由器都会知道** 到达本自治系统中任何一个网络的最短距离和下一跳路由器的地址。
  > **注意**：一般情况下，**协议RIP可以收敛，并且过程较快**。
  > **收敛**：在自治系统中所有节点都得到正确的路由选择信息的过程。
  > ![200](image/4-网络层%20-%20计算机网络/完整路由表示例.png)

> **注意**：路由表更新的原则是找出每个目的网络的最短距离，这种更新算法又称为 **距离向量算法**。

#### （二） 距离向量算法

对每一个相邻路由器发送过来的RIP报文，执行以下步骤：

**步骤1：修改RIP报文中的距离**：
对相邻路由器(设为R4)发来的RIP报文，先修改此报文中的所有项目：
- 把“下一跳”字段中的地址都改为 **R4**；
- 把所有“距离”字段的值 **加1**。
> 含义：我从R4到达某个网络的距离 = R4到达该目的网络的距离 + 1。
![555](image/4-网络层%20-%20计算机网络/RIP处理示例1.png)

**步骤2：逐项更新路由表**：
对修改后的RIP报文中的每一个项目，执行以下判断：

| 情况      | 条件                         | 操作                                     |
| :------ | :------------------------- | :------------------------------------- |
| **情况1** | 路由表中**没有**该目的网络            | **直接添加**该项目到路由表中                       |
| **情况2** | 路由表中**有**该目的网络，且**下一跳就是X** | **无条件替换**为收到的新项目(*以最新信息为准*)            |
| **情况3** | 路由表中**有**该目的网络，但**下一跳不是X** | 比较距离：若收到的距离 < 路由表中的距离，则**更新**；否则**不变** |

**步骤3：超时处理**：
若3分钟还没收到相邻路由器的更新信息，则把该路由器记为不可达，距离置为16。
> **注意**：RIP协议每隔30秒交换一次路由信息，采用 **UDP** 协议，端口520。
![555](image/4-网络层%20-%20计算机网络/更新示例.png)

#### （三） 坏消息传播得慢

**坏消息传播得慢**：又称为 **路由环路** 或 **距离无穷级数** 问题，这是 **距离向量算法的一个固有问题**。

可以采取多种 **减少** 出现该问题的概率或减小该问题带来的危害。
- 限制最大路径距离为 `15`(*16 表示不可达*)；
- 当路由表发生变化时，就立即发送更新报文(*即：触发更新*)，而不仅是周期性发送；
- 让路由器记录收到某特定路由信息的接口，而不让同一路由器信息再通过此接口反方向传送(*即：水平分割*)。
  ![555](image/4-网络层%20-%20计算机网络/坏消息传播得慢示例.png)

### 4.2.2. 内部网关协议OSPF

#### （一） 基本原理

**开放最短路径优先**(*Open Shortest Path First*)：是一种基于 **链路状态** 的路由协议。

**核心思想**：
1. 向本自治系统中 **所有路由器** 发送信息，使用 **洪泛法**；
2. 发送的信息是与本路由器 **相邻的所有路由器的链路状态**；
3. 当链路状态变化或每隔一段时间(*如：30分钟*)，路由器向所有路由器发送链路状态信息；
4. 所有路由器最终能建立一个 **链路状态数据库**，即全网的拓扑结构图，全网范围一致(*链路状态数据库同步*)。

> **注意**：
>   1. 每个路由器使用链路状态数据库中的数据，构造出自己的路由表(*使用Dijkstra最短路径算法*)；
>   2. OSPF的链路状态数据库能较快更新，收敛快；
>   3. OSPF **没有“坏消息传播得慢”** 的问题。

#### （二） 分区

为了使OSPF能够用于规模很大的网络，OSPF可以将一个自治系统再划分为若干个更小的范围，叫作 **区域**。

![555](image/4-网络层%20-%20计算机网络/分区示例.png)

- 每个区域有一个32位区域标识符(*点分十进制*)；
- 划分区域的好处：把洪泛法交换链路状态信息的范围局限于每个区域，减少网络通信量；
- **主干区域**：标识符为 `0.0.0.0`，用来连通其他下层区域；
- **区域边界路由器**：连接不同区域的路由器；
- **自治系统边界路由器**：连接本AS与外部AS的路由器。

#### （三） OSPF的五种分组类型

OSPF是基于IP的，属于网络层协议(*协议字段值为89*)。

| 分组类型 | 说明 |
| :--- | :--- |
| **问候(*Hello*)分组** | 用于发现和维护邻居关系(*每10秒交换一次，40秒未收到则视为不可达*) |
| **数据库描述(*Database Description*)分组** | 向邻居给出自己链路状态数据库中所有链路状态项目的摘要信息 |
| **链路状态请求(*Link State Request*)分组** | 向对方请求发送某些链路状态项目的详细信息 |
| **链路状态更新(*Link State Update*)分组** | 用洪泛法对全网更新链路状态(*OSPF最核心的部分*) |
| **链路状态确认(*Link State Acknowledgment*)分组** | 对链路更新分组的确认 |
> **注意**：路由器之间通过交换数据库描述分组和链路状态请求分组，实现链路状态数据库的同步。

## 4.3. 外部网关协议BGP

**BGP(*Border Gateway Protocol，边界网关协议*)**：在不同自治系统(AS)之间交换路由信息的协议，是 **外部网关协议(EGP)** 的典型代表。

![555](image/4-网络层%20-%20计算机网络/BGP示例.png)

**核心特点**：
- **类型**：基于 **路径-向量** 算法；
- **传输层协议**：基于 **TCP**，端口179；
- **交换内容**：不是距离，而是 **路径信息**(*“到达某个网络需要经过哪些AS”*)；
- **BGP发言人**：每个AS至少有一个边界路由器作为BGP发言人，负责与相邻AS交换路由信息。

**BGP路由选择原则**(按优先级)：
1. 本地偏好(*LOCAL-PREF*)值最高的路由；
2. 经过的AS数量最少的路由；
3. 使用 **热土豆路由选择** 算法(*尽快将分组送出本AS*)。

**BGP报文类型**：打开(*Open*)、更新(*Update*)、保活(*Keepalive*)、通知(*Notification*)。

## 4.4. RIP、OSPF、BGP对比总结
| 对比项       | RIP             | OSPF         | BGP          |
| :-------- | :-------------- | :----------- | :----------- |
| **协议类型**  | 内部(*IGP*)       | 内部(*IGP*)    | 外部(*EGP*)    |
| **路由算法**  | 距离-向量           | 链路状态         | 路径-向量        |
| **传输层协议** | UDP             | IP           | TCP          |
| **度量标准**  | 跳数(*≤15*)       | 代价(*带宽/时延等*) | 路径(*AS序列*)   |
| **交换对象**  | 仅相邻路由器          | AS内所有路由器     | BGP邻居(*对等站*) |
| **交换内容**  | 完整路由表           | 链路状态信息       | 可达性路径信息      |
| **核心优点**  | 实现简单            | 收敛快，支持大规模    | 策略灵活         |
| **主要缺点**  | 规模受限(*15跳*)，收敛慢 | 实现复杂         | 收敛慢(*非最佳路由*) |

![555](image/4-网络层%20-%20计算机网络/路由协议对比示例.png)

# 五、 IP组播与移动IP

## 5.1. IP组播

### 5.1.1. 组播的概念

**IP组播(*IP Multicast*)**：也称**多播**，一种一对多的通信方式，源主机只发送一份数据，目的地址为一组地址，只有加入到该组播组的主机才能收到数据。

| 通信方式 | 特点 | 适用场景 |
| :--- | :--- | :--- |
| **单播** | 一对一，每台接收方需要单独发送一份 | 普通文件传输、网页访问 |
| **广播** | 一对所有，发送给同一网络中的所有主机 | 局域网内广播消息 |
| **组播** | 一对多，发送给加入同一组播组的成员 | 视频直播、网络会议 |

**组成结构**：
- **组播组**：用IP组播地址标识的一个集合，主机可动态*加入或离开*；
- **组播源**：**产生组播数据的发送方**，一个组播源可以向一个或多个组发送组播数据；
- **组播路由器**：支持组播功能的路由器，负责组播数据的复制与转发。

![555](image/4-网络层%20-%20计算机网络/单播与组播对比示例.png)

> **注意**：组播数据报的目的地址是组播组地址，而不是单个主机地址。
>   **与的单播相比，在一对多的通信中，多播可大大节约网络资源**。

### 5.1.2. IP组播地址

IP组播所传送的分组，需要使用组播IP地址。
- **地址范围**：**D类IP地址**(*`224.0.0.0` ~ `239.255.255.255`*)，前四位固定为 `1110`；
- **组播MAC地址映射**：将IP组播地址的低23位映射到MAC地址的低23位，前缀固定为 `01-00-5E`；
- **IGMP(*Internet Group Management Protocol*)**：运行在主机和组播路由器之间，负责组播组成员管理，报文封装在IP数据报中(协议字段值为2)。

> **注意**：由于IP组播地址有28位可变，而MAC地址只映射低23位，因此 **32个IP组播地址可能映射到同一个MAC地址**。

## 5.2. 移动IP

### 5.2.1. 移动IP的概念

**移动IP**：使移动设备在不同网络中移动时，仍能保持其IP地址不变，通信不中断。

**核心概念**：

| 概念 | 含义 |
| :--- | :--- |
| **归属地址(*永久地址*)** | 设备在归属网络中的固定IP地址 |
| **转交地址(*临时地址*)** | 设备在外地网络时获得的临时IP地址 |
| **归属代理(*本地代理*)** | 归属网络上的路由器，维护设备的当前位置信息 |
| **外地代理** | 外地网络上的路由器，为设备提供转交地址 |

### 5.2.2. 移动IP通信过程

**三个阶段**：
1. **代理发现**：移动设备到达外地网络后，发现外地代理并注册；
2. **注册登记**：外地代理向归属代理登记设备的转交地址；
3. **数据传送**：
    - 发送给移动设备的数据先到达归属网络；
    - 归属代理截获数据报，通过 **隧道** 封装后转发给外地代理；
    - 外地代理解封后交付给移动设备。

![555](image/4-网络层%20-%20计算机网络/移动IP地址转交示例.png)

> **注意**：
>   1. 移动设备发送数据时，直接使用自己的归属地址作为源地址(*无需通过归属代理*)；
>   2. 移动IP对通信对端是透明的，对端不需要知道设备当前在哪个网络。

# 六、 网络层设备

## 6.1. 冲突域和广播域

[数据链路层](<3-数据链路层 - 计算机网络.md### 6.2.3. 冲突域与广播域>) 中冲突域和广播域概念。

**域**：冲突或广播在其中发生并传播的区域；
**冲突域**：连接到同一物理介质上的所有结点的集合，这些节点之间存在介质争用现象；
**广播域**：接受同样广播消息的节点集合；

局域网LAN特指使用路由器分割的网络，也就是广播域。

> **注意**：
> 1. 集线器所有端口在同一冲突域和广播域；
> 2. 交换机每个端口独立冲突域，但所有端口在同一广播域(*默认*)；
> 3. 路由器每个端口独立冲突域和独立广播域；
> 4. VLAN可以在交换机上**逻辑隔离**广播域。

## 6.2. 路由器的组成和功能

路由器是一种具有多个输入/输出端口的 **专用计算机**。
路由器主要实现：物理层、数据链路层和网络层的功能。

**路由器是网络层设备**。

**路由器的任务**：连接异构网络并完成路由转发。

**路由器的功能**：
- **分组转发**：处理通过路由器的数据流；
- **路由计算**：通过和其他路由器进行路由协议的交互，完成路由表的计算。

### 6.2.1. 路由器的组成

![555](image/4-网络层%20-%20计算机网络/路由器结构体系示例.png)

#### （一） 路由选择部分(控制层面)

三个组成部分：路由选择处理机 + 路由选择协议 + 路由表。

也叫控制部分，核心是 **路由选择处理机**。

任务是根据所选定的路由选择协议构造出路由表。

同时不断更新路由信息和维护路由表。


#### （二） 分组转发部分(数据层面)

三个组成部分：交换结构(*本身就是一个网络*) + 一组输入端口 + 一组输出端口。

三种交换方式：
- 通过存储器进行交换；
- 通过总线进行交互；
- 通过互联网进行交互。

> **注意**：转发是路由器根据转发表把收到的IP数据报从合适的端口转发出去；路由选择是多个路由器协同工作的结果。

## 6.3. 路由表与路由转发

路由表是根据路由选择算法得出的，主要用途是路由选择。

**路由表组成**：目的网络的IP地址 + 子网掩码 + 下一跳IP地址 + 接口

![555](image/4-网络层%20-%20计算机网络/R1的网络拓扑结构.png)
![555](image/4-网络层%20-%20计算机网络/R1的路由表.png)
> R1 的路由表如上所示，包含一条指向互联网的 **默认路由**。

路由表总是 **用软件实现**，转发表可以用软件也可以用硬件实现。
路由表不等于转发表，分组的实际转发是靠直接查找转发表，而不是直接查找路由表。

路由表中默认路由的目的地址和子网掩码都是 `0.0.0.0`。

> **注意**：
> 1. 转发表由路由表生成，信息更简略，查找更快；
> 2. 在讨论路由原理时，不会严格区分路由表和转发表，统称为路由表；
> 3. 默认路由用于匹配所有未明确指定的目的网路。
