# 一、 数据链路层的功能

## 1.1. 数据链路层的基本概念

### 1.1.1. 链路与数据链路

**链路** (*物理链路*) 是从 **一个节点** 到 **相邻节点** 的一段物理线路 (*有线或无线*)，而中间没有任何其他的交换节点。
> **注意**：数据通信时，两台计算机之间的通信路径往往要经过许多段这样的链路，**链路是一条路径的组成部分**。

**数据链路** (*逻辑链路*) 是除了必须有一条 **物理线路** 外，还必须有一些必要的 **通信协议** 来控制这些数据的传输。
> **注意**：将实现这些协议的硬件和软件加到链路上，就形成了数据链路。
> 最常用的是使用 **网络适配器** (*有硬件和软件*) 来实现协议。

**帧**：数据链路层对等实体间通信的 **协议数据单元**。发送方将网络层交下的数据封装为帧发送；接收方从帧中提取数据并上交网络层。

![555](image/3-数据链路层%20-%20计算机网络/协议层面数据流动示例.png)
![555](image/3-数据链路层%20-%20计算机网络/数据链路层的数据流动示例.png)

### 1.1.2. 适配器(网卡)

计算机与外界局域网通过 **适配器** 连接。
- 适配器本是主机箱内插入的“网卡”，但现在主板上均已经嵌入了适配器，不再使用单独的网卡；
- 适配器与局域网之间采用 **串行传输**；适配器与计算机之间采用 **并行传输**；
- **MAC地址** 在适配器的ROM中；**IP地址** 在计算机的存储器中。

## 1.2. 数据链路层的功能

数据链路层在网络体系结构中位于物理层与网络层之间，向上为网络层提供服务，向下使用物理层提供的比特流传输服务。

### 1.2.1. 提供的三种服务

| 服务类型           | 特点        | 适用场景                     |
| :------------- | :-------- | :----------------------- |
| **无确认的无连接服务**  | 不建立连接，不确认 | 实时通信或误码率较低的通信信道(*如：以太网*) |
| **有确认的无连接服务**  | 不建立连接，但确认 | 误码率较高的通信信道(*如：无线通信*)     |
| **有确认的面向连接服务** | 建立连接，确认   | 对可靠性、实时性要求较高的场合          |

### 1.2.2. 数据链路层的三个基本问题

数据链路层的主要任务是解决以下三个基本问题：
1. **封装成帧**(*组帧*)
2. **差错检测**
3. **可靠传输**

### 1.2.3. 两种信道类型下的协议

数据链路层根据使用的信道类型，采用不同的协议：
1. **点对点信道**：一对一的点对点通信方式；
2. **广播信道**：一对多的广播通信方式，需使用 **专用的共享信道协议** 来协调主机的数据发送。
   - 共享式以太网使用 **CSMA/CD** 协议；
   - 802.11 无线局域网使用 **CSMA/CA** 协议。

## 1.3. 基本任务

### 1.3.1. 组帧(封装成帧)

封装成帧(*组帧*)是指在 **一段数据的前后** 分别添加 *首部和尾部*，这样组成了一个帧。

每种链路层协议都规定了所能传送的帧的数据部分长度上限——**最大传送单元MTU(*Maximum Transfer Unit*)**
即：数据链路层把网络层交下来的数据构成帧发送到链路上，以及把接收到的帧中的数据取出并上交给网络层。

![350](image/3-数据链路层%20-%20计算机网络/封装成帧示例.png)

**首部尾部作用**：
1. **帧定界**：确定帧的界限；
2. 包括许多必要的 **控制信息**(*如：地址信息以及差错控制*)。

发送帧时，从 **帧首部开始发送** -> 接收端在收到物理层上交的比特流后，就能根据首尾部的标记，从收到的比特流中识别帧的开始和结束。

#### （一） 帧定界符

当数据是由 ASCII码 组成的文本文件时，**帧定界可以使用特殊的帧定界符**。

**控制字符SOH(*Start Of Header*)**：放在一帧的最前面，标识帧的首部开始；
**控制字符EOT(*End Of Transmission*)**：表示帧的结束。

它们的二进制数分别是 `00000001 B` 和 `00000100 B`。

![350](image/3-数据链路层%20-%20计算机网络/控制字符进行帧定界方法示例.png)

### 1.3.2. 透明传输

无论怎样的比特组合的数据，都能够按照原样没有差错地在数据链路层中传输。
即：数据链路层对这些数据来说是 **透明的**，不用考虑数据链路层的数据格式等要求。

#### （一） 字节填充法

帧的开始和结束的标记使用专门的控制字符，所传输的数据中的任何 `8bit` 的组合一定不允许和用作帧定界的控制字符的比特编码一样，否则会出现**帧定界的错误**。

![400](image/3-数据链路层%20-%20计算机网络/帧非透明传输示例.png)
> **注意**：上例是非透明传输，当数据中碰巧出现字符 `EOT` 时，就无法传出。
> 而后续的数据因为无匹配的 `SOH` ，被接收端当作无效帧丢弃。

![400](image/3-数据链路层%20-%20计算机网络/ESC的应用示例.png)

**解决方法**：在 `SOH` 或 `EOT` 前，插入一个转义字符 `ESC`(*二进制数：`00011011`*)。
- 接收端在把数据送往网络层之前，**删除插入的转义字符**；
- 如果转义字符同样出现在数据中，那么就再插入一个转义字符在其前，收到连续的两个转义字符时，**删除前一个**。

> **注意**：透明传输的核心思想是 **数据部分出现的控制字符不应被解释为控制信息**。字节填充法、零比特填充法、违规编码法均是为实现透明传输而设计的具体手段。

#### （二） 字符计数法

在帧的首部用一个计数字段标明该帧所包含的字节数(*包括计数字段自身*)，接收方根据该计数值确定帧的结束位置。

![350](image/3-数据链路层%20-%20计算机网络/字符计数法示例.png)

**优点**：实现简单，无需数据填充。
**缺点**：若计数字段在传输过程中出错，接收方将错误划分帧边界，导致后续帧全部错位，因此很少单独使用。

#### （三） 零比特填充的首位标志法

使用特定的比特序列 `01111110`(*连续的六个1*)表示一帧的开始和结束。

![555](image/3-数据链路层%20-%20计算机网络/零比特填充示例.png)

**填充规则**：发送方扫描数据部分，若出现**连续的五个1**，则在其后**插入一个0**；
**删除规则**：接收方扫描数据部分，若出现**连续的五个1**，则将其后的**一个0删除**，还原原始数据。
**优点**：透明传输，且易于硬件实现(*如HDLC协议采用此方法*)。

#### （四） 违规编码法

曼彻斯特编码中，`1` 编码为 `高-低` 电平对，`0` 编码为 `低-高` 电平对。

**`高-高` 和 `低-低` 在数据部分是违规的，不会出现在数据部分**，故以这两种违规编码作为帧的起始和终止。
**优点**：无需填充或计数即可实现透明传输。

> **注意**：违规编码法只适用于编码中存在冗余的情况。

### 1.3.3. 差错检测

现实的通信链路中，**比特在传输过程中可能会产生差错**：`1`可能变成`0`；`0`可能变成`1`，即 **比特差错**，是传输差错中的一种。

差错控制的方法一般通过 **编码技术** 来实现：
- **检错编码**：可以用于 **判断当前数据是否发生错误**；
- **纠错编码**：不仅可以判断是否发生错误，**还能确定错误发生的位置**。

#### （一） 检错编码

**奇偶校验码**：
- 在待发送的数据后面(*或者前面*)添加 *1位校验码*，使整个数据(*包括校验位*)中的 `1` 的个数为奇数或偶数。
	- **奇数个位误码**：可以检查出误码；
	- **偶数个位误码**：不能检查出误码(*漏检*)。
	![400](image/3-数据链路层%20-%20计算机网络/奇偶校验码示例.png)

**循环冗余码(*CRC*)**：
- CRC有很好的检错能力(*漏检率非常低*)；
- 计算比较复杂，但非常易于用硬件实现，因此被广泛应用于数据链路层；
- CRC具有纠错能力，但数据链路层只使用了他的检错能力，**检测出帧错误直接丢弃**。

**CRC计算步骤**：[多项式时，取最高次数个0，除数P根据多项式次数的系数确定，如：Gx=x^3+1 --> 1001]
1. 发送方和接收方事先商定一个长度 `r+1` 的除数 `P`，例如除数 `P=1101 B`。
2. 原始数据序列后添加 `r` 个 `0`，作为被除数。
   ![300](image/3-数据链路层%20-%20计算机网络/CRC计算1.png)
   ![300](image/3-数据链路层%20-%20计算机网络/CRC计算2.png)
3. 使用 `P=1011` 对被除数进行模2除法，相同位数进行**异或运算**，得到 $r$ 位余数即校验码。(*校验满称为 **帧检验序列(FCS)***)。
4. 将得到的 $r$ 位校验码拼接到原始数据序列后面，形成完整的帧发送出去。
5. 接收端将收到的帧作为被除数，用同一个除数 `P` 进行模2除法：
   - 若余数 `R = 0`，则判定帧无差错；
   - 若余数 `R ≠ 0`，则判定帧有差错，直接丢弃。

> **注意**：CRC在特定情况下，也有纠错功能，**但在数据链路层中只使用检错功能**。
> **发送端帧检验序列FCS的生成**和**接收端CRC检验**都是用**硬件**完成的。

#### （二） 纠错编码(海明码)

**纠错编码技术不仅能检测差错，而且能推导出错误的位置**，并还原出发送方实际想要发送的正确信息，实现纠错。

**海明码的工作原理**：通过**多组奇偶校验**实现。将数据位分布在多个校验组中，当某一位出错时，会引起多个校验组的结果发生变化，通过校验组的组合唯一确定出错位置。

**海明距离**：两个码字对应位不同的比特数称为海明距离。
- 一个编码集的海明距离 = 所有码字之间海明距离的最小值；
- 海明距离为 $d$ 的编码集：可检测 $d-1$ 位错，可纠正 $\lfloor (d-1)/2 \rfloor$ 位错。

**海明码的构成步骤**(*以 $n$ 位数据，$k$ 位校验位为例*)：
1. 确定校验位位数 $k$：满足 $n + k + 1 \leq 2^k$；
2. 将校验位放在 $2^{i-1}$ 位置上(*即第1、2、4、8...位*)；
3. 每个校验位负责校验一组特定位置的数据位(*该校验位所在位号的二进制表示的某一位为1的所有位*)；
4. 按奇校验或偶校验规则计算各校验位的值；
5. 接收方重新计算各校验组的校验结果，得到指错字 $S$，若 $S=0$ 则无差错，否则 $S$ 的十进制值即为出错位的位置。

> **注意**：海明码的检错/纠错能力依赖于海明距离。常规海明码(*指错字为 $k$ 位*)的海明距离为3，**可检2错纠1错**。

#### （三） 检错与纠错编码对比

| 编码方式             | 类型   | 检错能力       | 纠错能力           | 应用场景        |
| :--------------- | :--- | :--------- | :------------- | :---------- |
| **奇偶校验码**        | 检错编码 | 奇数位错       | 无              | 简单通信        |
| **循环冗余码(*CRC*)** | 检错编码 | 强(*漏检率极低*) | 无(*数据链路层仅用检错*) | 数据链路层       |
| **海明码**          | 纠错编码 | 双比特错       | 单比特错           | 内存校验、某些通信场景 |

# 二、 流量控制与可靠传输机制

检错以及差错编码仅仅能解决 **比特差错** 的问题，但是无法解决 **帧丢失、帧重复或帧失序** 的问题，因此增加了帧编号、确认和重传机制。
- **确认**：接收方收到正确的帧，就要向发送端发送确认；
- **重传**：发送端在一定期限内若没有收到对方的确认，就认为出了差错，**因而就进行重传**，直到收到对方的确认为止。

![300](image/3-数据链路层%20-%20计算机网络/重传示例.png)

基于帧编号、确认和重传机制，进一步产生了 **流量控制机制和可靠传输机制**。

> **注意**：流量控制侧重于控制 **发送方的发送速度**；可靠传输机制侧重于确保 **传输的可靠性**。

## 2.1. 流量控制

当数据链路中发送方的发送速率大于接收方的接收速率时，接收方无法全部接收发来的数据，从而导致数据的丢失，产生传输差错。
所以需要一种方法来**控制发送方的发送速率**，让接收方及时接收数据，这就是**流量控制**。

### 2.1.1. 停止-等待流量控制

**原理**：
- 发送方每次只能发送一帧；
- 接收方接收到该帧后，发回一个应答信号给发送方；
- 发送方接收到应答信号后才可以发送下一帧；
- 若发送方没有接收到接收方发回的应答信号，则需要一直等待。

![250](image/3-数据链路层%20-%20计算机网络/停止等待流量控制示例.png)

> **注意**：每次只允许发送一帧，且需要等待接收方发回应答，所以效率较低。

### 2.1.2. 滑动窗口流量控制

发送方将要发送的数据 **按帧组成一个队列**，对每一帧按顺序编号，依次发送队列里的数据。

![400](image/3-数据链路层%20-%20计算机网络/滑动窗口流量控制示例1.png)

数据链路中的发送方和接收方，分别维护一个发送窗口和一个接收窗口，假设数据传输的次序和窗口滑动的方向均从左向右。

![555](image/3-数据链路层%20-%20计算机网络/滑动窗口流量控制示例2.png)

队列里的数据主要包括四个部分：
- **已经发送并确认**的数据；
- **已经发送但未确认**的数据；
- **允许发送但未发送**的数据；
- **还不能发送**的数据。

**发送窗口限制了发送方可以发送的未经确认的帧的最大数量**。

> **注意**：若紧邻发送窗口左边界右侧的帧已经确定收到，窗口就可以向右移动，令原本不允许发送的帧被允许发送。

**接收窗口中包括当前可以接收的帧**，即序号在左边界和右边界之间的帧。

![555](image/3-数据链路层%20-%20计算机网络/滑动窗口流量控制示例3.png)

当到达 **帧的序号 *小于* 左边界**，代表该帧 **已被接收并确认**，不需要重复接收，直接丢弃；
当到达 **帧的序号 *大于* 右边界**，代表该帧 **当前还不能接收**，超过了接收方的处理范围，也会直接丢弃；
当紧邻左边界右侧的帧已经接收并确认，接收窗口随即向右移动。

![555](image/3-数据链路层%20-%20计算机网络/滑动窗口流量控制示例4.png)

### 2.1.3. 信道利用率

**信道利用率**：指发送数据所需要的时间占整个发送周期的比率。

$信道利用率 U = \frac{发送数据的时间}{一个发送周期的总时间}$

在停止-等待协议中，数据传输情况如下图中所示，假设一帧的发送时间为 $T_1$，往返传播时延是 $RTT$，接收方确认帧的发送时间是 $T_2$，则一个发送周期的总时间为 $T_1 + T_2 + RTT$。

![555](image/3-数据链路层%20-%20计算机网络/信道利用率计算实例.png)

**发送方的有效传输速率(*吞吐率*)**：指实际信道中单位时间内发送的数据量。

$有效传输速率 V_e = \frac{一个发送周期发送的数据量}{一个发送周期的总时间}$

> **注意**：一般来说 $RTT$ 都是远大于 $T_1 + T_2$ 的，所以停止-等待协议的信道利用率很低。

## 2.2. 可靠传输机制

**可靠传输**：指发送方发送的数据能够被接收方 **正确接收**。实现可靠传输需要两个重要机制：**确认和超时重传**。

使用上述两个机制地可靠传输协议称为 **自动重传请求(*ARQ，Automatic Repeat reQuest*)**，意味着 **重传是自动进行的**，接收方**不需要请求**发送方重传出错的分组。

**APQ协议注意事项**：
1. 发送方发出一帧后，**必须暂时保存该帧副本**，仅在收到相应的确认后才能将其清除；
2. 数据帧和确认帧都需要进行 **编号**，便于分辨确认帧是针对哪一帧进行的确认，以及哪些帧还未确认；
3. 超时计时器设置的 **重传时间** 应当比一帧的往返传播时间 **要长一些**：
	1. **太短**：产生不必要的重传，浪费链路资源；
	2. **太长**：通信的效率降低。

ARQ协议分为：**停止-等待协议、后退N帧协议和选择重传协议**。

### 2.2.1. 停止-等待协议

和流量控制中的停止-等待相同原理。

**基本原理**：
- 发送方每次只能发送一帧，发送后等待接收方的确认；
- 接收方收到正确的帧后，发回**确认帧(*ACK*)**；
- 发送方收到确认帧后，才发送下一帧；
- 若发送方在超时时间内未收到确认帧，则重传该帧。

**特点**：
- 发送窗口大小 = 1，接收窗口大小 = 1；
- 实现简单，但信道利用率较低；
- 数据帧和确认帧都只需用 1 位编号(*`0` 和 `1` 交替即可*)。

**可能出现的错误情况**：
1. **数据帧丢失或出错**：接收方无确认，发送方超时重传；
2. **确认帧丢失**：发送方超时重传，接收方收到重复帧后丢弃，并再次发送确认；
3. **确认帧迟到**：发送方已超时重传，收到迟到的确认帧后直接丢弃。

**信道利用率**：
$$\eta = \frac{T_{数据帧发送}}{T_{数据帧发送} + 2 \times T_{单向传播时延} + T_{确认帧发送}}$$
> **例题**：
> ![555](image/3-数据链路层%20-%20计算机网络/停止等待例题.png)
> 
> 画出传输草图：
> ![555](image/3-数据链路层%20-%20计算机网络/停止等待例题解答草图.png)
> 其中信道利用率 = 数据帧发送时延 / (数据帧发送时延 + 端到端往返时延)
> 假设数据帧长度为 X 比特。
> $40 \% = \frac{\frac{X \ b}{3k \ b/s}}{\frac{X \ b}{3k \ b/s} + 2 \times 200 \ ms}$
> X = 800 比特。

### 2.2.2. 后退N帧协议(GBN)

**基本原理**：
- 发送方可在未收到确认的情况下，连续发送发送窗口内的多个帧；
- 接收方采用 **累计确认**：收到一个帧后，发回对该帧及之前所有帧的确认；
- 接收窗口大小 = 1，接收方只按序接收，乱序帧直接丢弃；
- 若某个帧丢失或出错，发送方需 **回退到该帧**，重传该帧及其之后的所有帧。

![400](image/3-数据链路层%20-%20计算机网络/后退N帧协议示例.png)

**特点**：
- 提高了信道利用率(*相比停止-等待协议*)；
- 接收方缓存需求低(*窗口为1*)；
- 当信道误码率较高时，回退重传的开销较大。

**发送窗口大小限制**：
- 假设帧编号位数为 $n$，则发送窗口大小 $W_T$ 必须满足：$$1 \leq W_T \leq 2^n - 1$$
- 若不满足该条件，会出现 **新帧与旧帧无法区分** 的问题。

> **注意**：为了防止发送窗口和接收窗口出现相同的帧号，则需要限制发送窗口的大小。

> **例题**：
> ![555](image/3-数据链路层%20-%20计算机网络/后退N帧例题.png)
> **解析**：
>   直到超时，只有1号帧的确认帧(*ACK*)丢失，但是最后3号帧收到确认帧(*ACK*)，代表0~3号都已确认。
>   而此前发送是0~7号，此时4~7号之间都没有收到确认帧(*ACK*)，因此需要重传4~7号帧，即重传4帧。
> ![555](image/3-数据链路层%20-%20计算机网络/后退N帧例题解析.png)

### 2.2.3. 选择重传协议(SR)

**基本原理**：
- 发送方可在未收到确认的情况下，连续发送发送窗口内的多个帧；
- 接收方采用 **单独确认**：每个正确接收的帧都单独发回确认；
- 接收窗口大小 > 1，接收方可缓存 **乱序到达** 的帧，仅丢弃出错的帧；
- 发送方仅重传 **出错的帧或超时的帧**，无需回退。

**特点**：
- 进一步提高了信道利用率(*尤其在误码率较高的信道中*)；
- 接收方需要较大的缓存空间(*用于暂存乱序帧*)；
- 实现比 GBN 更复杂。

**窗口大小限制**：
- 假设帧编号位数为 $n$，则发送窗口 $W_T$ 和接收窗口 $W_R$ 必须满足：$$W_T + W_R \leq 2^n$$
- 通常取 $W_T = W_R = 2^{n-1}$，以避免新帧与旧帧混淆。

> **例题**：
> ![555](image/3-数据链路层%20-%20计算机网络/选择重传例题.png)
> **解析**：
>   接收方每收到一个数据帧，都发回相应的确认帧(*ACK*)。
>   由题目可知，发送0~3号数据帧--窗口大小为4；1号收到确认帧(*ACK*)，0、2号超时，则需要重传0、2号，**窗口不移动**，由于3号还未知，所以暂时不考虑3号。
> ![555](image/3-数据链路层%20-%20计算机网络/选择重传例题解析.png)

> **注意**：如果将题目更改：0号确认，1，2号超时，3号未知。
> 那么此时，需要重传的是1，2号，且窗口向右移动一格，并发送4号数据帧(*作为新帧发送*)。

### 2.2.4. 连续ARQ的信道利用率

连续ARQ(*包含GBN和SR*)的信道利用率取决于**发送窗口大小**与**一个发送周期内能发送的帧数**之间的关系。

假设：发送窗口允许发送方连续发送n帧；$T_1$ 为一个数据帧的发送时间；$T_2$ 为一个确认帧的发送时间，分两种情况讨论：

1. $nT_1 < T_1 + T_2 + RTT$，即在一个发送周期内 **可以发送完** n帧(*n=3*)：
   ![555](image/3-数据链路层%20-%20计算机网络/连续信道利用率情况1.png)
   则对应的信道利用率为：$U = \frac{nT_1}{T_1 + T_2 + RTT}$. 
   
2. $nT_1 < T_1 + T_2 + RTT$，即在一个发送周期内 **无法发送完** n帧(*n=3*)：
   ![555](image/3-数据链路层%20-%20计算机网络/连续信道利用率情况2.png)
   此时，发送方不断连续发送数据，信道利用率为1。

> **注意**：数据链路层的发送和接收窗口的大小是固定的(*区别于传输层*)。

# 三、 介质访问控制

广播信道使用 **一对多的广播通信方式**，连接的主机很多，因此必须使用 **专用的共享信道协议来协调这些主机的数据发送**。

当一个广播信道接入了多台设备，**两个或多个设备同时使用信道将产生冲突**。因此需要使用 **介质访问控制**(*MAC，Medium Access Control*)机制解决信道使用权的问题。

介质访问控制分为：**静态划分信道机制** 和 **动态媒体接入控制机制**。

> **注意**：只有使用广播信道的数据链路层(*多个主机接入一条信道*)，才需要考虑介质访问控制。
> 如果是点对点全双工的数据链路层，则不需要考虑(*信道上只会有一个主机使用，不可能产生冲突*)。

![250](image/3-数据链路层%20-%20计算机网络/全双工通信示例.png)

## 3.1. 信道划分介质访问控制

**信道划分**：将一个信道合理地划分成 *多个小的信道*，每个小的信道分给一个设备使用。

**多路复用**：发送端将多个发送方的信号先进行组合，然后在一条专用的信道上进行传输，最后在接收端将多路复合信号分离出来，分发给对应的接收方。

![555](image/3-数据链路层%20-%20计算机网络/信道复用示例.png)

**多路复用技术主要有四种**：频分复用；时分复用；波分复用；码分复用。

### 3.1.1. 频分复用(FDM)

**频分复用(*FDM*)**：将传输信道的总带宽(*总的频率范围*)按分为若干个互不干扰的子信道(*子频带，即某个频率范围*)，然后分配给不同的主机使用，所有的子信道可以用 **并行** 的方式传输数据。

![555](image/3-数据链路层%20-%20计算机网络/频分复用FDM示例.png)

频分复用要求信道总频率宽度大于所有子信道频率宽度之和。同时，为了保证子信道之间互不干扰，需要在它们之间加入 **隔离带**。

**频分复用技术更适合传输模拟信号**。

> **注意**：频分复用本质是将 **物理信道** 划分成了若干个逻辑上的点对点子信道，这些点对点子信道在通信时互不干扰。

### 3.1.2. 时分复用(TDM)

**时分复用(*TDM*)**：
- 将全部的传输时间分割成一个个**等长的时间片段**，称为 **TDM帧**(*与数据帧的概念无关*)；
- 再在每一个TDM帧中划分出等长的时间片段，称为 **时隙**；
- 每台主机在每一个TDM帧占用 **固定序号** 的时隙，这样每台主机**只能在指定的时间内发送数据**，也就实现了在一条信道上传输多个信号。

![555](image/3-数据链路层%20-%20计算机网络/频分复用TDM示例.png)

> **注意**：由于时分复用是**按固定的顺序**依次分配时隙，当某个主机被分配到时间片时正好没有数据需要传输，那就*只能让传输信道空闲*，导致复用后信道的利用率不高。

**统计时分复用(*STDM，Statistic TDM*)**：又称 **异步时分复用**，解决了普通时分复用信道利用率不高的问题。
通过 **集中器(*concentrator*)** 实现，发送方的各个主机的数据会被存储到集中器的输入缓存中，集中器按顺序扫描缓存，将缓存中的数据填入STDM帧中，当一个帧的数据填满后，就将此帧发送出去。

> **注意**：统计时分复用的时隙是 **动态分配** 的。

**TDM 更适合传输数字信号，是计算机网络中更常用的方式**。

### 3.1.3. 波分复用(WDM)

**波分复用(*WDM*)**：实际上是对光信号的频分复用。此技术运用于光纤中，能够使用一根光纤来同时传输多种不同频率的光信号，成倍增加了光纤的传输能力。

![555](image/3-数据链路层%20-%20计算机网络/波分复用WDM示例.png)

> **例如**：8路传输速率均为2.5Gbit/s的光载波(*其波长均为1310nm*)，经光的调制后，分别将波长变换到1550～1557nm，每个光载波相隔1nm。(*光速 = 波长 × 频率*)
> 这8个波长很接近的光载波经过光复用器后，在一根光纤中传输。因此，在一根光纤上数据传输的总速率就达到 $8 \times 2.5\text{Gbit/s} = 20\text{Gbit/s}$。

### 3.1.4. 码分复用(CDM/CDMA)

**码分复用(*CDM*)**，也叫 **码分多址(*CDMA*)**，其基本思想与频分复用(*FDM*)类似：
- 频分复用中，每个发送方都有自己的频率范围，**多个发送方的信号被叠加在一起后传输**。
  接收端通过**分离出不同频率范围的信号**，从而使得多个接收方能分别接收属于自己的信号。

![555](image/3-数据链路层%20-%20计算机网络/码分复用CDM示例.png)

在码分复用中，发送一比特的时间被拆分成 $m$ 个短的时间间隔，称为 **码片**，每个码片内可以发送一个高电平或低电平。

若 $m = 8$，则一个比特用8个高低电平的交替组合来表示，称为 **码片序列**。
- 用 `1` 表示高电平，`0` 表示低电平，**则一个码片序列可以写为一串二进制数**；
- 每个发送方的码片序列 **唯一**，可以将多个发送方的信号叠加在一起后传输；
- 接收端通过某种方法可以 **分离出不同信号**，从而使得多个接收方分别接收属于自己的信号。

**码片序列的正交性**：
1. 分配给每个主机的码片是 **相互正交** 的，即向量S和T的规格化内积为0：
   $S \cdot T = \frac{1}{m} \sum_{i=1}^{m} S_i T_i = 0$
2. 码片序列自己与自己的规格化内积为 **1**：
   $S \cdot S = 1$
3. 码片序列自己与自己的反码的规格化内积为 **-1**：
   $S \cdot (\bar{S}) = -1$

> **注意**：在主机发送数据时，以自身码片序列代表比特 `1`，以其 **二进制反码** 代表比特 `0`。
> 接收方收到叠加的码片序列后，只需将S、T与N相乘，即可得到S、T发送的数据。

![555](image/3-数据链路层%20-%20计算机网络/码分复用CDM示例2.png)


> **例题**：
> ![555](image/3-数据链路层%20-%20计算机网络/码分复用CDM例题1.png)
> 此题只需将S和T站的码片序列内积并除以序列长度即可，若内积为0，则表示正交；反之非正交。
> ![555](image/3-数据链路层%20-%20计算机网络/码分复用CDM例题2.png)

## 3.2. 随机访问介质访问控制

**胜者通过争用获得信道，从而获得信息的发送权，又称争用型协议。**

在随机访问协议的总线形网络中，主机可以随意发送信息。如果有多台主机在**同一时刻发送信息**，那么在共享信道上就会**发生碰撞**，使得这些*主机的发送都失败*。

为解决问题，需要让 **每个发送失败的主机** 都以一定的规则 **重传**，直到发送成功为止，这就是随机访问介质控制的核心思路。

### 3.2.1. ALOHA协议

#### （一） 纯ALOHA协议

【**想发就发，随机重发**】

**基本思想**：
- 局域网中的所有主机在发送信息前无需任何检测，可以直接发送；
- 如果在一定时间内未收到接收方发来的确认信息，那么认为发送成功。
  如果在时限内未收到确认，则认为发生了冲突，发送方需要等待一段随机的时间后 **重发**，重复这个过程直至发送成功(*在时限内收到确认帧*)为止。

![555](image/3-数据链路层%20-%20计算机网络/纯ALOHA协议示例.png)

**特点**：
- **优点**：实现简单，主机随时可发；
- **缺点**：冲突概率高，信道利用率低(*理论最大约为 18.4%*)。

#### （二） 时隙ALOHA协议

【**时隙发送，时隙重发**】

时隙 ALOHA 协议将时间划分为等长的时隙，并规定：
- 主机 **只有在每个时隙开始的时刻** 才能发送帧；
- 发送一帧的时间必须 ≤ 时隙的长度(*或者 =时隙长度*)。

![555](image/3-数据链路层%20-%20计算机网络/时隙ALOHA协议示例.png)

**特点**：
- **优点**：相较于纯ALOHA，冲突概率降低，信道利用率提高(*理论最大约为 36.8%*)；
- **缺点**：需要全网时间同步。

### 3.2.2. CSMA协议

如果主机在发送前 **检测信道是否被占用**，仅当未被占用才开始发送数据，则将 **大幅降低冲突发生的概率**，因此产生了 **载波侦听多路访问**(*CSMA，Carrier Sense Multiple Access*)。

**载波**：在通讯信道上传输信号的特定频率的电磁波，信道中有载波即说明信道正在被只能用。

**原理**：
- 每台主机在 **发送数据前** 先使用载波侦听装置 **检测当前信道是否被占用**，使用某种策略决定是否发送数据；
- 当发生冲突时，**随机等待一段时间后**，再重新开始侦听信道。

主机发送数据的策略主要有以下三种。

1. **1-坚持CSMA**：
	- 侦听到信道 **空闲** -> **立即发送**；
	- 侦听到信道 **忙** -> **持续侦听**，直到信道空闲后立即发送。
   **特点**：
	- 信道利用率较高；
	- 多个主机同时等待信道空闲时，易发生冲突。
2. **非坚持CSMA**：
	- 侦听到信道 **空闲** -> **立即发送**；
	- 侦听到信道 **忙** -> **随机等待一段时延后**，再重新侦听。
   **特点**：
	- 冲突概率降低；
	- 信道利用率降低(*等待期间信道可能空闲*)。
3. **p-坚持CSMA**：
	- 适用于 **分时隙** 的信道；
	- 侦听到信道 **空闲**：
		- 以概率 $p$ 立即发送；
		- 以概率 $1-p$ 推迟到下一个时隙再侦听；
	- 侦听到信道 **忙** -> 推迟到下一个时隙再侦听。
   **特点**：
	- 既能减少冲突，又能充分利用信道；
	- 是 1-坚持和非坚持的折中。

### 3.2.3. CSMA/CD协议

【**发前先听，边发边听，冲突停发，随机重发**】

总线网使用的协议 **CSMA/CD(*Carrier Sense Multiple Access with Collision Detection*)**：
载波侦听多路访问/碰撞检测。

在CSMA协议基础上加入了 **碰撞检测** 机制：**边发送边监听**。
适配器在发送数据的同时检测信道上的信号电压变化，若有多个主机同时发送，总线上的信号电压变化幅度会变大。

**工作流程**：
1. 适配器将**数据封装成帧**，准备发送；
2. 侦听信道，若信道 **忙**，持续侦听直到空闲，然后开始发送；
3. **发送过程中持续侦听**，进行碰撞检测：
	- 若整帧发送完毕未检测到碰撞 -> 发送成功；
	- 若检测到碰撞 -> 立即停止发送，发送 **拥塞信号**，通知全网(*信道上所有的主机*)；
4. 停止发送后，执行 **截断二进制指数退避算法**，等待随机时间后返回步骤 2。

**争用期(*碰撞窗口*)**：
- 信号在总线上传播的 **往返时延**($2\tau$)；
- 在争用期内未检测到碰撞，则后续不会再发生碰撞；
- 最小帧长 = 争用期 × 数据传输速率。

**截断二进制指数退避算法**：
1. 确定基本退避时间：两倍的总线端到端传播时延 $2\tau$(*争用期*)；
2. 定义 k = min(重传次数，10)；
3. 从 $[0, 1, \dots, 2^k - 1]$ 中随机取整数 $r$；
4. 退避时间 = $r \times 2\tau$；
5. 重传次数达到 16 次仍失败 -> 丢弃该帧，报告错误。

![555](image/3-数据链路层%20-%20计算机网络/传播时延对载波监听的影响.png)

### 3.2.4. CSMA/CA协议

无线局域网实用的协议 **CSMA/CA(*Carrier Sense Multiple Access with Collision Avoidance*)**：
载波侦听多路访问/碰撞避免。

无线局域网中无法实现 **碰撞检测(*CD*)**，原因如下：
1. 无线信号衰减快，碰撞检测需要很大的信号强度范围；
2. **隐蔽站问题**：站点无法检测到所有其他站点的信号；
3. **暴露站问题**：本可同时进行的通信被误判为冲突。

因此，无线局域网采用 **碰撞避免(CA)** 策略。

**基本思想**：发送前尽可能避免碰撞，一旦开始发送，**不能中途停止**。

**帧间间隔(*IFS*)**：
- **SIFS(*短帧间间隔*)**：$28 \mu s$，最短，用于分隔一次对话的各帧；
- **PIFS**：介于 SIFS 和 DIFS 之间；
- **DIFS(*分布协调功能帧间间隔*)**：$128\mu s$，用于竞争访问时的延迟。

**信道预约(*RTS/CTS*)**：
- 发送方侦听到信道空闲并等待 DIFS 后，发送 **RTS(请求发送)** 帧；
- 接收方收到 RTS 后，等待 SIFS，发回 **CTS(允许发送)** 帧；
- 发送方收到 CTS 后，开始发送数据；
- 接收方收到数据后，等待 SIFS，发回 ACK 确认。

**优点**：RTS/CTS 帧很短，碰撞只发生在 RTS 帧上，代价小；数据帧较长时效果显著。

**虚拟载波侦听**：
- 发送方在帧首部中记录 **需要占用信道的时间**；
- 其他站点收到后，在该时间段内主动停止发送，效果等同于侦听到信道忙；
- 因此称为 “虚拟” 载波侦听。

![555](image/3-数据链路层%20-%20计算机网络/虚拟载波侦听示例.png)

## 3.3. 轮询访问介质访问控制

当链路负载较大时，随机访问协议冲突概率高，传输效率低。轮询访问介质访问控制采用 **按一定次序轮流询问链路中的各个主机**，被询问到的主机才能发送数据。

**典型协议：令牌传递协议(*Token Passing Protocol*)**
- **令牌**：一个特殊的控制帧，不包含信息，仅控制信道的使用；
- 站点只有 **取得令牌** 后才能发送帧；
- 发送完成后 **释放令牌**，传递给下一站点；
- 逻辑拓扑必须为 **环形**(*物理拓扑不一定是环*)。

**特点**：
- 不会发生冲突(*令牌唯一*)；
- 访问公平；
- 负载较大时效率高；
- 若某个站点故障，令牌无法正常传递，可能导致整个网络瘫痪。

# 四、 局域网

**局域网(*LAN，Local Area Network*)** 往往覆盖较小的地理范围，**广域网** 覆盖较大的物理范围。

**将相距较远的局域网通过路由器与广域网相连**，可以组成一个覆盖范围很广的互联网。

![400](image/3-数据链路层%20-%20计算机网络/局域网示例.png)

## 4.1. 局域网的基本概念与体系结构

### 4.1.1. 基本概念

#### （一） 局域网特点

1. **范围小**：通常用于连接一个建筑物内部或距离较近的一组建筑物；
2. **速度快**：可达 `100Mb/s`、`1000Mb/s` 甚至 `10Gb/s`；
3. **低误码率**：一般在 $10^{-8}$ 到 $10^{-11}$；
4. 由于局域网传输距离较短，传输速率要求较高，因此局域网大多采用 **基带传输** 方式。

#### （二） 局域网特性的影响因素

![555](image/3-数据链路层%20-%20计算机网络/拓扑结构示例.png)
决定局域网性能差异的主要有以下三个因素：
1. **拓扑结构**：
	- **总线型**：所有站点连接在一条共享总线上，采用广播方式传输(*早期常见*)；
    - **星型**：每个站点以单独的线路与中央设备(*交换机/集线器*)相连，是目前最常用的拓扑结构；
    - **环型**：所有计算机接口设备连接成一个环，可靠性依赖环路(*常见于光纤局域网*)。
2. **传输介质**：
    - 常用介质：双绞线、同轴电缆、光纤、无线介质；
    - 采用双绞线、基带同轴电缆、光纤的局域网一般采用 **基带传输**；采用宽带同轴电缆、无线电波的网络一般采用 **频带(*宽带*)传输**。
3. **介质访问控制方法**：
    - 采用广播方式传输的局域网，需要解决的核心问题是 **介质访问控制方法**(*即：解决共享信道的竞争问题*)，不同局域网的主要差异体现在采用了不同的介质访问控制方法。

### 4.1.2. IEEE 802参考模型
IEEE 802标准遵循 ISO/OSI 参考模型的原则，主要确定 **物理层** 和 **数据链路层** 的功能。

![400](image/3-数据链路层%20-%20计算机网络/IEEE802局域网示例.png)

由于 IEEE 802 局域网大都采用 *广播式信道*，数据链路层需要介质访问控制功能。
为了使数据帧的传输独立于所采用的物理介质和介质访问控制方法，IEEE 802标准把数据链路层划分为两个子层：
- **介质访问控制子层(*MAC，Medium Access Control*)**：
    - 与接入到传输媒介相关的内容都放在该层，向上层**屏蔽物理层的差异**；
    - **主要功能**：数据帧的封装/卸装、介质访问控制等。
     ![400](image/3-数据链路层%20-%20计算机网络/介质访问控制示例.png)
- **逻辑链路控制子层(*LLC，Logical Link Control*)**：
    - 向网络层屏蔽不同的MAC层，**提供统一的接口**；
    - **主要功能**：帧编号、定义服务接入点等。
      ![250](image/3-数据链路层%20-%20计算机网络/逻辑链路控制示例.png)

## 4.2. 传统以太网

**以太网(*Ethernet*)**：是局域网组网规范。

**以太网采用无连接的工作方式，不对发送的数据帧编号，提供无连接不可靠(*不确认*)的服务。**

### 4.2.1. 以太网的发展(10Base系列)

| 标准           | 传输介质  | 最大段长  | 结点数  | 特点           |
| :----------- | :---- | :---- | :--- | :----------- |
| **10Base-5** | 粗同轴电缆 | 500m  | 100  | 抗干扰性好，早期应用   |
| **10Base-2** | 细同轴电缆 | 200m  | 30   | 价格便宜         |
| **10Base-T** | 双绞线   | 100m  | 1024 | 易于维护，星型拓扑    |
| **10Base-F** | 光纤    | 2000m | 1024 | 距离长，适用于楼宇间连接 |

> **注意**：“10”表示传输速率为 `10Mb/s`；“Base”表示基带传输；“5/2/T/F”分别表示最大段长(百米)或传输介质类型(T=双绞线，F=光纤)。

### 4.2.2. 以太网的工作原理

**总线**：总线网每个站都通过收发器连接到一条公用的总线上。

**广播式通信和争用总线**：各结点通过公共总线发送自己的信息，而其他结点都可以从总线上接收到这些消息。

**网卡**：一台主机与局域网中的其他主机进行通信，需要使用的硬件设备称为通信适配器或者网卡。
> **注意**：计算机的硬件地址(*MAC地址*)就在适配器的ROM中，而计算机的软件地址——IP地址，则在计算机的存储器中。

**传统以太网采用 *CSMA/CD* 协议解决总线争用问题。**

### 4.2.3. 以太网MAC帧格式

以太网与 IEEE 802 的帧格式不同，两种帧格式兼容，**可同时在同一局域网使用**。

![555](image/3-数据链路层%20-%20计算机网络/以太网MAC帧格式示例.png)
> **注意**：一般考察的是以太网帧。

| 字段                | 长度(字节)  | 说明                      |
| :---------------- | :------ | :---------------------- |
| **前同步码**         | 7       | 10101010重复，用于同步        |
| **帧开始定界符(*SFD*)** | 1       | 10101011，标志帧的开始         |
| **目的地址(*DA*)**    | 6       | 目的主机的MAC地址              |
| **源地址(*SA*)**     | 6       | 源主机的MAC地址               |
| **类型(*TYPE*)**    | 2       | 标志上一层使用的协议类型(*如：IP*)    |
| **数据部分**          | 46~1500 | IP数据报，长度范围由CSMA/CD协议决定  |
| **帧检验序列(*FCS*)**  | 4       | CRC校验码，校验除前导码外的所有信息     |

> **注意**：
>   以太网没有尾部定界符，利用曼彻斯特编码的违规编码(*保持电压不变*)来识别帧的结束；
>   最小帧长64B(*数据部分至少46B*)，由CSMA/CD协议决定；
>   最大帧长1518B(*数据部分最多1500B*)，防止单站长时间占用信道。
>   ![555](image/3-数据链路层%20-%20计算机网络/以太网曼彻斯特编码示例.png)

### 4.2.4. MAC地址分类

**MAC地址长度**：6字节(*48位*)，通常用十六进制表示(*如：8C-85-90-21-10-D3*)；
**MAC地址结构**：高24位为厂商代码，低24位为厂商自行指派的网卡序列号；

**MAC地址分类**：
- **单播MAC地址**：用于单播，即向局域网中的 **单个主机** 发送MAC帧。
- **组播MAC地址**：用于组播，即向局域网中的 **某一些主机** 发送MAC帧。
- **广播MAC地址**：所有位全为 `1` 的MAC地址，即 `FF-FF-FF-FF-FF-FF`，是组播MAC地址的一个特例。用于广播，即向局域网中的 **所有其他主机** 发送MAC帧。

> **注意**：MAC地址是对网络上各接口的唯一标识，而**不是对设备的唯一标识**(*一台设备有多个网卡则对应多个MAC地址*)。
> **网络上的接口不一定必须是物理接口，还可以是虚拟接口。**

### 4.2.5. 高速以太网

| 名称 | 传输速率 | 传输介质 | 通信模式 | CSMA/CD |
| :--- | :--- | :--- | :--- | :--- |
| **100Base-T(快速以太网)** | 100Mb/s | 双绞线 | 支持半双工/全双工 | 半双工时使用 |
| **千兆以太网** | 1Gb/s | 双绞线/光纤 | 支持半双工/全双工 | 半双工时使用 |
| **10吉比特以太网** | 10Gb/s | 双绞线/光纤 | 仅全双工 | 不使用 |

## 4.3. 无线局域网

**IEEE 802.11 无线局域网**：有固定基础设施，使用 802.11 系列标准，**又称为无线以太网**。
**自组网络**：无固定基础设施。

固定设施在移动通信领域通常指 **预先建立的固定基站**，负责无线信号的 **发送和接收**。

> **注意**：无线信号的传输距离通常比有线信号短。

### 4.3.1. IEEE 802.11 无线局域网

**特点**：
1. 采用星形拓扑结构，中心称为接入点(*AP，Access Point*)；
2. 使用 CSMA/CA 协议进行介质访问控制。

**基本服务集(*BSS，Basic Service Set*)**：无线局域网的最小构件，包含一个接入点(*AP*)和若干个移动站。
**扩展服务集(*ESS，Extended Service Set*)**：通过分配系统(*DS*)将多个BSS相互连接构成。

### 4.3.2. IEEE 802.11 局域网的MAC帧

802.11 帧有三种类型：**数据帧、控制帧和管理帧**。
**组成**：
1. **MAC首部**：共30字节。帧的复杂性都在MAC首部；
2. **帧主体**：即帧的数据部分，不超过2312字节；
3. **帧检验序列**：FCS是MAC尾部，共4字节。

![555](image/3-数据链路层%20-%20计算机网络/802局域网数据帧示例.png)

帧首部中最关键的四个地址字段(*均是MAC地址*)：

| 去往AP | 来自AP | 地址1       | 地址2       | 地址3  | 地址4 | 场景 |
| :---: | :---: | --------- | --------- | ---- | --- | --- |
| 0 | 0 | 目的地址 | 源地址 | BSSID | — | 同一BSS内站点间通信 |
| 0 | 1 | 目的地址 | AP地址 | 源地址 | — | AP->站 |
| 1 | 0 | AP地址 | 源地址 | 目的地址 | — | 站->AP |
| 1 | 1 | 目的AP地址 | 源AP地址 | 目的地址 | 源地址 | AP间转发 |

> **注意**：考试中最常考查的是 **ToDS=1/FromDS=0**(站->AP)和 **ToDS=0/FromDS=1**(AP->站)两种情况，需重点掌握。

# 五、 广域网

## 5.1. 广域网基本概念

**广域网**(*WAN，Wide Area Network*)：指覆盖范围很广(*超出一个城市的范围*)的长距离网络，通常连接着不同地区的局域网或城域网。

**广域网可以在多个地区、国家或者大洲之间形成通信网络，提供远距离通信。**

![555](image/3-数据链路层%20-%20计算机网络/广域网在互联网中的示例.png)

> **注意**：广域网不等同于互联网。
> **互联网强调的是不同网络之间的互相连接**，不同网络之间通常使用路由器连接。
> **广域网只是单一的网络，使用结点交换机来连接网络中的各个主机**，结点交换机负责在单个网络中转发分组。

## 5.2. PPP协议

### 5.2.1. PPP 协议的帧格式

![555](image/3-数据链路层%20-%20计算机网络/PPP协议帧格式示例.png)
- **标志字段F**：首部和尾部各有一个标志字段，规定为 `0x7E`(*二进制为 01111110*)，表示一个帧的开始或结束；
- **协议字段**：占两个字节，表示信息部分是什么类型的数据(*如：协议字段为 `0x0021` 时，代表信息字段是 IP数据报*)。
- **信息字段**：长度可变，存放实际要传输的数据(*由于使用的是点对点的双全工通信，所以不用CSMA/CD协议，也就不会有最短帧长的限制*)；
- **帧检验序列FCS**：占两个字节，是使用CRC算法计算的帧检验序列。

### 5.2.2. PPP 帧的透明传输

PPP协议是面向字节的，既支持在异步链路中传输，也支持同步链路中传输。

**同步链路**：在数据传输过程中，**发送方和接收方的时钟信号是同步的**，数据传输的节奏和速度是一致的；
**异步链路**：在数据传输过程中，**发送方和接收方没有同步的时钟信号**，数据传输的速度和节奏不一定是一致的。

![555](image/3-数据链路层%20-%20计算机网络/透明传输示例.png)

**透明传输方式**：
- **异步链路(*默认*)**：采用 **字节填充法** 实现透明传输；
- **同步链路**：采用 **零比特填充法** 实现透明传输。

### 5.2.3. PPP协议的差错检测

PPP协议使用 **CRC校验**(*循环冗余校验*)进行差错检测。

**特点**：
- 能够检测出接收到的帧是否存在比特差错；
- **不提供纠错功能**；
- **不使用序号和确认机制**，是不可靠的传输协议。
- 若检测到帧出错，**直接丢弃**，不通知发送方重传。

> **注意**：PPP协议只保证 **无差错接收，不保证可靠交付**。可靠传输由上层协议(*如：TCP*)负责。

### 5.2.4. PPP协议的工作状态

PPP协议是 **面向连接** 的(*需要建立和释放连接*)，工作过程分为以下几个状态：

| 状态        | 说明                                                    |
| :-------- | :---------------------------------------------------- |
| **链路静止**  | 通信双方不存在物理层的连接，是PPP的起始状态                               |
| **链路建立**  | 物理层连接建立后，进入链路建立状态，通过 **LCP** 协商链路配置选项(*如：最大帧长、认证协议等*) |
| **鉴别**    | 双方通过 **LCP** 进行身份验证(*可选，如：PAP/CHAP*)。若鉴别失败，则进入链路终止状态  |
| **网络层协议** | 鉴别成功后，通过 **NCP** 协商网络层协议(*如：IP地址分配*)，配置完成后进入链路打开状态    |
| **链路打开**  | 双方可以进行数据传输                                            |
| **链路终止**  | 数据传输结束后，一方发送终止请求，另一方确认后释放连接，返回链路静止状态                  |

> **注意**：
>   **LCP(*Link Control Protocol*)**：链路控制协议，用于建立、配置和测试数据链路连接。
>   **NCP(Network Control *Protocol*)**：网络控制协议，用于对不同网络层协议进行连接建立和参数协商(*如：IPCP用于IP协议*)。
>   PPP协议的身份鉴别是可选的，但实际应用中通常都会启用(*如：PPPoE拨号*)。

# 六、 数据链路层设备

## 6.1. 交换式以太网

### 6.1.1. 以太网交换机的基本特点

**以太网交换机**(*Switch*)实质上是一个 **多端口的网桥**，工作在数据链路层。

**核心特点**：
1. **每个端口独占带宽**：每个端口直接连接一台主机或另一个交换机，形成独立的**冲突域**；
2. **全双工通信**：支持全双工模式，**不使用CSMA/CD协议**；
3. **并行通信**：可同时连通多对端口，多对主机可同时通信；
4. **帧缓存**：端口有存储器，可在输出端口繁忙时缓存帧。

### 6.1.2. 交换方式

| 交换方式       | 工作原理               | 优点             | 缺点               |
| :--------- | :----------------- | :------------- | :--------------- |
| **直通交换方式** | 收到目的地址(*前6B*)后立即转发 | 延迟极小           | 不检测错误，不能连接不同速率端口 |
| **存储转发方式** | 完整接收帧，检查CRC无误后转发   | 可检错，支持不同速率端口转换 | 延迟较大             |

### 6.1.3. 自学习功能与交换表

**交换表(*MAC地址表*)**：记录 **MAC地址 -> 转发端口** 的映射关系，并包含写入时间。

**自学习过程**：
1. 交换机收到一个帧，**记录源MAC地址和进入端口**到交换表；
2. 若交换表中已有目的MAC地址的记录，则**按记录端口转发**；
3. 若无目的MAC地址记录，则**向除源端口外的所有端口广播**该帧(*泛洪*)。

> **注意**：交换表项有**老化时间**(*通常300秒*)，超时自动删除，以适应网络变化。

### 6.1.4. 生成树协议(STP)

**问题**：冗余链路可能导致帧在网络中**无限循环**(*广播风暴*)。

**生成树协议STP(*Spanning Tree Protocol*)**：在逻辑上 **切断某些链路**，形成无环路的树状拓扑，消除广播风暴。

## 6.2. 共享式以太网

### 6.2.1. 基本概念

**共享式以太网**：所有主机连接在同一条共享总线上(*物理上可为星型，逻辑上仍是总线型*)，通过 **CSMA/CD** 协议争用信道。

**核心设备**：**集线器(*Hub*)**，实质上是一个**多端口的中继器**。

### 6.2.2. 集线器的工作原理

1. 一个端口接收到数据信号后，**整形再生**，恢复到发送时的状态；
2. 将信号**转发到所有其他(除输入端口外)端口**；
3. 所有端口共享同一带宽，同一时刻**只允许一台设备发送数据**；
4. 不识别MAC地址，不进行帧过滤。

### 6.2.3. 冲突域与广播域

- 所有端口属于同一冲突域(*多个端口同时发送会产生碰撞*)；
- 所有端口属于同一广播域。

#### （一） 冲突域

**冲突域(*Collision Domain*)**：在同一个冲突域中，任意两台设备同时发送数据都会产生冲突(*碰撞*)的集合。

**关键理解**：
- 集线器(*Hub*)的所有端口处于同一冲突域；
- 交换机的每个端口是一个独立的冲突域；
- 同一冲突域内的设备共享同一传输介质，需要使用 CSMA/CD 协议避免冲突。

**划分冲突域的边界**：
- 集线器 -> 不隔离冲突域；
- 网桥 -> 隔离冲突域(*每个端口独立*)；
- 交换机 -> 隔离冲突域(*每个端口独立*)；
- 路由器 -> 隔离冲突域。

> 注意：冲突域是数据链路层的概念，其范围由物理层和数据链路层设备决定。

#### （二） 广播域

**广播域(*Broadcast Domain*)**：网络中能接收任一节点发出的广播帧的所有节点的集合。

**关键理解**：
- 集线器和交换机连接的节点处于同一广播域；
- 路由器可以隔离广播域(*广播域的范围被限制在路由器的一侧*)；
- VLAN 可以在交换机上逻辑上划分广播域。

**划分广播域的边界**：
- 集线器 -> 不隔离广播域；
- 交换机 -> 不隔离广播域(*默认*)；
- VLAN -> 隔离广播域(*逻辑划分*)；
- 路由器 -> 隔离广播域。

> 注意：广播域是网络层的概念，其范围由网络层设备(*路由器*)或逻辑划分(*VLAN*)决定。

| 设备 | 工作层次 | 是否隔离冲突域 | 是否隔离广播域 |
| :--- | :--- | :--- | :--- |
| 中继器/集线器 | 物理层 | 否 | 否 |
| 网桥/交换机 | 数据链路层 | 是 | 否 |
| 路由器 | 网络层 | 是 | 是 |

> **注意**：VLAN 是一种特殊的数据链路层技术，可以在交换机上实现广播域的隔离，但通常将其归类为数据链路层的扩展功能。

### 6.2.4. 共享式以太网的局限性

1. **带宽共享**：n台主机共享总带宽，平均带宽 = 总带宽/n；
2. **冲突限制**：半双工工作，需要使用CSMA/CD，效率随主机数增加而降低；
3. **安全性差**：同一广播域内，所有主机都能收到其他主机的帧。

### 6.2.5. 集线器与交换机的对比

| 对比项 | 集线器(Hub) | 交换机(Switch) |
| :--- | :--- | :--- |
| **工作层次** | 物理层 | 数据链路层 |
| **是否识别MAC地址** | 否 | 是 |
| **处理方式** | 广播到所有端口 | 按MAC地址转发 |
| **冲突域** | 所有端口同一冲突域 | 每个端口独立冲突域 |
| **带宽** | 共享 | 独享 |
| **适用场景** | 小型网络、早期以太网 | 现代局域网 |
