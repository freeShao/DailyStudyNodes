# 进程管理【\*非重点；※重点】
---

程序由 **一条条指令和数据构成的**。在程序执行前，首先将程序所含的 **指令和数据送入主存**，一旦程序被 **启动执行**，就无须人员干预，**计算机会自动逐条完成指令的取出和执行任务**。

**一个程序的执行就是周而复始地执行一条一条指令的过程。**
每条指令的执行过程包括：
1. 从主存中取指令；
2. 对指令进行译码；
3. 计算下一条指令地址；
4. 取操作数并执行；
5. 将结果送回存储器。

## 1.2. 进程的基本概念

**定义**：
- 进程是 **程序的一次执行过程**；
- 进程是一个程序及其数据在处理机上 **顺序执行所发生的活动**；
- 进程是具有独立功能的 **程序在一个数据集合上运行的过程**，是系统进行 **资源分配和调度的一个独立单位**。

进程一般包括以下信息：
1. 程序的 **代码**；
2. 程序的 **数据**；
3. **CPU寄存器的值**，包括通用寄存器、程序计数器；
4. **堆(heap)**，是用来保存进程运行时 **动态分配的内存空间**；
5. **栈(stack)**，有两个用途：
	1. **保存运行上下文信息**(进程运行时的状态信息)；
	2. **函数调用时**，用来保存被调用函数的形参和局部变量。
6. 进程所占用的一组系统资源，如打开文件等。
> **注意**：进程中包含了正在运行的一个程序的**所有状态信息**。

**特征**：
1. **动态性**：进程是一个正在运行的程序，在程序运行的过程中，**状态是在不断变化的**。*是进程的最根本特征*；
2. **独立性**：一个进程是一个独立的实体，是计算机系统资源的使用单位；
3. **并发性**：**某段时间内看上去有多个进程都在执行**，当多个进程[并发](<1-操作系统概述 - 操作系统.md#### （一） 并发>)执行时，有以下三个特性：
	1. **间断性**：并发的程序会有间断运行的特点；
	2. **失去封闭性与不可再现性**：失去封闭性意味着进程的执行结果与执行速度有关，使得进程的执行有不可再现性【*相同的初始环境和条件下，可能得到不同的结果*】。
4. **异步性**：由于进程的相互制约，使得进程按各自独立的、**不可预知的速度向前推进**。【操作系统中必须配置相应的*进程同步机制*】

**其他考点**：
- **进程实体/进程映像** = PCB + 程序段 + 相关数据段；
- **进程映像**是静态的，**进程**是动态的，**程序**是静态的；
- **进程控制块(PCB)** 是进程的唯一标志；
- **系统资源** = 处理机，存储器和其他设备服务于某个进程的“时间”【类似于处理机的*时间片*】。

## 1.3. 进程的状态与转换

### 1.3.1. 进程的状态

- **运行态(Running)**：该时刻进程占用CPU；
- **就绪态(Ready)**：进程获得了除处理机外的一切所需资源，一旦得到处理机，就可以立即运行；
- **阻塞态(Blocked)**：该进程正在等待某一事件发生而暂停与逆行，即使给他CPU控制权，它也无法运行；
- **创建态(New)**：进程正在被创建时的状态；
- **结束态(Exit)**：进程正在从系统中消失的状态。

> **注意**：进程的三个基本状态发生在内存中。

### 1.3.2. 状态的转换

![555](image/2-进程管理%20-%20操作系统/进程状态转换.png)
![250](image/2-进程管理%20-%20操作系统/进程状态转换2.png)

- **就绪态 -> 运行态**：进程被调度，获得处理机资源(*分派处理机时间片*)；
- **运行态 -> 就绪态**：
	1. 时间片用完后，不得不让出处理机；
	2. 可剥夺的OS中，当有更高优先级的进程就绪时，调度程序将正在执行的进程转换为就绪态。
- **运行态 -> 阻塞态**：
	1. 进程请求某一资源(如外设)的使用和分配时；
	2. 等待某一事件的发送时(如IO操作的完成)
	3. 进程以[系统调用](<1-操作系统概述 - 操作系统.md## 2.4. 系统调用【广义指令】>)的方式请求OS提供服务，**这个过程系统从用户态转换为核心态(内核态)**。
	4. 该过程是 **主动行为**。
- **阻塞态 -> 就绪态**：
	1. IO操作结束或中断结束时；
	2. 该过程是 **被动行为**，需要其他相关进程的协助。

## 1.4. 进程的控制结构

### 1.4.1. PCB

进程控制块(PCB，Process Control Block)是进程存在的**唯一标志**。
一个进程的存在，必然会有一个PCB，如果进程消失了，那么PCB也会随之消失。

#### （一） PCB中包含的信息

- **进程描述信息**：
	- **进程标识符PID**：标识各个进程，每个进程都有一个并且唯一的标识符；
	- **用户标识符UID**：进程归属用户，用户标识符主要是为[共享](<1-操作系统概述 - 操作系统.md#### （二） 共享>)和保护服务。
- **进程控制和管理信息**：
	- **进程当前状态**：如new、ready，running、waiting或blocked等；
	- **进程优先级**：进程抢占CPU时的优先级。
- **资源分配清单**：
	- 有关内存地址空间或虚拟地址空间的信息；
	- 所打开文件的列表和所使用的IO设备信息。
- **CPU相关信息**：
	- **CPU中各个寄存器的值**；
	- 当进程被切换时，CPU的状态信息都会被保存在相应的PCB中以便进程重新执行时，能从断点处继续执行。

#### （二） 组织PCB的方式

**链接方式**：
- 把统一状态的PCB链成一个队列，不同状态对应不同的队列；
- 也可把处于阻塞态的进程PCB，根据阻塞原因，排成多个阻塞队列。
**索引方式**：
- 将统一状态的进程组织在一个索引表中(如就绪索引表，阻塞索引表)。

### 1.4.2. 程序段

能被进程调度程序调度到CPU执行的程序代码段；
程序可以被多个进程共享，即 **多个进程可以运行同一个程序**。

### 1.4.3. 数据段

可以是进程对应的程序加工处理的原始数据；
可以是程序执行时产生的中间或最终结果。

## 1.5. 进程的控制

即 **进程的创建、终止、阻塞、唤醒的过程**。

|        | 定义和过程                                                                                                                                                                                                                                                           | 对应事件                                                      |
| ------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------- |
| **创建** | 1.允许一个进程创建另一个进程；<br>2.允许子进程继承父进程的所拥有的资源。<br>**创建过程**：<br>1.申请一个空白的PCB，并向PCB中填写一些控制和管理进程的信息，比如进程的唯一标识PID等；<br>2.为该进程分配运行时所必须的资源，比如内存资源；<br>3.将PCB插入到就绪队列，等待被调度运行。                                                                                                | 1.终端登录系统，作业调度；<br>2.系统提供服务；<br>3.用户程序的应用，**设备分配不需要创建进程**。 |
| **终止** | 1.有3种终止方式：正常结束、异常结束以及外界干预；<br>2.当子进程被终止时，其在父进程处继承的资源应当**还给父进程**；<br>3.当父进程被终止时，该父进程的子进程就变为孤儿进程。<br>**终止过程**：<br>1.查找需要终止的进程的 PCB；<br>2.如果处于执行状态，则立即终止该进程的执行，然后将CPU资源分配给其他进程；<br>3.如果其还有子进程，则应将该进程的子进程交给1号进程接管；<br>4.将该进程所拥有的全部资源都归还给操作系统；<br>5.将其从 PCB 所在队列中删除。 | 1.正常结束；<br>2.异常结束；<br>3.外界干预。                             |
| **阻塞** | 1.当进程需要等待某一事件完成时，它可以调用阻塞语句把自己*阻塞等待*；<br>2.一旦被阻塞等待，只能由*另一个进程唤醒*。<br>**阻塞过程**：<br>1.找到将要被阻塞进程标识号对应的 PCB；<br>2.如果该进程为运行状态，则*保护其现场*，将其状态转为阻塞状态，停止运行；<br>3.将该 PCB 插入到阻塞队列中去。                                                                                         | 1.请求系统资源失败；<br>2.等待某种操作的完成；<br>3.新数据尚未到达或无新任务可做。          |
| **唤醒** | 1.进程由[运行]转变为[阻塞]状态，是由于进程必须等待某一事件的完成；<br>2.处于阻塞状态的进程是绝对不可能叫醒自己；<br>3.如果某进程正在等待I/O事件，需由别的进程发消息给它；<br>4.只有当该进程所期待的事件出现时，才由发现者进程用唤醒语句叫醒它。<br>**唤醒过程**：<br>1.在该事件的阻塞队列中找到相应进程的 PCB；<br>2.将其从阻塞队列中移出，并置其状态为就绪状态；<br>3.把该 PCB 插入到就绪队列中，等待调度程序调度。                       | 1.释放该IO设备的进程；<br>2.提供数据的进程。                               |

## 1.6. 进程的通信

**定义**：进程通信是指进程之间的 **信息交换**。
**低级通信方法**：PV操作。
**高级通信方法**：
1. **共享存储**：共享内存、共享文件系统；
2. **信息传递**：需要发送消息和接受信息两个原语；
3. **管道通信**：【以 *生产者-消费者模式* 进行数据交换，管道**大小固定**】
	- 需要满足的能力 = **互斥 + 同步 + 确定对方的存在**；
	- 缓冲区只允许一边写入，另一边读出，所以管道 **只能采用半双工通信**；
	- 管道是一种文件，所以两个进程可以通过文件系统交换数据，**读写进程以字符流形式读出和写入**。

## 1.7. 进程的上下文切换

- **上下文**：某一时刻CPU寄存器和PC的内容。
- **进程上下文切换**：一个进程切换到另一个进程的过程。
- **上下文切换的实质**：实质是处理机从一个进程的运行转到另一个进程上运行，这个过程中，进程的运行环境产生了实质性的变化。
- **上下文切换的消耗**：有些处理器提供多个寄存器组，上下文切换只需要简单改变当前寄存器组的指针。
- **上下文切换的场景**：
	1. 某个进程时间片耗尽时；
	2. 进程在系统资源不足时，要等到资源满足后才可以运行；
	3. 进程通过sleep将自己主动挂起；
	4. 有优先级更高的基础运行时；
	5. 发送硬件中断时。
- **上下文切换的流程**：
	1. 挂起一个进程，保存CPU上下文，包括PC和其他寄存器；
	2. 更新PCB信息；
	3. 把进程的PCB移到相应的队列(如就绪队列，阻塞队列)；
	4. 加载另一个进程执行，更新其PCB；
	5. 跳转到新进程PCB中的PC所指向的位置执行；
	6. 恢复处理机上下文。

![555](image/2-进程管理%20-%20操作系统/进程上下文切换.png)

**调度与切换的区别**：先有资源的调度，才有进程的切换。
- **调度**：决定资源分配给哪个进程的行为；是一种 **决策** 行为；
- **切换**：实际分配的行为；是一种 **执行** 行为。

# 二、 线程

在多道程序操作系统中，**为了进一步提高程序的并发执行程度**，引入了线程概念。
**线程**：即进程当中的一条执行流程，是比进程更小的概念，是将进程进一步细分的单位。
一个进程可以同时拥有多个线程，**借助多个线程实现程序的并发执行(而不必借助进程)**。

## 2.1. 线程常考的知识点

| 知识点      | 概念                                                                                                          |
| :------- | :---------------------------------------------------------------------------------------------------------- |
| **线程的特征**    | 1.线程是处理机调度的 **基本单位**，可以独立执行程序；<br>2.没有相同的进程，但是调用在不同进程中的线程可以相同。                                              |
| **线程可共享的东西** | 1.线程没有自己独立的地址空间，每个线程只拥有自己的独立的栈空间；<br>2.线程之间可以共享进程的资源(如：代码段，堆空间，数据段，打开的文件)；<br>3.线程之间不能共享虚拟地址空间，线程之间不能共享栈指针。 |
| **线程的并行与并发** | 1.同一进程或不同进程内的线程都可以并发执行；<br>2.进程之间可以并发，但不可以并行，统一进程之间的线程可以并行。                                                 |
| **其他**       | 键盘驱动程序**不能**体现多线程系统的特点，因为计算机一般只有一个键盘。                                                                       |

## 2.2. 线程与进程的比较

|            | 进程                                                       | 线程                                                                       |
| ---------- | :------------------------------------------------------- | :----------------------------------------------------------------------- |
| **是什么的单位？**    | 是 **资源分配** 的基本单位                                         | 是 **调度** 的基本单位                                                           |
| **不能共享什么？**    | 不能共享虚拟地址空间                                               | 不能共享栈指针                                                                  |
| **可以共享什么？**    | 拥有一个完整的资源平台；<br>每个进程都有独立的地址空间和资源；<br>除了共享全局变量，不允许其他进程访问。 | 某进程中的线程对其他进程不可见；<br>线程共享进程的地址空间和资源，线程自己没有独立的地址空间；<br>只独享必不可少的资源，如：寄存器和栈。 |
| **进程切换会引起什么？** | 不同进程的线程的切换 **会引起进程切换**。                                  | 同一进程的线程的切换 **不会引起进程的切换**。                                                |
| **创建、终止、切换时间** | 慢                                                        | 快                                                                        |
| **数据交换效率**     | 低                                                        | 各线程共享内存和文件资源，数据交换效率高                                                     |

## 2.3. 线程的概念和特征

**定义**：
- 线程是进程当中的一条执行流程；
- 线程之间可以并发运行且共享相同的地址空间；
- 线程自己不拥有系统资源，但可与同属一个进程的程序共享进程所有的资源；
- 线程同样具有 **三种基本状态**：时空态+阻塞态+就绪态。

**引入线程的意义**：减少程序在并发执行过程中所付出的时空开销，提高操作系统的并发能力。

> **注意**：线程可以导致 **平均每次切换所需开销变少**，使得更多线程参与开发，因此线程利于提高系统并发性。

## 2.5. 线程的分类

线程的实现分为两类 = 用户级线程(User-Level Thread, ULT) + 内核级线程(Kernel-Level, KLT)

|     | ULT                                                                                                    | KLT                                                           | 组合模式      |
| --- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------- | --------- |
| **定义**  | 由用户级线程库函数来完成整个线程的管理和调度【**库函数负责**】                                                                      | 线程对应的TCB放在OS里，线程的管理和调度由OS负责【**OS负责**】                         | 内核支持的用户进程 |
| **模型**  | **多对一模型**(多个用户对应一个线程)                                                                                  | **一对一模型**(一个用户对应一个线程)                                         | **多对多模型** |

# 三、 处理机调度

处理机调度就是把 **CPU** 有效、合理地分配给进程。

## 3.1. 调度常考的知识点

1. 作业时用户提交的，以用户任务为单位；
2. 进程是系统自动生成的，以操作系统控制为单位。

## 3.2. 调度概念

### 3.2.1. 调度基本概念

1. 调度是处理机进行分配，即从就绪队列种按一定算法(公平、高效的原则)选择 一个进程并将处理机分配给他运行，以实现进程并发地执行；
2. 调度是多道程序OS的基础；调度是OS设计的核心问题。

### 3.2.2. 调度的层次分类

![555](image/2-进程管理%20-%20操作系统/CPU三级调度.png)

#### （一） 高级调度(作业调度)

- 是 **内存与辅存** 的调度，从后备队列中调度作业；
- 每个作业只调入调出一次；
- 通常存在于多道批处理系统中。

#### （二） 中级调度(内存调度)

- **目的是提高内存利用率和系统吞吐量**；
- 将暂时不能运行的进程调到外存等待，设为挂起态，最后修改状态为就绪态，挂在就绪队列上；
- 是存储器管理中的对换功能。

> **注意**：“调出”与“挂起”的区别。
> **调出**：操作系统**强制**将进程从内存移到外存，释放内存空间；
> **挂起**：进程**自身主动**让出CPU，等待某个时间，进程**还在内存**。

进入挂起态后，**一个进程中的状态如下**：

![555](image/2-进程管理%20-%20操作系统/进程挂起态的状态.png)

#### （三） 低级调度(进程调度)

- **从就绪队列中选取一个进程**，调用频率很高；
- 各种OS都 **必须配置** 这种调度。

#### （四） 三种调度的联系

|      | 调度目标                            | 发生频率 | 进程状态的改变                      |
| ---- | ------------------------------- | ---- | ---------------------------- |
| **高级调度** | 将 **作业由外存调度到内存** 中，为其创建进程。      | 低    | **作业 -> 创建态 -> 就绪态**         |
| **中级调度** | 将 **进程** 数据 **暂存在辅存中**(或恢复到内存中) | 中    | 就绪态 -> 就绪挂起态<br>阻塞态 -> 阻塞挂起态 |
| **低级调度** | 调度进程轮流使用处理器                     | 高    | 就绪态 -> 执行态                   |

1. 作业调度为进程活动做准备，进程调度使进程正常活动；
2. 中级调度将暂时不能运行的进程挂起，中级调度处于另外两个调度之间；
3. **调用频率**：作业调度 < 内存调度 < 进程调度；
4. 进程调度是 **最基本的**，不可或缺。

## 3.3. 调度的实现

![555](image/2-进程管理%20-%20操作系统/调度程序的结构.png)
用于实现CPU调度与分派的软件组件称为 *调度程序*，它由三部分组成：
1. **排队器**：按策略给就绪进程排出一个或多个队列；
2. **分派器**：从就绪队列中取出进程，并分配CPU；
3. **上下文切换器**：在对处理机进行切换时，会发生两对上下文的切换操作。

### 3.3.1. 调度的时机

**先调度再切换**。
进程从一个状态到另一个状态变化时，就会触发一次调度。

样例：
- 运行的进程运行完毕；
- 运行的进程时间片用完；
- 运行的进程所需资源未准备好；
- 运行的进程自我阻塞；
- 运行的进程出现错误。

### 3.3.2. 进程的切换

#### （一） 不能进行调度与切换的情况

- 在处理中断的过程中；
- 进程在OS内核临界区中；
- 其他需要完全屏蔽中断的原子操作过程中。
> **原子操作**：要么全部执行，要么都不执行，不饿能出现执行到一半的中间状态的操作。

#### （二） 可以进行调度与切换的情况

- 发生引起调度条件且当前进程无法继续进行下去时(*非剥夺调度*)；
- 中断处理结束或自陷处理结束后，被置上请求调度标志(*剥夺方式的调度*)；
- 在**进程结束时**能进行处理机调度；
- 在**创建新进程后**能进行处理机调度；
- 在**系统调用完成并返回用户态时**能进行处理机调度；
- 进程处于临界区时，**只要不破坏临界资源的使用规则**，就不影响处理机的调度。

#### （三） 切换的过程

1. 将原进程的信息推入到当前进程的内核堆栈中，并更新堆栈指针；
2. 内核从新进程的内核栈中装入新进程的信息；
3. 内核更新当前运行的进程空间指针，重设PC寄存器后开始运行新的进程。

### 3.3.3. 调度方式

|     | 非抢占调度方式                                               | 抢占调度方式                      |
| --- | ----------------------------------------------------- | --------------------------- |
| **优点**  | 实现简单，系统开销小，适合批处理系统                                    | 有利于提高系统吞吐量和响应效率             |
| **缺点**  | 不适合[分时](<1-操作系统概述 - 操作系统.md##1.4. 操作系统发展历程>)和大多数的实时系统 | 必须遵循一定的准则(如优先级，短进程优先，时间片原则) |
> **注意**：调度是一个“白白”消耗系统资源的行为，因为调度程序占用处理器资源这一行为对作业的完成是没有任何贡献的。

## 3.4. 调度的目标

**调度最终目标要考虑的元素**：特定用户的要求+系统整体效率+调度算法的开销。

$$CPU \ 利用率 = \frac{CPU \ 有效工作时间}{CPU \ 有效工作时间 + CPU \ 空闲等待时间}$$

$$等待时间 = 等待CPU的时间$$

$$周转时间(t_i) = 作业完成时间 - 作业提交时间$$

$$带权周转时间(W_i) = \frac{周转时间}{作业实际运行时间}$$ 
$$平均周转时间 = \frac{t_1 + t_2 + ··· + t_i}{i}$$ 
$$平均带权周转时间 = \frac{W_1+W_2+···+W_i}{i}$$

## 3.5. 调度算法

### 3.5.1. 先来先服务(FCFS)

FCFS也称先进先出算法(First In First Out, FIFO)，既可用于作业调度，又可用于进程调度。
FCFS属于 **非抢占式算法**。

![555](image/2-进程管理%20-%20操作系统/FCFS算法.png)

**优点**：逻辑简单；
**缺点**：
1. 效率差；
2. 无法实现人机交互；
3. 未考虑到不同进程间的差异性，例如：进程的紧急和不紧急；
4. **FCFS算法对于长进程和处理器密集型进程更有利**，长进程排队并使用处理器直到作业完成或阻塞，**可以使用处理器更长时间**。

### 3.5.2. 短作业优先(SJF)

短进程(作业)优先调度算法(Shortest Job/Process First)，可以适用于作业调度、进程调度。
> 进程调度：短进程优先调度算法，调度选择预估剩余处理器使用时间最短的进程；
> 作业调度：短作业优先调度算法，调度选择预估剩余处理器使用时间最短的作业。

![555](image/2-进程管理%20-%20操作系统/SJF算法.png)

**优点**：较FCFS而言，**SJF的平均等待时间和平均周转时间是最优的**。
> **注意**：**SJF是十分理想的调度算法，现实中难以实现**
> 1. 进程 **难以准确预估运行** 所需时间；
> 2. 程序 **可以谎报运行所需时间而恶意竞争处理器使用权**。

**缺点**：
1. **算法需要进程(作业)预估器运行时间**，在预估时，可能出现估算时间不准或进程“谎报”时间等问题；
2. **算法偏向短进程**。

根据是否可以抢占，短进程调度算法可以分为两种：
1. **非抢占式短进程优先调度算法**：
	- 调度时，会选择当前就绪队列中要求处理器时间最少的进程，为其分配处理器；
	- **该进程运行期间，不会被抢占**，直到进程主动放弃处理器。
2. **抢占式短进程优先调度算法**：
	- 调度时，会选择当前就绪队列中要求处理器时间最少的进程，为其分配处理器；
	- **如果在该进程运行过程中，就绪队列中出现了要求时间更短的进程，则这个要求时间更短的进程会抢占处理器资源，当前进程的状态会由执行态变为就绪态**。

### 3.5.3. 高响应比优先

综合考虑进程(作业)的等待时间和运行时间来调度进程。

$$响应比 = \frac{等待时间 + 估计运行时间}{估计运行时间}$$
*等待时间是变化的，则优先级也是动态变化的*，随着 **进程的等待时间增加，该进程的优先级就会变高，更容易被调度。**

### 3.5.4. 其余算法

#### （一） 优先级调度算法
- IO繁忙作业优先于计算繁忙作业【*因为IO操作要及时完成，没办法长时间保存数据*】；
- 系统进程优先于用户进程。

#### （二） 时间片轮转算法
- 若时间片过大，退化为FCFS；
- 若时间片过小，则切换频繁，处理机开销增大。

#### （三） 多级队列算法
**多级反馈队列算法需要综合考虑**
- 优先级数量，优先级之间的转换规则；
- 就绪队列数量，就绪队列的调度算法；
- 进程在就绪队列间的迁移条件。

### 3.5.5. 调度算法对比

|            | FCFS                                                            | SJF                    | 高响应比                             | 时间片轮转                                    | 多级反馈队列                        |
| ---------- | :-------------------------------------------------------------- | :--------------------- | :------------------------------- | :--------------------------------------- | :---------------------------- |
| **可抢占？**   | ❌                                                               | ✅                      | ✅                                | ✅                                        | 队列内算法不一定                      |
| **不可抢占？**  | ✅                                                               | ✅                      | ✅                                | ❌                                        | 队列内算法不一定                      |
| **特点&优势**  | 公平；<br>实现简单；<br>有利于长作业；<br>不利于短作业；<br>有利于CPU繁忙作业；<br>不利于IO繁忙作业。 | 平均等待时间最少；<br>**效率最高**。 | 兼顾长短作业；<br>**满足短作业优先且不会发生饥饿现象**。 | 兼顾长短作业；<br>为了多个用户能及时干预系统；<br>**绝对可抢占的**。 | 兼顾长短作业；<br>有较好的响应时间；<br>可行性强。 |

# 四、 同步和互斥

## 4.1. 选择题常考点

1. **可重入代码/纯代码**：一种允许多个进程同时访问的代码；如进程映像中的共享程序段。
2. PV操作实现的 **同步的S的初值由用户确定**；
   如果期望的信息还没发送，则对应的初值为0，若信息已存在，则初值为非0的正数；
   PV操作实现的 **互斥的S的初值=1**
3. 执行P操作的进程处于运行态；若P操作之后，S<0，则表示没有可用资源，该进程进入阻塞状态。
4. 判断代码中的语句是否要互斥执行，可以从以下几个方面考虑：
	1. 不同范围的变量不需要互斥(如 进程A和进程B都有变量x，这是两个不同范围的变量，不用互斥)；
	2. 对变量赋值前，都有声明语句的话，不需要互斥(如 `int a; a=1; int a; a=2`，a=1和a=2不需要互斥)
5. 信箱通信时一种间接通。

## 4.2. 基本概念

**同步互斥**：因为并发进程是异步的，为了协调进程之间相互制约关系，所以引入 **同步互斥**。

**进程的异步性**：由于系统的资源有限，进程的执行不是一贯到底的，而是走走停停，以 **不可预知的速度** 向前推进。

![555](image/2-进程管理%20-%20操作系统/临界示例图.png)

### 4.2.1. 互斥关系

通过 **资源共享** 而使进程之间产生关系，称为互斥关系，也叫间接制约关系。
即：**进程A和进程B不能在同一时刻执行。**
> **例如**：进程P1和P2在运行中都要使用打印机，如果允许这两个进程同时向一台打印机输出数据，那么它们的输出就会交织在一起，为了避免此类情况的发生，就需要保证两个进程互斥地使用打印机。

### 4.2.2. 同步关系

进程同步是指 **多个进程间** 发生的事件存在某种 **时序关系**，例如先后关系，必须协同合作，相互配合来共同完成一个任务。
即：**进程A应在进程B之前执行。**
> **例如**：一项工作由A、B、C三个进程来完成，A进程用于输入数据，B进程对输入的数据进行处理，C进程输出结果。这三个进程之间就需要同步，当A进程完成数据输入后，B进程才可运行，B进程计算出结果后，C进程才可输出结果。进程之间的这种制约关系称作直接制约关系，又叫 **同步关系**。

### 4.2.3. 临界资源与临界区

**临界资源**：一次仅允许一个进程使用的资源；如物理设备(打印机)，共享变量，共享缓冲区，公共队列。
**共享资源**：可被多个进程同时使用的资源；如可重入代码/纯代码，共享程序段，磁盘，非共享数据。
**临界区**：
- 访问临界资源的那段代码；
- 如果n个进程涉及到了同一个变量A，则A的相关临界区 = 访问临界资源A的那段代码 = n个代码段。

![555](image/2-进程管理%20-%20操作系统/临界示例图.png)

## 4.3. 同步互斥的实现

### 4.3.1. 临界区互斥准则

**空闲让进**：临界区空闲，允许一个进程进入。【*运行进程访问空闲的临界资源*】
**忙则等待**：有进程进入临界区时，其他进程需等待。【*两个进程不能同时进入临界资源*】
**有限等待**：请求访问的进程应保证在有限的时间内进入临界区。【*进程等待进入临界区的事件是有限的*】
**让权等待**：进程不能进入临界区时，应立即释放处理器，防止进程忙等待。【不能进入临界区的执行态进程立即放弃CPU】
> **注意**：前三个准则必须满足。

![555](image/2-进程管理%20-%20操作系统/临界区互斥准则示例.png)

### 4.3.2. 软件实现方法

**单标志法；双标志先检查法；双标志后检查法；Peterson算法**。
[Perterson 算法满足有限等待但不满足让权等待]
[记录型信号量引入阻塞机制，可以让权等待]

在 **进入区设置并检查一些标志** 来标明是否有进程在临界区中，**若已有进程在临界区，则在进入区通过循环检查进行等待**，进程离开临界区后，则在退出区修改标志。

```cpp title:*关键节点
whild (true) {
	entry section;        // 进入区*
	critical section;     // 临界区
	exit section;         // 退出区*
	remainder section;    // 剩余区
}
```

#### （一） 单标志法

算法设置一个 **公用整型变量 turn**，指示 **允许进入临界区的进程编号**。
- 当 `trun=0` 时，表示允许 $P_0$ 进入临界区；
- 当 `trun=1` 时，表示允许 $P_1$ 进入临界区。

**进程退出临界区时，将临界区的使用权赋给另一个进程**，当 $P_i$ 退出临界区时，将 turn 置为 j(`i=0、j=1 或 i=1、j=0`)。

![555](image/2-进程管理%20-%20操作系统/单标志法.png)

该算法可以实现 **每次只允许一个进程进入临界区**。
**但两个进程必须交替进入临界区**，若某个进程不再进入，则另一个也将无法进入临界区【*违背 “空闲让进” 准则*】。

#### （二） 双标志先检查法

算法设置一个 **布尔型数组 flag[2]**，用来标记 **各个进程想要进入临界区的意愿**。
- 当 `flag[i]=true` 时，表示 $P_i$ 想要进入临界区(`i=0或1`)；
- $P_i$ 进入临界区前，**先检查对方是否想进入临界区**。若想，则等待；否则，将 `flag[i]` 置为 `true` 后，再进入临界区；当 $P_i$ 退出临界区时，将 `flag[i]` 置为 `false`。

![555](image/2-进程管理%20-%20操作系统/双标志先检查法.png)
> 按序列①②③④执行时，即检查对方标志后和设置自己的标志前可能发生进程切换，结果双方都检查通过，会同时进入临界区(*违背 “忙则等待” 准则*)。
> 原因在于检查和设置操作不是一气呵成的。

**优点**：不用交替进入，可连续使用；
**缺点**：$P_0$ 和 $P_1$ 可能同时进入临界区。

#### （三） 双标志后检查法

**先检查法的问题**：先检查对方的标志，再设置自己的标志，但是两个操作 **不能一气呵成**，导致两个进程同时进入临界区的问题。

**双标志后检查法**：**先设置自己的标志**，再检查对方的标志，若对方的标志为 true，则等待；否则，进入临界区。

![555](image/2-进程管理%20-%20操作系统/双标志后检查法.png)
> 按序列①②③④执行时，即两个进程依次设置自己的标志，并依次检查对方的标志，发现对方也想进入临界区，双方都争着进入临界区，结果谁都进不了(*违反 “空闲让进” 准则*)，于是因 **各个进程都长时间无法访问临界区而导致 “饥饿”现象(*违背 “有限等待” 准则*)**。

#### （四） Peterson 算法

结合*单标志法*和*双标志后检查法*的思想，利用 `flag[]` 解决互斥访问问题，而利用 `turn` 解决“饥饿”问题。
**若双方都争着进入临界区，则可让进程将进入临界区的机会谦让给对方**。
即，在每个进程进入临界区之前，先设置自己的flag标志，再设置允许进入turn标志；之后再检测对方的flag和turn标志，以保证双方同时要求进入临界区时，只允许一个进程进入。

![555](image/2-进程管理%20-%20操作系统/Peterson算法.png)
![555](image/2-进程管理%20-%20操作系统/Peterson算法2.png)

#### （五） 总结

| 方法         | 简述                         | 缺点                   |
| ---------- | -------------------------- | -------------------- |
| 单标志法       | 引入 turn，循环检查直到turn=本进程编号。  | **只能交替进入**、违背“空闲让进”。 |
| 双标志先检查法    | 引入flag[2]，先检查对方是否进入临界区。    | **会同时进入**，违背“忙则等待”。  |
| 双标志后检查法    | 引入flag[2]，设置自身flag，再检查。    | 同时希望进入时，违背“有限等待”。    |
| Peterson算法 | 引入turn和flag[2]，进入临界区前检查两次。 | 违背“让权等待”，不适用于多进程。    |

### 4.3.3. 硬件实现方法

**中断屏蔽方法；硬件指令方法；swap方法；TestAndSet指令**。
[硬件方法实现同步时，不能实现“让权等待”]

机器指令在执行过程中不会受到其他指令的干扰，也不会被中断。因此，可以利用机器指令来实现 **进程互斥**。

#### （一） 关中断方法

当一个进程正在执行他的临界区代码时，防止其他进程进入其临界区的最简单的方法是 **关中断**。
CPU只有在发生中断时才能引起进程切换，**屏蔽中断** 能够保证当前运行的进程让临界区代码顺利地执行完成，进而保证互斥地正确实现，然后执行开中断。

```cpp title:关中断一般流程
while (True) {
	关中断;
	临界区;
	开中断;
	剩余区;
}
```

**关中断缺点**：
1. 关中断权被滥用会产生严重后果，权限不可交由用户进程；
2. 并发环境中 **关中断会限制程序交替运行**，导致CPU和IO不能并行，影响系统执行效率；
3. 对多处理器环境不适用。即使同时关闭了所有核心的中断，也**不能阻塞**其他核心上正在执行的进程。

#### （二） 互斥锁

**定义**：解决临界区最简单的工具。
**特点**：
- 通常采用硬件机制实现；
- 常用于多处理器系统。
**缺点**：忙等待。
**代码**：
- `acquire()`获取🔒；
	```cpp title:获得锁的定义
	acquire(){
		while(!available);    // 忙等待
		available=false;      // 获得锁
	}
	```
- `release()`释放🔒。
	```cpp title:释放锁的定义
	release(){
		available=true;        // 释放锁
	}
	```

> **注意**：互斥锁可以应用于多进程/线程之间。
> 互斥锁的获取与释放执行 **必须是原子操作([原语](<1-操作系统概述 - 操作系统.md#### （一） 核心态【管态】>))**。

#### （三） TSL指令
TSL(Test And Set Lock，测试并上锁) 指令
TSL指令是一条特殊的机器指令，**用一条指令连贯地执行了多个操作**，即 **原子操作**。

```cpp title:TSL指令等价
bool TSL(bool *lock) {  // lock 即想要获取的锁
	bool old = *lock; // 记录锁的状态
	*lock = TRUE;     // 上锁
	return old;
}
```
> lock 变量代表锁：FALSE未上锁；TRUE上锁。

#### （四） Swap 指令
Swap指令，又称exchange指令，**用于交换两个变量的内容**。
```cpp title:Swap指令等价
void Swap (bool *a, bool *b) {
	bool temp = *a;
	*a = *b;
	*b = temp;
}
```
每个 **全局布尔变量lock**，其初值为 FALSE；
在每个进程中还会设置一个 **局部布尔变量key**，其初值为 TRUE。
```cpp title:Swap指令实现进程互斥一般流程
while (TRUE) {
	key = TRUE;
	while (key != FALSE) {
		Swap(&lock, &key);
	}
	临界区；
	lock = FALSE;
	剩余区；
}
```

#### （五） 总结

| 方法         | 简述                 | 缺点                   |
| ---------- | ------------------ | -------------------- |
| **关中断方法**      | 进入临界区前关中断，退出再开中断。  | **只能运行再内核态，且会降低效率**。 |
| **TSL、Swap指令** | 硬件保证测试和上锁、解锁为原子操作。 | **违背“让权等待”，可能导致饥饿**  |

### 4.3.4. 管程

**定义**：
- 管程定义了共享数据结构和各种进程在该数据结构上的全部操作；
- 结构类似 Class，把对共享资源的操作封装起来；
- **管程支持进程互斥**；任何时候只有一个进程在管程中执行；
- 管程不仅能实现进程间的互斥，还能实现进程间的同步；
- Java 采用管程机制(*面向对象*)；
- Java中管程常见的代码：`synchronized 关键字`，`wait()`，`notify()`，`notifyAll()`。

**组成**：
1. 管程(程序)的名字；
2. **局部于管程内部** 的共享数据结构或者共享变量说明；
3. 对 **管程内的数据结构** 进行操作的一组过程；
4. 对 **局部于管程内部的共享数据** 设置初始值的语句。
> **注意**：*管程外* 字眼出现，必定错误。管程的组成均基于**管程内部**。

#### （一） 管程中设置的条件变量

**定义**：阻塞原因定义为条件变量 condition。

**两种操作**：
- `x.wait`：阻塞进程，将其插入到阻塞队列中；
- `x.signal`：唤醒进程，将其插入到就绪队列中。

**与信号量的相似点**：wait/signal 类似于信号量的P/V操作，实现进程的阻塞/唤醒，但不能说和PV操作相同。

**与信号量的不同点**：
- *条件变量没有值*，仅实现“排队等待”功能；
- *信号量有值*，这个值反映了剩余资源数。

## 4.4. 信号量与PV操作

| 操作      | 定义                                                                                                                                                                                   |
| ------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **P操作** | 1.将 **信号量值S减1**，表示[*申请占用一个资源*]；<br>2.如果`s<0`，表示已经没有可用资源，则 **执行P操作的进程被阻塞**；<br>3.如果`s≥0`，表示现有的资源足够使用，则 **执行P操作的进程继续执行**；<br>e.g.当信号量的值为2时，表示有2个资源可以使用；当信号量的值为-2的时候，表示有两个进程正在等待使用这个资源。 |
| **V操作** | 1.将 **信号量S加1**，表示[*释放一个资源*]，即使用完资源后归还资源；<br>2.如果`s≤0`，表示有某些进程正在等待该资源；<br>3.由于我们已经释放出一个资源了，因此需要唤醒一个等待使用该资源(就绪态)的进程，使之运行下去。                                                            |

**常见问题**：
1. *S>0表示有临界资源可供使用，这个时候为什么不需要唤醒进程？*
	- 所谓唤醒进程时从就绪队列(阻塞队列)中唤醒进程，而信号量的值大于0表示有临界资源可供使用；
	- 也就是说这个时候没有进程被阻塞在这个资源上，所以不需要唤醒，正常运行即可。
2. *S=0表示没有临界资源可供使用，为什么还要唤醒进程？*
	- V操作时先执行S+1，也就是说，把**信号量的值加1后才变成了0**；
	- 在此之前，信号量的值是-1，即有一个进程正在等待这个临界资源，需要唤醒它。

```cpp title:信号量定义和PV操作
// 信号量定义
typedef struct semaphore {
	int value;           // 信号量值
	struct pcb * list;   // 信号量队列指针
}
// P操作
void P (semaphore s) {
	s.value --;
	if (s.value < 0)
		asleep(s.list);
}
// V操作
void V (semaphore s) {
	s.value ++;
	if (s.value <= 0)
		wakeup(s.list);
}
```

PV操作是低级进程通信语言。

### 4.4.1. 信号量分类

**整形信号量**：
- 该信号量被定义为一个用于表示资源数目的整型量S；
- **该机制不遵循“让权等待”的准则**。
**记录型信号量**：
- 是一种不存在“忙等”现象的进程同步机制；
- 需要一个用于代表资源数目的变量Value；
- 需要一个进程链表L，用于链接所有等待该资源的进程；
- wait操作 = P操作 = 请求一个资源；
- signal操作 = V操作 = 释放一个资源。

### 4.4.2. 信号量应用

#### （一） 利用信号量实现同步

用资源P操作；释放资源V操作；*此时信号量表示资源量*。

- **同步信号量初始值不确定**，可以设置；
- **信号量最大值** = 最多可以请求的资源数；
- **信号量最小值** = 最大值/初始值 - 最大请求值。

#### （二） 利用信号量实现互斥

PV操作夹着互斥资源；*此时信号量表示互斥量*。

- **互斥信号量初始值=1**，表示临界区只运行一个进程进入，从而实现互斥；
- **互斥信号量=0**，表示临界区已经有一个进程进入，临界区外还没有进程等待；
- **互斥信号量<0**，表示临界区有一个进程；
- **|互斥信号量|**，表示在临界区外等待进入的进程数。

#### （三） 利用信号量实现前驱关系

描述程序之间或语句之间的前驱关系。

### 4.4.3. 实现进程同步

步骤1：定义一个同步信号量，并初始化为当前可用资源的数量；
步骤2：在优先级较 [高] 的操作的 [后] 面执行V操作，释放资源；
步骤3：在优先级较 [低] 的操作的 [前] 面执行P操作，申请占用资源。

```cpp title:进程同步
semaphore S = 0; // 初始化同步信号量，表示当前可用资源数为0

P1() {
	代码 1;
	代码 2;
	V(S);     // 代码 2 运行完成后，释放资源
	代码 3;
}

P2() {
	P(S);     // 代码 4 运行前先申请占用资源，保证代码 4 一定是在代码 2 之后执行。
	代码 4;
	代码 5;
	代码 6;
}
```

### 4.4.4. 实现进程互斥

步骤1：定义一个互斥信号量，并初始化为 1；
步骤2：把对于临界资源的访问置于 P 操作和 V 操作之间。
> **注意**：P操作和V操作必须成对出现。
> 缺少P操作就 *不能保证对临界资源的互斥访问*；
> 缺少V操作就会 *导致临界资源永远得不到释放、处于等待态的进程永远得不到唤醒*。

```cpp title:进程互斥
semaphore mutex = 1; // 初始化互斥信号量，初始化值为 1

P1() {
	...
	P(mutex);  // 申请占用资源
	临界区
	V(mutex);  //释放资源
}

P2() {
	...
	P(mutex);  // 申请占用资源
	临界区
	V(mutex);  // 释放资源
}
```

## 4.5. 经典同步问题

### 4.5.1. 生产者-消费者问题

**问题描述**：
- 系统中有一组生产者进程和一组消费者进程；
- 生产者进程每次生产一个产品放入缓冲区；
- 消者进程每次从缓冲区中取出一个产品并使用；
- 任何时刻，只能有一个生产者或消费者可以访问缓冲区。

> **注意**：缓冲单元仅是缓冲区的一部分，生产/消费者是对**整个缓冲区**进行竞争。

![555](image/2-进程管理%20-%20操作系统/生产者-消费者问题.png)
> **注意**：生产者-消费者问题用于解决 **多个进程之间的同步和互斥问题**。
> 互斥：缓冲区互斥使用，每个缓冲区可以容纳一个产品。生产者先生产，消费者才能消费。

**题目中得到的同步互斥关系**：
- **缓冲区**：生产者、消费者共享一个初始为空、大小为n的缓冲区；
- **同步关系1**：只有缓冲区没满时(*优先级高*)，生产者才能把产品放入缓冲区(*优先级低*)，否则必须等待；
- **同步关系2**：只有缓冲区不为空时(*优先级高*)，消费者才能从中取出产品(优先级低)，否则必须等待；
- **互斥关系**：缓冲区是临界资源，各进程必须互斥地访问。

**设置的信号量**：

**empty**:
- 同步信号量(对应同步关系 1);
- 表示生产者还能生产多少，即*还能放入缓冲区多少产品*；
- 该数量小于等于 0，则生产者不能进行生产；
- 初始化为 n。
**full**：
- 同步信号量(对应同步关系 2)
- 表示消费者还能从缓冲区取出多少，即*当前缓冲区已有的产品数量*；
- 该数量小于等于 0，则消费者不能进行读取；
- 初始化为 0。
**mutex**：
- 互斥信号量；
- 实现对缓冲区的互斥访问；
- 初始化为 1。

```cpp title:实现代码
semaphore empty = n;  // 同步信号量
semaphore full = 0;  // 同步信号量
semaphore mutex = 1;  // 互斥信号量

// 生产者
producer() {
	while(1) {
		p(empty);   // 申请一个生产者可用数量 [同步关系1]
		p(mutex);   // 互斥使用缓冲区 [互斥关系]
		把产品放入缓冲区
		v(mutex);   // 释放缓冲区占用 [互斥关系]
		v(full);    // 增加一个消费者可用数量 [同步关系2]
	}
}

// 消费者
consumer() {
	while(1) {
		p(full);   // 申请一个消费者可用数量  若该信号量≤0，则阻塞，不进行消费 [同步关系2]
		p(mutex);  // 互斥使用缓冲区 [互斥关系]
		从缓冲区取出一个产品
		v(mutex);  // 释放缓冲区占用 [互斥关系]
		v(empty);  // 增加一个缓冲区/生产者可用数量 [同步关系1]
	}
}
```

# 五、 死锁

## 5.1. 常考点

1. 每个进程都得分一个资源，而且有多余的资源可以让任意一个进程使用，则不出现死锁；
2. 多道程序技术要求进程间能实现并发，需要实现进程调度保证CPU的工作效率，而并发性的实现需要中断功能的支持；
3. 系统资源不足不是系统产生死锁的原因，资源不足只会对进程造成“饥饿”；
4. 设进程有X个，每个进程最多请求使用3个A资源，系统有11个A资源，则不会出现死锁的最大X为？
   答：$2 \cdot X + 1 = 11, X = 5$ (极端情况时，每个进程分配2个A资源，只要再有一个资源就不会出现死锁)

## 5.2. 死锁概念

死锁是 **多个进程因为竞争资源** 而造成的一种 *互相等待*。
**死锁的充分条件**：资源费配图中每种资源只有一个，又出现了环路。

**死锁出现情况**：
1. **系统资源的竞争[*空间上*]**：
	- 系统中不可剥夺资源不足以满足多个进程；
	- 只有对不可剥夺资源(如磁带机、打印机)的竞争才可能产生死锁。
2. **进程推进顺序非法[*时间上*]**：
	- 进程运行时，请求和释放资源的顺序不当；
	- 系统对独占资源分配不当。

### 5.2.1. 死锁产生必要条件

当以下条件 **均满足** 时，才会出现死锁。
**互斥条件**：多个线程不能同时使用同一个资源；
**不剥夺条件**：进程A已经拥有资源1，在自己使用完之前不能被其他进程获取；
**请求并保持条件**：进程A已经有资源1，想申请资源2，但是资源2被进程B持有，进程A处于等待状态，但是 **进程A不释放资源1**；
**循环等待条件**：两个线程获取资源的顺序构成了环形链。

## 5.3. 解决死锁

### 5.3.1. 死锁预防

|           | 定义                                 | 举例        |
| --------- | ---------------------------------- | --------- |
| **破坏互斥条件**    | 缺点：打印机等临界资源只能互斥使用。                 | 方法可行性差。   |
| **破坏不剥夺条件**   | 常用于状态易于保存和恢复的资源(CPU的寄存器和内存资源)。     | 剥夺资源法。    |
| **破坏请求并保持条件** | 可能会导致饥饿现象。                         | 一次性分配策略。  |
| **破坏循环等待条件**  | 可采用顺序资源分配法，但是编号必须相对稳定，限制了新类型设备的增加。 | 资源有序分配策略。 |

### 5.3.2. 死锁避免

**核心结论**：
- **安全状态** -> 一定无死锁（存在安全序列）。
- **不安全状态** -> 不一定发生死锁（只是存在死锁风险）。
- **死锁状态** -> 一定是不安全状态。
**死锁避免的特点**：
- 不限制用户申请资源的顺序。
- 需要进程运行所需资源总量信息（Max）。
- 核心策略：只在分配资源后系统仍处于**安全状态**时才允许分配。

![555](image/2-进程管理%20-%20操作系统/死锁避免例题.png)
> 最大需求矩阵(MAX)、分配矩阵(Allocation)、系统可用资源向量(Available)，可以计算出需求矩阵(Need)。

| 数据结构                   | 含义              | 示例说明                                   |
| :--------------------- | :-------------- | :------------------------------------- |
| **最大需求矩阵 `Max`**       | 每个进程对每类资源的最大需求量 | `Max[0][0]=7` 表示 P0 最多需要 7 个资源 A       |
| **分配矩阵 `Allocation`**  | 每个进程当前已分配的资源数   | `Allocation[1][0]=2` 表示 P1 已分配 2 个资源 A |
| **需求矩阵 `Need`**        | 每个进程还需要多少资源才能完成 | `Need = Max - Allocation`              |
| **可用资源向量 `Available`** | 系统中当前每类资源的空闲数量  | `Available[0]=3` 表示当前有 3 个资源 A 可用      |
> **注意**：死锁避免 在发现系统没有安全序列时将不对资源分配。

#### （一） 安全性算法

**目的**：判断当前系统是否处于安全状态。
**算法步骤**：
1. 计算每个进程的 `Need = Max - Allocation`。
2. 找到一个进程 `Pi`，满足 `Need[i] ≤ Available`（即其所需资源系统当前可满足）。
3. 假设系统将资源分配给 `Pi`，`Pi` 运行完毕并**释放其当前占有的全部资源**：
   `Available = Available + Allocation[i]`
4. 标记 `Pi` 为已完成，重复步骤 2-3。
5. 如果所有进程都能被标记完成，则存在**安全序列**，系统处于**安全状态**；否则处于**不安全状态**。

![555](image/2-进程管理%20-%20操作系统/安全性算法解答.png)
> **注意**：要判断某Available是否安全，可以将选项依次带入验证。

#### （二） 银行家算法

**目的**：处理进程的资源请求，决定是否分配资源。
**算法步骤**：
1. **请求合法性检查**：
   - 若 `Request[i] > Need[i]`，则请求非法(进程请求超过其最大需求)，报错。
   - 若 `Request[i] > Available`，则暂时无法满足，进程等待。
2. **试探性分配**：
   - 假设满足请求，修改数据结构：
     - `Available = Available - Request`
     - `Allocation[i] = Allocation[i] + Request`
     - `Need[i] = Need[i] - Request`
3. **安全性检查**：
   - 调用**安全性算法**，判断分配后系统是否仍处于安全状态。
4. **正式分配或回滚**：
   - 若安全 → 正式分配，进程继续运行。
   - 若不安全 → **撤销试探性分配**(恢复原来的 `Available`、`Allocation`、`Need`)，进程等待。
> **注意**：银行家算法不会限制进程申请资源的顺序，只是通过动态检查安全性来避免进入不安全状态。

### 5.3.4. 死锁解除

1. **资源剥夺法**：挂起某些死锁进程，并抢占它的资源；
2. **撤销进程法**：强制撤销部分甚至全部死锁进程，并剥夺这些进程的资源；
3. **进程回退法**：让一个或多个进程回退到足以回避死锁的地步。

### 5.3.5. 各个策略的比较

|          | 资源分配策略                      | 各种可能模式               | 主要优点                   | 主要缺点                               |
| -------- | --------------------------- | -------------------- | ---------------------- | ---------------------------------- |
| **死锁预防** | 保守，宁可资源限制                   | 一次请求所有资源，资源剥夺，资源按序分配 | 适用于突发式处理的进程，不必进行剥夺     | 效率低，进程初始化时间延长；剥夺次数过多；<br>不便灵活申请新资源 |
| **死锁避免** | 是“预防”和“检测”的折中(在运行时判断是否可能死锁) | 寻找可能的安全允许顺序          | 不必进行剥夺                 | 必须知道将来的资源需求；<br>进程不能被长时间阻塞         |
| **死锁检测** | 宽松，只要允许就分配资源                | 定期检查死锁是否已经发生         | 不延长进程初始化时间，允许对死锁进行现场处理 | 通过剥夺解除死锁，造成损失                      |
