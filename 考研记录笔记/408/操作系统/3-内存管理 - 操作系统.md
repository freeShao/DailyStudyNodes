# 一、 内存管理概念

## 1.1. 常考点

1. **程序运行过程相关**：
	1. 形成 **逻辑地址** 的阶段：链接；
	2. 形成 **物理地址** 的阶段：装入或程序运行时。
2. **与重定位相关**：
	1. 动态重定位是在作业的执行过程中进行的；
	2. 静态重定位是在转入的时候进行的；
	3. 固定分区可以采用静态重定位(装入后位置不再改变)；
	4. 在整个系统设置一个重定位寄存器，用来存放程序在内存中的始址。
3. **其他**：内存保护需要OS和硬件机构合作完成，以保证进程空间不被非法访问。

## 1.2. 内存管理的基本概念

**内存管理** 是操作系统对内存的划分和动态分配。

**目的**：
1. 为了更好地支持多道程序并发执行；[**双核技术**【双实核】](<5-中央处理器 - 计算机组成原理.md# 七、 多处理器基本概念>)
2. 方便用户；
3. 提高内存利用率。

**功能**
1. **内存空间的分配**：由OS完成主存储器空间的分配和管理；
2. **地址转换**：存储管理将逻辑地址转换为物理地址；
3. **内存空间的扩充**：利用虚拟存储技术/自动覆盖技术，从逻辑上扩充内存；
4. **内存共享**：允许多个进程访问内存的同一部分；
5. **存储保护**：保证多道作业在各自的存储空间运行，互不干扰。

**分配**：
1. **连续分配**：单一连续分配 -->[单道发展到多道OS]--> 固定分区分配 -->[为了适应大小不同的程序]--> 动态分区分配；
2. **非连续分配**：分段存储管理 --> 分页存储管理 --> 段页存储管理。

### 1.2.1. 逻辑地址与物理地址

|     | 逻辑地址                                                                                        | 物理地址                |
| --- | :------------------------------------------------------------------------------------------ | :------------------ |
| **定义**  | 每个目标模块都从0号单元开始编址的地址。                                                                        | 物理地址空间是指内存中物理单元的集合。 |
| **特点**  | 不同进程可以有系统的逻辑地址，这些逻辑地址可以映射到主存的不同位置；<br>进程运行时，看到和使用的地址都是逻辑地址；<br>将逻辑地址转换为物理地址的过程叫做 **地址重定位**。 | 物理地址是地址转换的最终地址。     |

**地址转换(重定位)**：
- **静态重定位**：装入时一次性完成转换，装入后地址固定；
- **动态重定位**：运行时每次访问时由硬件实时转换(需重定位寄存器)；
- **重定位寄存器**：存放程序在内存中的起始物理地址。

### 1.2.2. 程序链接与装入

![555](image/3-内存管理%20-%20操作系统/程序链接与接入过程图.png)

[从C语言源程序到可执行文件](<1-计算机系统概述 - 计算机组成原理.md### 1.4.2. 从源程序到可执行文件>) 

**步骤1 - 编译**：由编译程序将用户源代码编译成若干目标模块。
**步骤2 - 链接**：由链接程序将目标模块和库函数链接，形成完整的装入模块。
- **链接类别**：静态链接；动态链接；运行时动态链接。
**步骤3 - 装入**：是由装入程序将装入模块装入内存运行。
- **装入类别**：
	- 静态装入：在编译时把物理地址计算好；
	- 可重定位装入：装入时把逻辑地址转换为物理地址，但装入后不能改变；
	- 动态重定位装入：执行时再决定装入的地址并装入，装入后有可能会换出。

![555](image/3-内存管理%20-%20操作系统/重定位类型.png)

### 1.2.3. 内存保护

**目的**：确保每个进程都有一个单独的内存空间。

**方法**：
1. 在CPU中设置一堆上下限存储器，判断CPU访问的地址是否越界；
2. 使用重定位寄存器和界地址寄存器(*只有==OS内存==才可以使用这两个寄存器*)
	1. 重定位寄存器/界地址寄存器含最小的物理地址值(*用于“加”*)；
	2. 界地址寄存器含逻辑机制的最大值(*用于“比”*)；
	3. **逻辑地址 + 重定位寄存器的值 = 物理地址**。

![555](image/3-内存管理%20-%20操作系统/重定位和界地址寄存器.png)

### 1.2.4. 内存共享

**概念**：
- 只有只读区域的进程空间可用共享；
- **纯代码/可重入代码** = 不能修改的代码，不属于临界资源；
- 可重入程序通过 **减少交换数量** 来改善系统性能。

**实现方式**：
- 段的共享；
- 基于共享内存的进程通信([同步互斥](<2-进程管理 - 操作系统.md## 1.6. 进程的通信>));
- 内存映射文件。

### 1.2.5. 进程的内存映像

**定义**：当一个进程调入内存运行时，就构成了进程的内存映像。

**组成要素**：
1. **代码段**：代码段是只读的，可以被多个进程共享；
2. **数据段**：程序运行时加工处理的对象，包括全局变量和静态变量；
3. **进程控制块PCB**：存放在系统区，OS通过PCB控制和管程进程；
4. **堆**：用来存放动态分配的变量(*动态的*)；
5. **栈**：用来实现函数调用的(*动态的*)。

# 二、 内存管理方法

## 2.1. 常考点

**共享相关**：段的共享是通过两个作业的段表中响应表项指向被共享的段的统一物理副本实现的；
**存储器相关**：
- 对主存储器的访问以字节或字为单位；
- 对主存储器的分配以块或段为单位。
**其他**：确定一个地址需要几个参数，作业地址空间就是几维的。

### 2.1.1. 分页和分段比较

|                    | 分段                                                                                             | 分页                                                 | 段页式                                                           |
| ------------------ |:------------------------------------------------------------------------------------------------ |:---------------------------------------------------- |:---------------------------------------------------------------- |
| **地址映射表**     | 每个进程由多个不同的段组成                                                                       | 每个进程一张页表，且进程的页表驻留在内存中           | 每个进程一张段表，每个段一张页表                                 |
| **地址结构**       | 段号+段内偏移                                                                                    | 页号+页内偏移                                        | 段号+段内页号+页内偏移量                                         |
| **地址结构维度**   | 二维                                                                                             | 一维                                                 | 二维                                                             |
| **供什么感知**     | 供用户感知                                                                                       | 供操作系统感知                                       | -                                                                |
| **以什么单位划分** | 以段为单位分配；<br>每段是一个连续存储区；<br>每段不一定等长；<br>段与段之间可连接，也可不连续。 | 逻辑地址分配按页分配；<br>物理地址分配按内存块分配。 | 分段方法来分配管理用户地址空间；<br>分页方法来管理物理存储空间。 |
| **长度是否固定**   | 段长不固定                                                                                       | 页长固定                                             | 段长不固定，页长固定                                             |
| **访问主存次数**   | 2次                                                                                              | 2次                                                  | 3次                                                              |
| **碎片情况**       | 只产生外部碎片                                                                                   | 产生内部碎片                                         | 产生内部碎片                                                     |

## 2.2. 连续分配管理方式

**定义**：连续分配管理是为一个用户程序分配一个连续的内存空间。

**特点**：
- 用户程序在主存中都是连续存放的；
- 非连续分配的方式的存储密度 < 连续分配方式。

**碎片**：
- **内部碎片**：当程序小于固定分区大小时，也要占用一个完整的内存分区，导致分区内部存在空间浪费；
- **外部碎片**：内存中产生的小内存块。

### 2.2.1. 单一连续分配

**定义**：
- 内存分为两个区：
- **系统区**：供OS使用，在地址区；
- **用户区**：内存用户空间由一道程序独占。

**优点**：简单，*无外部碎片*；无需进行内存保护(*内存中永远只有一道程序*)。

**缺点**：只能用于单用户单任务的OS；有内部碎片，**存储器**利用率极低。

### 2.2.2. 固定分区分配

**定义**：
- 用户内存空间划分为固定大小(*分区大小相等或不等*)的区域；
- 每个区装一道作业。

**优点**：简单。

**缺点**：程序太大可能放不下任何一个分区，有内部碎片；不能实现多进程共享一个主存区，**存储空间**利用率极低。

### 2.2.3. 动态分区分配

进程转入内存时，根据进程的实际需要，动态地分配内存；动态分区是在作业装入时动态建立的。

| 动态分配算法          | 链接次序     | 特点                |
| :-------------- | :------- | :---------------- |
| **首次适应(First Fit)** | 按地址递增的次序 | 最简单，*效果最好*，速度最快   |
| **邻近适应(Next Fit)**  | -        | 比首次适应算法差          |
| **最佳适应(Best Fit)**  | 按容量递增的次序 | 性能很差，*会产生最多的外部碎片* |
| **最坏适应(Worst Fit)** | 按容量递减的次序 | 可能导致没有可用的大内存块，性能差 |

![555](image/3-内存管理%20-%20操作系统/动态分区分配示例.png)

> **注意**：外部碎片可通过 *紧凑(拼接)技术* 缓解：操作系统周期性地移动进程，将所有空闲块合并为一个连续区域。
> 该操作要求系统支持 **动态重定位**，且开销较大。

## 2.3. 分段

### 2.3.1. 分段概念

- **分段** = 程序由若干个逻辑分段组成，不同的段有不同的属性，用分段的方式把程序进行分离；
- **段表** = 一张逻辑空间与内存空间映射的表。

![555](image/3-内存管理%20-%20操作系统/分段概念图.png)

> **注意**：分段操作用户可见。

### 2.3.2. 段的共享与保护

**段的共享**：通过两个作业的段表中相应表项指向被共享的段的统一物理副本。
**段的保护**：
- 存储控制保护；
- 地址越界保护

### 2.3.3. 优缺特点

**优点**：
- 能 **产生连续的内存空间**；
- 分段存储管理能反映程序的逻辑结构，并有利于段的共享和保护；
- 程序的动态链接与逻辑结构有关，分段存储管理有利于程序的动态链接。

**缺点**：
- 会产生 **外部碎片**；
- 内存交换的 **效率低**。

**特点**：
- 满足程序员/用户；
- 方便编程，分段共享；
- 分段保护，动态链接，增长；
- 分段管理地址空间是二维的；
- 每段的长短不同。

## 2.4. 分页

### 2.4.1. 分页概念

**分页**：把整个虚拟和物理内存空间切成一段段固定尺寸的大小，在linux中，每一页的大小为4KB。

> **注意**：
>   逻辑地址可以被划分为两部分，高位页号，低位页内地址；
>   物理地址可以被划分为两部分，高位页框号，低位页内地址。

**页/页面**：
- 页就是进程中的块；
- 页面大 -> 页内碎片增多，降低内存的利用率；
- 页面小 -> 进程的页面数大，页表过长，占用大量内存，增加硬件地址转换的开销，降低页面换入/出的效率。

**地址结构**：
- 地址结构 = 页号P + 页内偏移量W；
- 地址结构决定了虚拟内存的寻址空间有多大；
- *完成地址转换工作* 的是有硬件的地址转换机构，而不是地址转换程序。

**页表**：
- 页表就是记录页面在内存中对应的物理块号；
- 页表的起始物理地址放在页表基址寄存器(PTBR)中；
- 页表是存储在内存里的，内存管理单元(MMU)就做将虚拟内存地址转换成物理地址的工作。

> **注意**：页的思想类似于cache块与主存块，其区别如下：
>   1.cache块是*cache和主存之间*进行信息交换的单位；页可以理解成*主存和外存之间*进行信息交换的单位；
>   页大小一般4KB，而cache块的大小一般32B/64B，**一个页包含了多个块**。

### 2.4.2. 优缺特点

**优点**：能有效地提高内存利用率。

**缺点**：会产生内部碎片。

**特点**：
- **逻辑地址分配** 按页分配；
- **物理地址分配** 按内存块分配；
- 划分的页面大小都相同；
- 所有进程都有一张页表；
- 页表存在内存中；
- 分页是 **面向计算机的**；
- 整个系统设置一个页表寄存器用于存放页表在内存中起始地址和长度。

## 2.5. 分页的地址变换

### 2.5.1. 基本地址变换

1. 把虚拟内存地址，切分成页号和偏移量；
2. 根据页号，从页表里面，查询对应的物理页号；
3. 直接拿物理页号，加上前面的偏移量，得到了物理内存地址。

> **注意**：*商即逻辑页面号，余数即页内偏移地址*
> 逻辑页号 = 逻辑地址 / 页面大小 (右移n位，相当于除$2^n$)
> 页内偏移 = 逻辑地址 % 页面大小 (去除低n位，相当于%$2^n$)

![400](image/3-内存管理%20-%20操作系统/基本地址变换结构图.png)

### 2.5.2. 两级页表地址变换

> 分页产生的页表过大，使用多级页表，解决空间上的问题。

1. 一级页表覆盖到全部虚拟地址空间，二级页表在需要时创建；
2. 建立多级页表的目的在于建立索引，以便不用浪费主存空间区存储无用的页表项，也不用盲目地顺序式查找页表项；
3. **页表寄存器存放的是一级页表起始物理地址**。

![400](image/3-内存管理%20-%20操作系统/两级页表地址变换结构图.png)

> **注意**：计算方式和cache中类似，总共分为三个部分：页目录号、页号、页内偏移。
> 地址写成二进制后，从前往后划分对应位数，再转为十六进制，不足往前补0。

### 2.5.3. 具有快表的地址变换

> 很多层参与，时间上开销大，加入TLB，提高地址转换的速度。

1. **快表是相联存储器([TLB](<3-存储器层次结构 - 计算机组成原理.md### 1.2.4. 相联存储器>))**;
2. 快表也叫页表缓存，转址旁路缓存；
3. 快表专门存放程序最常访问的页表项的Cache；
4. **快表位于CPU芯片中，用于加速地址变换的过程**；
5. CPU芯片中，封装了MMU(内存管理单元)；
6. MMU用来完成地址转换和TLB的访问与交互。

![400](image/3-内存管理%20-%20操作系统/具有快表的地址变换结构图.png)

#### （一） 快表对系统的影响

1. **内存的有效访问时间(EAT)**：从进程发出地址访问请求到内存中对应的数据的这一段时间；
2. 在只有一级页表的分页管理方式中，EAT主要包括 **第一次访存**，从页表中获得页框号的时间；以及 **第二次访存**，获得所需要的数据的时间；
3. 在引入快表后，**第一次访存** 时间以一定概率被替换成访问快表的时间，这个概率称为 **快表命中率**，快表的访问时间远远低于访存时间，从而使得内存的有效访问时间大大减少。

## 2.6. 段页

### 2.6.1. 实现方法

步骤1：将程序划分为多个有逻辑意义的段[*分段*]；
步骤2：对分段划分出来的连续空间，再划分固定大小的页[*分页*]。

### 2.6.2. 地址变换

作业的逻辑地址划分为：**段号、段内页号、页内偏移量**。
对内存的管理以 *存储块* 为单位，**地址空间是二维的**。

# 三、 虚拟内存管理

## 3.1. 常考点

**虚拟存储概念相关**：
- 虚拟存储器的**最大容量**是由计算机的地址结构决定的，与主存容量和外存容量没有关系；
- 虚拟存储技术基于程序的 **[局部性原理](<3-存储器层次结构 - 计算机组成原理.md### 6.1.1. 局部性原理>)**，局部性越好，虚拟存储系统越能更好地发挥作用；
- 虚拟存储技术只能**基于非连续分配技术**；
- 使用 **覆盖，交换** 方法可以实现虚拟存储。
**页面置换算法相关**：无论采用什么页面置换算法，每种页面第一次访问时不可能在内存中，必然发生缺页，所以 **缺页次数 ≥ 不同的页号数量**。
**缺页中断相关**：
- 请求分页存储器中，**页面尺寸增大，存放程序需要的页帧数减少，缺页中断次数也会减少**；
- **影响缺页中断**的时间有：缺页率、磁盘读写时间、内存访问时间；
- **影响缺页中断可能执行的操作**：置换页面，分配内存(不会进行越界出错处理)；
- **缺页处理过程中可能执行的操作**：修改页表，分配页框，磁盘IO(内存没有页面，需要从外存读入)。
**其他**：
- [系统调用](<1-操作系统概述 - 操作系统.md## 2.4. 系统调用【广义指令】>)是由用户进程发起的，请求OS的服务；
- 创建新进程可以通过系统调用完成；
- **可以加快虚实地址转换的操作**：增大快表TLB的容量，让页表常驻内存；
- 当磁盘利用率很高，但是CPU利用率不高时，**改进CPU利用率的操作**：增大内存容量，减少多道程序的度数。

## 3.2. 虚拟内存的基本概念

### 3.2.1. 传统存储管理方式的特征

**一次性**：作业必须一次性全部装入内存，才能开始运行。
**驻留性**：
- 作业被装入内存后，就一直驻留在内存中，直到作业结束；
- 运行中的进程会因等待IO而被阻塞，可能处于长期等待状态。

### 3.2.2. 局部性原理
**[计组 - 局部性原理](<3-存储器层次结构 - 计算机组成原理.md### 6.1.1. 局部性原理>)** 
- **时间局部性**：程序中的某条指令一旦执行，不久后该指令可能再次运行(如循环)；
- **空间局部性**：程序在一段时间内所访问的地址，可能集中在一定范围内(如数组顺序访问)。

### 3.2.3. 虚拟存储器

**定义**：系统为用户提供的一个比实际内存容量大得多的存储器。

**特征**：
- **多次性**：程序可分多次调入内存，只需将当前运行的那部分程序和数据装入内存即可开始运行[*最重要的特征*]；
- **对换性**：程序可在内存和外存间动态交换，作业无需一直常驻内存，要用时换入，不要用时换出；
- **虚拟性**：从逻辑上扩充内存容量，逻辑地址空间可大于物理地址空间[*最重要的目标*]。

### 3.2.4. 虚拟内存的实现

**方式(离散分配)**：
1. 请求分页存储管理；
2. 请求分段存储管理；
3. 请求段页式存储管理。

**需要的东西**：
- 一定的硬件支持，一定容量的内存和外存；
- 页表/段表机制作为主要的数据结构；
- 中断机制，当程序要访问的内容还未调入内存时，产生中断；
- 地址变换机构。

## 3.3. 请求分页管理

**特点**：
- 只要求将当前一部分页面装入内存，便可启动作业运行，不需要一次性全部装入；
- 在作业执行的过程中，当访问的页面不存在时，再通过调页功能将其调入。

### 3.3.1. 页表机制

在基本分页管理中，OS为每个进程都建立并维护了一张页表，用来把用户地址空间中的**逻辑页面号映射**为内存中的**物理页面号**。
**每个页表项**都需要记录每个**逻辑页号对应的物理页号**。

在虚拟页式存储管理中，新增页表项字段：
  - **状态位(有效位/驻留位)**：页面是否在内存中(*1表示在内存中有效，0表示不在内存中无效*)；
  - **保护位**：读写/执行权限；
  - **修改位(脏位)**：页面是否被修改过(*供换出判断使用，已被修改==CPU==会自动置其为1*)；
  - **访问位**：页面是否被访问过(*供置换算法使用，被访问过==硬件==会自动置其为1*)。

### 3.3.2. 缺页中断处理流程

**定义**：缺页是在CPU执行某条指令过程中，进行取指令或读写数据时发生的一种故障，是 **内中断或称为异常**。
**产生时间**：
- 每当要访问的页面不在内存中时，便产生一个缺页中断，请求OS将所缺的页调入内存；
- 缺页中断是访存指令引起的，说明要访问的页面不在内存中；
- 进行缺页中断处理并调入所要访问的页后，访存指令应该重新执行。
**特点**：
- 在指令执行期间而非一条指令执行完后产生和处理中断信号；
- 一条指令在执行期间，可能产生多次缺页中断。

![500](image/3-内存管理%20-%20操作系统/缺页中断处理过程.png)
> 在地址映射中，如果所要访问的 **逻辑页面P** 不在内存，则产生缺页中断。

### 3.3.3. 地址变换机构

**新增**：
1. 产生和处理中断信号；
2. 从内存中换出一页。

![500](image/3-内存管理%20-%20操作系统/地址变换过程.png)

**具体流程**：
1. **查快表（TLB）**：CPU 发出逻辑地址（页号 + 页内偏移），硬件首先并行查询快表
	- **命中**：直接取出物理块号，并置**访问位**为 1；若是写操作，还需置**修改位**为 1。跳转到步骤 4；
	- **未命中**：转入步骤 2。
2. **查页表**：根据页表基址寄存器（PTBR）找到内存中的页表，查找该页的页表项
   - **若状态位 = 1**（页面已在内存中）：取出物理块号，**将该页表项装入快表**（若快表已满，则按替换算法淘汰一项）。跳转到步骤 4。
   - **若状态位 = 0**（页面不在内存中）：转入步骤 3。
3. **缺页中断处理**：触发缺页中断，CPU 陷入内核态，操作系统执行中断处理程序：
	- 检查内存中是否有空闲页框
		- 若有：直接调入所需页面；
		- 若无：按页面置换算法（如 LRU）**换出一页**（若被换出页面被修改过，需先写回外存）。
	- 将目标页面从外存调入内存，更新页表(状态位 = 1，记录物理块号)；
	- 更新快表(若快表已满，淘汰一项)；
	- 返回用户态，**重新执行引发缺页的那条指令**，从头开始地址变换。
4. **形成物理地址**：将查到的物理块号与页内偏移拼接，形成最终的物理地址，用于访问内存。

## 3.4. 页框分配与回收

**进程准备执行时，由OS决定给特定进程分配几个页框。**

**驻留集**：给一个进程分配的物理页框(也叫 物理块)的集合。
**驻留集的大小**：
1. 分配给进程的页框越少，驻留在内存的进程就越多，CPU的利用率就越高；
2. 进程在主存中的页面过少，缺页率相对较高；
3. 分配的页框过多，对进程的缺页率没有大的影响。

### 3.4.1. 内存分配策略

- **固定分配局部置换**：物理块固定，缺页时先换出一个线程再调入所缺页；
- **可变分配全局置换**：物理块可变，缺页时增加物理块再调入所缺页；
- **可变分配局部置换**：物理块可变，若不频繁缺页则用局部置换，频繁缺页再用全局置换。
> **注意**：对个进程进行固定分配时页面数不变，不可能出现全局置换。

### 3.4.2. 页框调入算法

1. 平均分配算法；
2. 按比例分配算法；
3. 优先权分配算法。

### 3.4.3. 调入页面的时机

**预调页策略 = 运行前的调入**：主要用于进程的首次调入，由程序员指出应先调入哪些页；
**请求调页策略 = 运行前的调入**：
- 调入的页一定会被访问，策略易于实现；
- 每次仅调入一页，增加了磁盘IO的开销。

### 3.4.4. 请求分页系统外存组成

- 存放文件的文件区[*采用离散分配方式*]；
- 存放对换页面的对换区[*采用连续分配方式*]。
> **注意**：对换区的磁盘IO速度更快。

### 3.4.5. 从何处调入页面

1. 系统拥有足够的对换区空间；
2. 系统缺少足够的对换区空间；
3. UNIX方式。

### 3.4.6. 如何调入页面

情况1：
  所访问的页面不在内存时 --> 缺页中断 --> *无空闲物理块* --> 决定淘汰页 --> 调出页面 --> 调入所缺页面。
情况2：
  所访问的页面不在内存时 --> 缺页中断 --> *有空闲物理块* --> 调入所缺页面。

## 3.5. 页面置换算法

当**缺页中断发生时**，需要调入新的页面，如果此时内存已经满了，就需要使用页面置换算法，从内存中选择一个页面，把它置换出去。

|        | 最佳置换算法(OPT)                            | 先进先出置换算法(FIFO)                                       | 最近最久未使用置换算法(LRU)                                          | 时钟置换算法(CLOCK)   |
| ------ | :------------------------------------- | :--------------------------------------------------- | :-------------------------------------------------------- | :-------------- |
| 英文全称   | Optimal replacement                    | First In First Out                                   | Least Recently Use                                        | Clock           |
| 被淘汰的页面 | 以后永不使用的                                | 在内存中驻留时间最久的页面                                        | 最近最长时间未访问过的页面                                             | 最近未使用的页面        |
| 特点     | 基于队列实现的；<br>**该算法无法实现**；<br>只能用于评价其他算法 | 会出现Belady异常(*分配的物理块数增大，但也故障数不减反增*)；<br>**性能差，但实现简单** | **性能好，但实现复杂**；<br>需要寄存器和栈道硬件支持；<br>堆栈类算法；<br>耗费高因为要对所有页排序 | **FIFO和LRU的结合** |
> **注意**：Belady异常在[Cache的替换算法](<3-存储器层次结构 - 计算机组成原理.md### 6.4.2. 先进先出（FIFO）(\*)>)中也出现过，*给的越多，反而越差*。

### 3.5.1. 抖动（Thrashing）

- **定义**：进程频繁缺页，系统忙于换入换出，导致 CPU 利用率急剧下降。
- **根本原因**：分配给进程的物理块数 < 其工作集大小。
- **解决思路**：通过工作集模型，保证驻留集 ≥ 工作集。

### 3.5.2. 工作集与驻留集

- **工作集（Working Set）**：进程在一段时间间隔内频繁访问的页面集合。
- **驻留集（Resident Set）**：进程当前实际驻留在内存中的页面集合。
- **关系**：驻留集大小应 ≥ 工作集大小，否则会频繁缺页，引发抖动。

## 3.6. 内存映射文件（Memory-Mapped Files）

- 将磁盘文件内容映射到进程的虚拟地址空间。
- 进程可直接通过内存地址访问文件内容，由 OS 自动完成磁盘 I/O。
- 优点：简化文件访问，便于进程间共享同一文件。

## 3.7. 虚拟存储器性能影响因素

### 3.7.1. 缺页率

- **定义**：缺页次数 / 总访问次数。
- **影响因素**：页面大小、置换算法、分配页框数、程序局部性。

### 3.7.2. 页面大小

- **太小**：页表过大，TLB 命中率低，页表占用内存多。
- **太大**：内部碎片增加，调入/调出开销大。
- **选择原则**：需在页表大小、碎片率、I/O 开销之间折中。

### 3.7.3. 性能改进方向

- 选用更优的置换算法（如 LRU / CLOCK）。
- 合理设置页面大小。
- 采用预调页策略，减少缺页等待。
- 利用 TLB 加速地址转换。
