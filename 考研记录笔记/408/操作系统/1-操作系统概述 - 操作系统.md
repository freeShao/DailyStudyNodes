# 一、 操作系统概述

## 1.1. 操作系统的基本概念

1. **定义**：操作系统是**管理计算机硬件和软件资源**的系统软件，为用户提供使用计算机的接口。
2. **四大特征**：**并发**（关键特征，区别于并行）、**共享**、**虚拟**、**异步**。
3. **功能**：处理机管理、存储器管理、设备管理、文件管理、提供用户接口。

## 1.2. 操作系统的特征

**并发和共享** 是最基本的两个性质。
并发和共享护卫存在条件，没有并发和共享，就谈不上虚拟和异步。

#### （一） 并发

**并发**：两个或多个事件在同一时间间隔内发送【**同一时间间隔**】
**并行**：系统具有同时进行运算或操作的特性【**同一时刻**】
- 可并行的有【处理机与设备】【处理机与通道】【设备与设备】
- 不可并行的有【进程与进程】
- 真正实现并行的是多核处理机

#### （二） 共享

**共享**：是指系统中的资源可供内存中多个并发执行的程序共同使用。
1. **互斥共享方式**：
	- A用完后，才可以给B用；
	- 如对摄像头设备的共享使用。
2. **同时共享方式**：
	- 一段时间内由多个进程同时访问；
	- 如对硬盘资源的共享使用。

#### （三） 虚拟

**虚拟**：是指把一个物理上的实体变为若干逻辑上的对应物。
1. **空分复用技术**【虚拟的扩充空间】：如虚拟存储器。
2. **时分复用技术**【虚拟的扩充时间】：如处理器的分时共享。

#### （四） 异步

进程的执行不是一贯到底的，而是走走停停的，它以不可预知的速度向前推进。

## 1.3. 操作系统的功能和目标

操作系统四大核心功能：**处理机管理、存储器管理、设备管理和文件管理**。

#### （一） 资源的管理者

1. **处理器管理**：
	1. 处理器的分配和运行都以进程为基本单位，处理器管理=对进程的管理；
	2. **主要功能**：进程控制+进程管理+进程通信+死锁处理+处理机调度。
2. **存储器管理**：
	1. 为了给多道程序的运行提供良好的环境，方便用户使用及提高内存的利用率；
	2. **主要功能**：内存分配与回收+地址映射+内存保护+共享和内存扩充。
3. **文件管理**：
	1. 计算机的信息都是以文件的形式存在的；
	2. **主要功能**：文件存储空间的管理+目录管理+文件读写管理和保护。
4. **设备管理**：
	1. 主要是完成用户的I/O请求，方便用户使用各种设备，提高设备的利用率；
	2. **主要功能**：缓冲管理+设备分配+设备处理+虚拟设备。

#### （二） 为用户和计算机硬件系统提供接口

![316](image/1-操作系统概述%20-%20操作系统/用户与硬件系统之间的接口.png)

**给用户使用**：
- GUI用户图像界面
- 命令接口
	- **联机命令接口**：用户发送一个命令，系统就执行一次，主要特点是 **交互性**，适用于分时或实时系统；
	- **脱机命令接口**：用户一次性发送命令清单，系统按清单执行，**中途不能干预**，适用于批处理系统。【解决独占问题】
**给软件/程序员使用**：
- 程序接口【即*系统调用*】

#### （三） 对计算机资源的扩充

**裸机**：没有任何软件支持的计算机；
**扩充机器/虚拟机**：覆盖了软件的机器。

## 1.5. 操作系统结构

### 1.5.1. 宏内核

**定义**：所有的系统功能都放在内核里(*大内核结构的OS通常也采用了“模块化”的涉及思想。*)
**优点**：
1. 性能高；
2. 内核内部各种功能可以直接互相调用。

**缺点**：
1. 内核庞大功能复杂，难以维护；
2. 大内核中某个功能模块出错，就可能导致整个系统崩溃。

### 1.5.2. 微内核

**定义**：只把核心功能放入内核，其余功能用用户进程的形式运行在用户态。
**优点**：
1. 内核足够小；
2. 基于C/S模式；
3. 应用机制与策略分离原理；
4. 采用面向对象技术。
**缺点**：性能低、开销大。

### 1.5.3. 分层与模块化

**分层结构**：单向依赖，易于调试与扩充。*但效率低，不可跨层调用，系统调用执行时间长。*
**模块化结构**：模块间通过接口通信，灵活性高。
**宏内核**：所有系统服务都在**内核态**运行，效率高，但可靠性差（如Linux）。
**微内核**：内核只保留最基本功能，服务在**用户态**运行，可靠性高，但性能有开销（如Windows NT）。
**外核**：硬件抽象层，让应用直接管理硬件资源。

## 1.6. 操作系统引导【开机过程】

程序不执行的时候被保存在外村中，保存在外存中的这些01序列被称为 **文件**。
等程序运行的时候，**再从外存中将这些01序列给复制到主存中**，然后 **CPU不断从主存中取出指令以及数据执行**。

> **注意**：对于一般的程序，实际上是 **操作系统通过执行相关的指令，把这个程序调入内存，然后修改PC的值，使得该程序能够执行。**

![](image/1-操作系统概述%20-%20操作系统/操作系统引导.png)
![](image/1-操作系统概述%20-%20操作系统/操作系统引导2.png)

**启动过程**：
1. CPU加电，CS：IP指向 `FFFF0H`；
2. 执行 `JMP` 指令跳转到 `BIOS`；
3. 登记 `BIOS` 中断例程入口地址；
4. 硬件自检；
5. 进行操作系统引导。

**引导过程**：
1. CPU从一个特定的主存地址开始，取指令，执行ROM中的引导程序【*即前面的启动过程*】；
2. 将磁盘的第一块 *主存引导记录* 读入内存，执行磁盘引导程序，扫描分区表；
3. 从活动分区【*又称主分区，即安装了操作系统的分区*】读入分区引导记录，执行其中的程序；
4. 根据根目录下找到完整的操作系统初始化程序【*即启动管理器*】并执行，完成开机的一系列操作。

**计算机加点启动过程中执行程序的过程**：

自检程序 --> 引导装入程序/自举装入程序  --> 引导程序 --> 操作系统

# 二、 操作系统的运行环境

硬件系统是计算机系统的 **最底层**，是指令的 **实际执行者**，**软件必须借助硬件提供的指令** 才能实现其功能。
*任何系统软件都是建立在硬件基础上的，离不开硬件设施的支持。*

设计操作系统时，需要硬件提供五个方面的支持：
*中断机制、特权指令、系统调用、内存保护、输入输出系统*

## 2.1. 处理器运行的机制

### 2.1.1. 程序运行的原理

高级语言程序编写代码，然后转换为机器指令，即[编译程序](<1-计算机系统概述 - 计算机组成原理.md#### （二） 按语言分类>)；
程序运行的过程就是CPU执行指令的过程。

### 2.1.2. 两种程序

内核程序
应用程序

### 2.1.3. 两种指令

#### （一） 特权指令

指不允许用户直接使用的指令。
- IO设备操作指令；
- 存取特殊寄存器的指令；
- 有关访问程序状态的指令；
- 置中断指令；
- 关中断指令；
- 清内存指令；
- 置时钟指令。

#### （二） 非特权指令

允许用户直接使用的指令；不能直接访问系统中的软硬件资源；只限于访问用户的地址空间。
- 访管/trap指令。

### 2.1.4. 两种处理器状态

#### （一） 核心态【管态】

可执行特权指令，运行操作系统内核。
- 时钟管理相关的指令【置时钟指令】；
- 中断机制相关的指令【时钟中断程序】；
- 原语相关的指令；
- 系统控制的数据结构与处理【进程调度程序】【进程切换】【缺页处理程序】。

#### （二） 用户态【目态】

只能执行非特权指令，进行用户程序。
- 命令解释程序【属于命令接口，面向用户】；
- 访管/Trap指令，跳转指令，压栈指令；
- 广义指令(系统调用)的调用；
- 外部中断，缺页。

#### （三） 模式切换

即变态，通过**中断/异常/系统调用**从用户态陷入内核态。
**内核态->用户态**：发生在*中断返回用户程序时*，需要一条修改 **PSW(程序状态字)** 的特权命令；
**用户态->内核态**：发生在*中断时*，通过硬件完成。

> **注意**：区分核心态与用户态的原因是 **保护系统程序**。

## 2.2. 内核的功能

时钟管理：实现时钟功能；
中断处理：负责实现中断机制；
设备管理：完成设备的请求和释放，以及设备启动等功能；
文件管理：完成文件的读，写，创建和删除等功能；
进程管理：完成进程的创建，撤销，阻塞及唤醒等功能；
进程通信：完成进程之间的信息传递或信号传递等功能；
内存管理：完成内存的分配，回收以及获取作业占用内存区大小及地址等功能。
**原语**：
- 是一种特殊的程序；
- 处于操作系统最底层，是最接近硬件的部分；
- 该程序运行具有原子性(运行只能一气呵成，不可中断)；
- 运行时间较短，调用频繁。

## 2.3. 外中断和内中断

**核心区别**：内中断（异常）由CPU内部事件**同步**触发，与当前指令相关；外中断（中断）由外部设备**异步**触发，与当前指令无关。
**响应流程**：关中断 → 保存断点 → 识别中断源 → 转入处理程序 → 开中断。
> **注意**：中断响应流程适用于内外中断，均需要CPU检测到需要响应的事件后的处理。**作为中断响应的共同骨架**

### 2.3.1. 内中断(异常)

**基本概念**：
- 由 **CPU内部** 产生的意外事件；
- 是CPU执行一条命令时，由CPU在其内部检测到的、与正在执行指令相关的 **同步事件**；
- 故障与自陷为 **异常**；
- 终止异常和外中断 **属于硬件中断**。

**分类**：
1. **故障**：在引起故障的指令启动之后、执行结束前被检测到的异常事件；
2. **自陷**：也称陷阱或陷入，是预先安排的一种“异常事件”，就像预先设置好的“陷阱”一样；
3. **终止**：若在执行指令的过程中发生了使计算机无法继续执行的硬件故障，那么程序将无法继续执行，只能终止。

**执行时间**：CPU在执行指令时会检查是否有异常发生。

**不同点**：
- “缺页”或“溢出”等异常事件是由特定指令在指令过程中产生的；
- **异常的检测由CPU自身完成**，不必通过外部的某个信号通知CPU。

**样例**：
- **故障**：
	1. 指令译码时，出现“非法操作码”；
	2. 取数据时，发生“缺段”或“缺页”；
	3. 除数为零；
	4. 地址越界。
- **自陷**：
	1. X86机器中，用于程序调试“断点设置”和单步跟踪功能；
	2. 系统调用指令；
	3. 条件自陷指令。
- **终止**：
	1. 控制器出错；
	2. 存储器校验错；
	3. 调出中断服务程序来重启系统。

### 2.3.2. 外中断(中断)

**基本概念**：
- 由来自 **CPU外部** 的设备发出的中断请求(常用于输入输出)；
- 典型的由外部设备触发的、与当前正在执行的指令无关的 **异步事件**；
- 外部IO设备通过特定的中断请求信号线向CPU提出中断请求；
- CPU每 **执行完一条指令** 就 **检查中断请求信号线**，若检测到中断请求，则进入中断响应期；
- 外部中断都是在一条指令 **执行完成后(中断周期)** 才被检测并处理的。

**分类**：
1. **可屏蔽中断**：
	- 通过 **可屏蔽中断请求线INTR** 向CPU发出的中断请求；
	- CPU可以通过在中断控制器中设置相应的屏蔽字来屏蔽或不屏蔽它，被屏蔽的中断信号将不被送到CPU。
2. **不可屏蔽中断**：
	- 通过 **不可屏蔽中断请求线NMI** 向CPU发出的中断请求；
	- 通常是非常紧急的硬件故障，如 **电源掉电** 等。


**执行时间**：每个指令周期末尾，CPU都会检查是否有外中断信号需要处理。

**不同点**：中断不予任何指令相关联，也不阻止任何指令的完成。

**样例**：
1. Cache缺失；
2. IO中断：键盘输入，打印机缺纸(*并非缺页-缺页属于异常*)；
3. 时钟中断；
4. IO中断请求。


## 2.4. 系统调用【广义指令】

**定义**：
- 操作系统对应用程序和程序员提供的接口；
- 系统调用需要触发 Trap【*也叫陷入/访管指令*】；
- os通过提供系统调用，避免用户程序直接访问外设【*应用程序通过系统调用使用os的 **设备管理服务***】
> **注意**：系统调用命令经过编译后，形成 **若干参数和陷入指令**。

**目的**：请求系统服务。

**与库函数的区别**

| 库函数                                                                     | 系统调用                                                                                                   |
|:-------------------------------------------------------------------------- |:---------------------------------------------------------------------------------------------------------- |
| 是语言或应用程序的一部分，可以运行在用户空间中。                           | 是操作系统的一部分，是内核为用户提供的程序接口，运行在内核空间。                                           |
| **许多库函数都会使用系统调用来实现功能**；<br>有的库函数没有使用系统调用。 | 未使用系统调用的库函数，执行效率通常比系统调用的高。<br>【因为**系统调用要完成上下文的切换和状态的转换**】 |

**按功能分类**：
- **设备管理**：完成设备的请求或释放+设备启动；
- **文件管理**：完成文件的读+写+创建+删除；
- **进程管理**：完成进程的创建+撤销+阻塞+唤醒；
- **进程通信**：完成进程之间的信息传递或信号传递；
- **内存管理**：完成内存的分配+回收+获取作业占用内存区大小及始址。

**系统调用的过程**：

![600](image/1-操作系统概述%20-%20操作系统/系统调用的过程.png)

步骤1：传参；
步骤2：陷入指令/Trap/访管【*执行系统调用*】，**发生在用户态**；
步骤3：由操作系统内核程序处理系统调用请求，**发生在内核态**；
步骤4：返回应用程序。

## 2.5. 程序的链接与装入

### 2.5.1. 程序装入（Load）

**概念**：将程序从外存（磁盘）加载到内存中，使其具备运行条件。

**装入方式**（按地址转换时机划分）：

| 装入方式 | 地址转换时机 | 特点 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **绝对装入** | 编译时确定物理地址 | 装入后地址固定，无需地址转换 | 单道程序、嵌入式系统 |
| **可重定位装入**（静态重定位） | 装入时一次性转换所有地址 | 装入后地址固定，运行期间不变 | 早期多道批处理系统 |
| **动态运行时装入**（动态重定位） | 运行时每次访问地址时才转换 | 支持程序在内存中移动，地址转换由MMU完成 | 现代OS（虚拟内存基础） |

### 2.5.2. 程序链接（Link）

**概念**：将多个目标模块（.o）和库函数组合成一个完整的可执行文件。

**链接方式**：

| 链接方式        | 时机      | 特点                 | 优缺点                        |
| :---------- | :------ | :----------------- | :------------------------- |
| **静态链接**    | 编译阶段    | 所有代码**合并**为一个可执行文件 | 优点：独立运行<br>缺点：文件大，更新库需重新链接 |
| **装入时动态链接** | 装入内存时   | 在装入时解析未确定的外部符号     | 节省磁盘空间，但装入速度稍慢             |
| **运行时动态链接** | 程序执行过程中 | 在程序运行时按需加载所需模块     | 最灵活，共享库（.dll/.so）基础        |

### 2.5.3. 链接与装入的关系

- **编译 → 链接 → 装入 → 执行** 是程序运行的完整链条。
- **链接**解决的是“模块间引用”问题（外部符号解析）。
- **装入**解决的是“地址分配”问题（逻辑地址→物理地址）。

## 2.6. 程序运行时内存映像与地址空间

### 2.6.1. 程序的内存映像（Memory Image）

**概念**：程序在内存中的布局，即进程的地址空间结构。

**典型布局**（从低地址到高地址）：

| 段 | 内容 | 特点 |
| :--- | :--- | :--- |
| **代码段（.text）** | 指令代码 | 只读，可共享 |
| **数据段（.data）** | 已初始化的全局变量/静态变量 | 读写 |
| **BSS段** | 未初始化的全局变量/静态变量 | 运行前初始化为0，不占用磁盘空间 |
| **堆（Heap）** | 动态分配的内存（malloc/new） | 向高地址增长 |
| **栈（Stack）** | 函数调用帧、局部变量、返回地址 | 向低地址增长 |
| **内核空间** | 操作系统代码和数据 | 用户态不可访问（高地址区域） |

### 2.6.2. 地址空间（Address Space）

| 概念 | 定义 | 特点 |
| :--- | :--- | :--- |
| **逻辑地址空间** | 程序视角的地址范围（虚拟地址） | 每个进程拥有独立的逻辑地址空间 |
| **物理地址空间** | 实际内存硬件的地址范围 | 所有进程共享，由OS统一管理 |

**地址转换**：
- **逻辑地址 →（MMU+页表）→ 物理地址**
- 现代OS通过**虚拟内存**使逻辑地址空间可大于物理地址空间

# 三、 虚拟机

**定义**：使用虚拟化技术，将一台物理机器虚化为多台虚拟机器VM，每个虚拟机器都可以独立运行一个操作系统。

|           | 第一类VMM                                                     | 第二类VMM                                                              |
| --------- | :--------------------------------------------------------- | :------------------------------------------------------------------ |
| 对物理资源的控制权 | 直接运行在硬件上，能直接控制和分配物理资源。                                     | 运行在Host OS之上，依赖于Host OS为其分配物理资源。                                    |
| 资源分配方式    | 在安装Guest OS时，VMM要在原本的硬盘上自行分配存储空间，类似于“外核”的分配方式，分配未经抽象的物理硬件。 | GusetOS拥有自己的虚拟磁盘，该盘实际上是Host OS文件系统的一个大文件。GuestOS分配到的内存是虚拟内存。        |
| 性能        | 性能更好。                                                      | 性能更差，需要HostOS作为“中介”。                                                |
| 可支持的虚拟机数量 | 更多，不需要和Host OS竞争资源，相同的硬件资源可以支持更多的虚拟机。                      | 更少，Host OS 本身需要使用物理资源，Host OS上运行的其他进程也需要物理资源。                       |
| 虚拟机的可迁移性  | 更差。                                                        | 更好，只需要导出虚拟机镜像文件即可迁移到另一台Host OS上，商业化应用更广泛。                           |
| 运行模式      | 第一类VMM运行在最高特权级(Ring 0)，可以执行最高特权的指令。                        | 第二类VMM部分运行在用户态、部分运行在内核态。GuestOS发出的系统调用会被VMM截获，并转化为VMM对Host OS的系统调用。 |
