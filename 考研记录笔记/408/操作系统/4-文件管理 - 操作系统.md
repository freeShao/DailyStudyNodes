# 一、 文件

## 1.1. 常考点

**UNIX相关知识**：
- UNIX采用树型目录结构，文件信息存放在索引节点中，超级块是用来描述文件系统的；
- UNIX系统所有设备都被视为特殊文件；
- UNIX每个目录文件中，默认有两个目录项，`.`代表当前目录，`..`代表父目录。
**各种表、图**：
1. **打开文件夹**：存放已经打开的文件信息的表，将指明文件的属性从外存复制到内存，在使用该文件时直接返回索引；
2. **位图**：==磁盘管理方法==；
3. **空闲盘链表**：==磁盘管理方法==；
4. **索引表**：记录每个文件所存放的盘块地址；
5. **系统调用表**：是一张由指向实现各种系统调用的内核函数的函数指针组成的表，该表可以基于系统调用函数进行索引，来定位函数地址，完成[系统调用](<1-操作系统概述 - 操作系统.md## 2.4. 系统调用【广义指令】>)。
**文件性能相关**：
- **与单个文件长度/大小有关的因素**：文件块大小，地址项个数，间接地址索引的级数(索引节点总数与单个文件大小无关)；
- **提高文件访问速度的方法**：提前读，延迟写，为文件分配连续的簇，采用磁盘高速缓存；
- **文件在磁带上采用连续存放方式**；在硬盘上不采用连续存放方法；在内存上采用随机存放方法；
- 连续结构的文件数据读最快，链式的方法不能随机存取，索引的方法占面积。
**文件打开相关**：
- 文件打开 `open` 是把FCB(文件控制块)读到内存，不是把文件内容读到内存(*即不会读入文件数据，只有用`read`的时候才会读数据*)；
- `open`参数包含文件名；
- `read/write`参数不包含文件名，而是`open`返回的文件索引。
**文件保护相关**：
- **防止文件受损的方法**：备份；
- **用于多用户之间的存取权限保护**：存取控制矩阵方法。
**其他**：
- 系统级安全管理包括注册和登录；
- 用户确定文件的逻辑结构，由操作系统设计者根据文件存储器的特性确定文件的物理结构，一旦确定，由操作系统管理。

## 1.2. 文件的基本概念

**文件**：
- 文件是以硬盘为载体的存储在计算机上的信息集合；
- 文件可以是文本文档，图片，程序；
- 用户进行的输入输出中，以文件为基本单位。

**文件组成**：
- 一块存储空间；
- 分类和索引的信息；
- 关于访问权限的信息。

**文件特性**：
- 可以长期存储在硬盘中；
- 允许可控制的进程间共享访问；
- 能够被组织成复杂的结构。

**文件的属性/元数据**：
- 文件名；文件类型；
- 创建者；所有者；
- 位置；大小；保护；创建信息。

## 1.3. 文件的数据结构

### 1.3.1. 目录项

**概念**：
- **目录项/FCB** = 用来记录文件的名字，索引节点指针以及其他目录项的层级关联关系；
- **目录/目录文件**：FCB的集合；
- 为了实现“按名存取”，在文件系统中为每个文件设置用于描述和控制文件的数据结构，称作文件控制块FCB，也叫做目录项；
- 目录也被视作一个文件，该文件叫做目录文件；
- 目录项是由内核维护的一个数据结构，缓存在内存，目录项文件存储在磁盘；
- 目录文件存放该目录中所有子目录文件和数据文件的目录。

**包含信息**：
- **基本信息**：文件名；文件物理位置，文件逻辑结构，文件物理结构；
- **存取控制信息**：文件主或核准用户或一般用户的存取权限；
- **使用信息**：文件创立时间，上次修改时间。

### 1.3.2. 索引节点

**概念**：
- **索引节点** 是用来记录文件的元信息，是文件的唯一表示；
- 索引节点同样占用磁盘空间；
- 将文件描述信息从目录项中分离，即应用了索引某节点的方法；
- 使用索引节点可以减少查找文件时的IO信息量。

**分类**：
1. **磁盘索引节点**：
	- 指存放在**磁盘上**的索引节点，每个文件有一个唯一的磁盘索引节点；
	- **包含内容**：文件主标识符；文件类型；文件存取权限；文件物理地址；文件长度；文件链接计数；文件存取时间。
2. **内存索引节点**：
	- 指存放在**内存中**的索引节点，文件打开后，将磁盘索引节点复制到内存中；
	- **新增内容**：索引节点编号；状态；访问计数；逻辑设备号；链接指针。

## 1.4. 文件的操作

**基本操作**：创建文件；写文件；读文件；重新定位文件；删除文件；截断文件。

**文件打开的过程**：
- 文件打开就是调用`open`，根据文件名搜索目录，将指明文件的属性(包括该文件在外上的物理地址)从外存**复制**到内存打开文件表的一个表目中，并将该表目的编号(也叫索引)返回给用户；
- 打开文件操作的主要工作就是把*指定文件的目录复制到内存指定的区域*；
- `open`操作会把文件FCB(文件控制块)调入内存，而不会把文件内容读到内存，只有进程虚妄获取文件内容时才会读入文件内容。

**文件打开和关闭关联的信息**：文件指针；文件打开计数；文件磁盘位置；访问权限。
> **注意**：文件描述符是打开文件的标识。

## 1.5. 文件的保护

**保护的目的**：解决对文件的读，写，执行的许可问题。
一个文件的访问常由 **用户访问权限和文件属性**(*包括保存在文件控制块(FCB)中对文件访问的控制信息*)共同设置。

### 1.5.1. 保护的方式

#### （一） 非访问控制方法

|          | 口令                                                                 | 加密保护                         |
| -------- |:-------------------------------------------------------------------- |:-------------------------------- |
| **定义** | 用户建立一个文件时需要提供口令；<br>用户请求访问时**必须**提供口令。 | 对文件进行加密，访问时需要密钥。 |
| **优点** | 时间空间开销不多。                                                   | 保密性强，节省了存储空间。       |
| **缺点** | 口令直接存在系统内部，不安全。                                       | 编码和译码需要时间。             |

#### （二） 访问控制方法

**访问控制的目的**：用于控制用户对文件的访问方式。
**访问控制的对象**：读；写；执行；添加；删除；列表清单。
访问控制基址必须**由系统实现**。

|      | 方法1                                                                                 | 方法2                                                                  |
| ---- |:------------------------------------------------------------------------------------- |:---------------------------------------------------------------------- |
| 定义 | 为每个文件和目录增加一个访问控制列表ACL；<br>该表规定每个用户名及其所允许的管理空间。 | 采用精简的访问列表；<br>该列表采用 **拥有者，组和其他** 三种用户类型。 |
| 优点 | 可以使用复杂的访问方法。                                                              | 只需要三个域即可列出访问表中这三类用户的访问权限。                     |
| 缺点 | 长度无法预计且可能导致复杂的空间管理。                                                | -                                                                      |

## 1.6. 文件的逻辑结构

**用户角度的文件组织形式。**

**定义**：文件中的数据在逻辑层面是如何组织起来的。

**无结构文件(流式文件)**：
- 最简单的文件组织形式，是有序相关信息项的集合，以 **字节** 为单位；
- 对基本信息单元操作不多的文件适合该方式(*如：源代码文件，目标代码文件*)。
**有结构文件(记录式文件)**：由若干记录组成
1. **顺序文件**(记录按顺序排列)：
	- 串结构：只能按顺序查找，费时；
	- 顺序结构：可采用折半查找，检索效率高；
	- **顺序查找平均次数 $\frac{N}{2}$；索引顺序查找平均查找次数 $N^{\frac{1}{2}}$**
2. **索引文件**(每个记录建立索引表)：提高了存取速度，但索引表增加了存储空间；
3. **索引顺序文件**(索引+顺序结合)：
	- 同一组中的关键字可以无序，但组与组之间的关键字必须有序；
	- 先通过索引表查找所在的组，然后在该组中使用顺序查找。

## 1.7. 文件的物理结构

**文件在外存上的存储组织形式。**

**定义**：研究文件数据在物理存储设备上是如何分布和组织的。
- 文件在 **磁带** 上 --> 连续存放方式；
- 文件在 **磁盘** 上 --> 不采用连续存放方式；
- 文件在 **内存** 上 --> 随机存放方式。

### 1.7.1. 文件的存储方式

**文件的存储方式**：文件的存储就是对 **磁盘非空闲块** 的管理。

| 方式       | 访问磁盘次数       | 优点                                           | 缺点                                       |
| :------- | :----------- | :------------------------------------------- | :--------------------------------------- |
| **顺序分配** | 需访问磁盘1次      | 顺序**存取速度快**，当**文件是定长时**，可根据文件起始地址及记录长度进行随机访问 | **要求连续的存储空间**，**会产生外部碎片**，不利于文件的动态扩充     |
| **链表分配** | 需访问磁盘n次      | **无外部碎片，提高了外存空间的利用率，动态增长较方便**                | 只能按照文件的指针链顺序访问，**查找效率低**，指针信息存放小号内存或磁盘空间 |
| **索引分配** | m级需要访问磁盘m+1次 | 可以 **随机访问**，易于文件的增删                          | 索引表增加存储空间的开销，索引表的查找策略对文件系统效率影响较大         |

#### （一） 顺序分配
**类似数组**
顺序(连续)分配：
- 文件头需要指定 **起始块的位置和长度**；
- 要求 **连续的存储空间**；
- **可随机访问**。

![400](image/4-文件管理%20-%20操作系统/顺序分配结构.png)

#### （二） 链接分配
**类似链表**

链接(表)分配：
- 存放是离散的，不是连续的，于是就可以消除磁盘碎片；
- 可大大提高磁盘空间的利用率，同时文件的长度可以动态扩展；
- **隐式链接** 无法直接访问数据块，只能通过指针顺序访问文件；
- **显示链接** 把用于链接文件各数据块的指针，显式地存放在内存的一张链接表中；
- 内存中的这样的一个表格称为 **文件分配表(FAT)**;
- 不可随机访问。

1. **隐式链接**：除了最后一块外，**每个盘块均存有指向下一个盘块的指针**，指针对用户透明。
	![400](image/4-文件管理%20-%20操作系统/隐式链接结构.png)
2. **显示链接**：链接各个物理块的指针集中存在内存的一张全局表中，**该表在整个文件系统中仅设一张**，称为 **文件分配表(FAT)**。
	![400](image/4-文件管理%20-%20操作系统/磁盘文件的分配表.png)

> **注意**：为解决隐式的缺点，引入 **簇** 的概念：
> 将若干连续的盘块组成一个簇(*基本分配单位*)，文件的分配与链接均以簇为单位进行。
> **代价**：可能产生内部碎片。

#### （三） 索引分配
**类似索引表**

索引分配：
- 为每个文件创建一个 *[索引数据块]*；
- 存放的是指向文件数据块的指针列表；
- 可随机访问。

1. **单级**:
	![400](image/4-文件管理%20-%20操作系统/单级索引分配结构.png)
2. **多级**：与内存管理中的[多级页表](<3-内存管理 - 操作系统.md### 2.5.2. 两级页表地址变换>)思想类似。
	![400](image/4-文件管理%20-%20操作系统/多级索引分配结构.png)
3. **混合**：根据文件大小动态选用最合适的分配策略。
	![400](image/4-文件管理%20-%20操作系统/混合索引分配结构.png)
> *对于小文件*：使用直接查找的方式可以减少索引数据块的开销；
> *对于大文件*：以多级索引的方式来支持，大文件在访问数据块时需要大量查询。

# 二、 目录

## 2.1. 常考点

**目录结构相关**：
1. 在树形目录中，为了加快文件检索速度，可设置当前目录，于是文件路径可以从当前目录开始查找；
2. 文件系统采用多级目录的目的是解决命令冲突；
3. 树形目录结构中，用户对文件的首次访问通常采用文件路径名，之后对文件的访问通常使用文件描述符。
**目录检索相关**：在顺序检索法时，只要路径名的一个分量名未找到，就应停止查找。
**文件共享相关**：用户进程的 *打开文件表* 关于同一个文件不一定相同(*如：读写指针位置不一定相同*)。
**其他**：整个文件系统只有一个系统文件打开表(里面的表项都是不重复的)，同一文件打开多次只需 *改变引用计数*。

## 2.2. 目录的基本概念

每当建立一个新文件时，**系统就为其设立一个FCB(文件控制块)**，其中记录该文件的所有属性信息。
**多个文件的FCB组成了文件目录**，文件目录也以文件形式保存起来，这个文件就是目录文件。

UNIX文件系统把文件目录项中的文件名和其他管理信息分开，后者单独组成一个定长的数据结构，称为 **索引节点(i-node/inode/i节点指针)**。

### 2.2.1. 目录管理要求

1. 实现 “按名存取”；
2. 需要提高目录的检索速度；
3. 需要提供用于控制访问文件的信息；
4. 允许不同用户对不同文件采用系统的名字。

## 2.3. 目录结构

### 2.3.1. 单级目录结构

**定义**：
- 整个文件系统只建立一张目录表；
- 每个文件占一个目录项/FCB。

**缺点**：
- 查找速度慢；
- 文件不允许重名
- 不便于文件共享；
- 不适合多用户的OS。

![500](image/4-文件管理%20-%20操作系统/单级目录结构.png)

### 2.3.2. 两级目录结构

**定义**：
- 文件目录分为 **主文件目录(MDF)** 和 **用户文件目录(UFD)**;
- MDF 记录用户名 UFD 所在的存储位置；
- UFD 记录用户文件的 FCB 信息。

**优点**：
- **解决了多用户之间的文件重名问题**；
- 文件系统可以在目录上实现访问限制。

**缺点**：缺乏灵活性，不能对文件分类。

![500](image/4-文件管理%20-%20操作系统/两级目录结构.png)

### 2.3.3. 树形目录结构

**定义**：
- 使用绝对路径，相对路径，当前路径的结构；
- 不同的用户的文件，文件名可相同可不同；
- **大多OS采用这种目录结构**

**优点**：
- 可以很方便的对文件进行分类；
- 能够有效地进行文件的管理和保护；
- 利于文件共享(*基于链接机制*)。

**缺点**：查找文件增加了磁盘访问次数，会影响查询速度。

![500](image/4-文件管理%20-%20操作系统/树形目录结构.png)

> **绝对路径**：从根目录开始的完整路径；
> **相对路径**：从当前目录开始的路径。

### 2.3.4. 无环图目录结构

**定义**：
- 在树形目录结构上；
- 加入有向边，组成一个有向无环图。

**优点**：实现了文件共享。

**缺点**：使系统的管理变得更加复杂。

![300](image/4-文件管理%20-%20操作系统/无环图目录结构.png)

## 2.4. 目录的操作

搜索文件，修改目录，创建文件，创建目录，删除目录，移动目录，显示目录。
> **注意**：删除一个文件时，会根据FCB回收相应的磁盘空间，将FCB回收，并删除目录中对应的目录项。

### 2.4.1. 目录的查询-检索

**概念**：
- 目录可以通过在磁盘上反复搜索完成，需要不断进行IO操作，开销大；
- 可以把 **当前使用的文件目录复制到内存**，从而降低磁盘操作次数，提高系统速度。

**实现方法**：

|              | 定义            | 优点          | 缺点          |
| ------------ | ------------- | ----------- | ----------- |
| **线性列表(*线性查找*)** | 采取线性列表存储文件目录项 | 实现简单        | 查找费时        |
| **哈希表(*散列查找*)**  | 采取哈希表存储文件目录项  | 查找迅速，插入删除简单 | 需要一些措施来避免冲突 |

## 2.5. 文件共享

**概念**：文件共享使多个用户共享同一个文件，**系统只需保留该文件的一个副本**。

### 2.5.1. 文件共享方式

|           | 基于索引节点的关系方式(*硬链接*)                                              | 基于符号链实现文件共享(*软链接*)                               |
| --------- | --------------------------------------------------------------- | ------------------------------------------------ |
| **定义**    | 硬链接就是多个指针指向一个索引节点；<br>文件的物理地址和其他文件属性信息放在索引节点中。                  | 软链接相当于重新创建一个文件；<br>新文件只包含被链接文件的路径名。              |
| **特点**    | 硬链接不可用于跨文件系统；<br>硬链接查找速度比软链接块。                                  | 软链接可跨文件系统。                                       |
| **新增文件时** | **建立硬链接时，引用计数值加1**。                                             | **符号链接，计数值直接复制**。                                |
| **删除文件时** | 删除文件时，计数值减1；<br>若得到的值不为0，则不能删除此文件；<br>**只要还有一个指针在，索引节点就不会被删除**。 | 删除操作对符号链接不可见；<br>以后再通过符号链接访问时，若发现文件不存在，直接删除符号链接。 |
| **示例**    | ![](image/4-文件管理%20-%20操作系统/基于索引节点的共享方式-硬链接.png)                | ![](image/4-文件管理%20-%20操作系统/利用符号链的共享方式-软链接.png)  |
> **注意**：快捷方式属于文件共享中的软链接。

# 三、 文件系统

## 3.1. 基本概念和目标

### 3.1.1. 概念

**文件系统**：
- OS中负责管理持久数据的子系统；
- 于文件管理有关的文件 + 被管理的文件 + 实时文件管理所需的数据结构；
文件系统需要先挂载在某个目录才可正常使用；
**文件的基本操作就是 *数据块***。

### 3.1.2. 目标

**实现对文件的基本操作**：按名存储和查找文件 + 组织成合适的结构 + 文件共享 + 文件保护 (*用户角度*)；
管理与磁盘的信息交换 + 完成逻辑结构和物理结构的变换 (*OS角度*)；
组织文件在磁盘上的存放 + 采取好的文件排放顺序和磁盘调度方法 (*OS角度*)。

### 3.1.3. 分类

**磁盘的文件系统**：直接把数据存储在磁盘中。(*如：Ext 2/3/4、XFS 等*)
**内存的文件系统**：
- 这类文件系统的数据不是存储在硬盘的，而是占用内存空间；
- 常用的 `/proc` 和 `/sys` 文件系统都属于这一类；
- 读写这类文件，实际上是读写内核中的相关数据。
**网络的文件系统**：用来访问其他计算机主机数据的文件系统。(*如：NFS、SMB 等*)

## 3.2. 文件系统的层次结构

### 3.2.1. IO控制

**设备驱动程序**：将输入的命令翻译成底层硬件的特定指令；
**中断处理程序**：利用指令使IO设备与系统交互。

### 3.2.2. 基本文件系统

向对应的设备驱动程序发送通用命令，以读取和写入磁盘的物理块；
管理内存缓冲区，保存各种文件系统，目录和数据块的缓冲。

### 3.2.3. 文件组织模块

组织文件及其逻辑块和物理块；
可以将逻辑地址转换为物理地址；
有空闲空间管理器，以追踪未分配的块，根据需要提供给文件组织模块。

### 3.2.4. 逻辑文件系统

用于管理元数据信息(*包括文件系统的所有结构，不包括文件内容*)；
管理目录结构；
通过FCB维护文件结构；
负责文件保护。

## 3.3. 文件系统的布局

### 3.3.1. 在磁盘中的结构

![555](image/4-文件管理%20-%20操作系统/文件系统布局示例.png)
- 最前面的第一个块是 **引导块**，在系统启动时用于启动引导；
- 后面紧跟着连续的块组：
	1. **超级块**：包含的是文件系统的重要信息(*如：inode 总个数、块总个数、每个块组的 inode 个数、每个块组的块个数*)；
	2. **块组描述符**：包含文件系统中各个块组的状态(*如：块组中空闲块和 inode 的数目等，每个块组都包含了文件系统中 [所有块组的组描述符信息]*)；
	3. **数据位图/inode位图**：用于表示对应的数据块或 inode 是空闲的，还是被使用中；
	4. **inode列表**：包含了块组中的所有 inode，inode 用于保存文件系统中与各个文件和目录相关的所有元数据；
	5. **数据块**：包含文件的有用数据。

### 3.3.2. 在内存中的结构

内存中维护的信息用于管理文件系统，并通过**缓存机制**加速文件访问。
这些信息在文件系统 **挂载时加载**，在 **运行期间动态更新**，并在 **卸载时释放**。

> **注意**：
>   **加载**：指的是信息从外存读入内存的过程；
>   **挂载**：指的是将一个 **文件系统(设备/分区)** 附加到操作系统的**目录树**中，使其可被用户访问；
>   **卸载**：指的是移除挂载。

**典型的内存结构**：
1. 内存中的安装表；
2. 内存中的目录结构的缓存包含最近访问目录的信息；
3. 整个*系统*的打开文件表；
4. 每个*进程*的打开文件表。

## 3.4. 空闲空间管理

类似存储管理中的空闲 [内存空间的管理](<3-内存管理 - 操作系统.md# 二、 内存管理方法>)，这里 **管理的是空闲的磁盘空间**。
常用的磁盘存储空间管理方案有：**空闲表法、空闲链表法、位示图法和成组链接法。**

### 3.4.1. 空闲表法

空闲表法属于 **[连续分配方式](<3-内存管理 - 操作系统.md## 2.2. 连续分配管理方式>)**，适用于为每个文件分配连续的存储块。

系统为 **外存中的所有空闲区维护一张空闲表**，每个空闲区对应一个表项，包含 **序号、起始盘块号和空闲盘块数** 等信息，并按起始盘块号递增顺序排列。

![400](image/4-文件管理%20-%20操作系统/空闲表法示例.png)

**盘块的分配**：分配策略与 [内存动态分区分配](<3-内存管理 - 操作系统.md### 2.2.3. 动态分区分配>) 一致，通常采用 **首次适应、最佳适应** 算法。
**盘块的回收**：回收机制与 [内存回收机制](<3-内存管理 - 操作系统.md#### （一） 回收机制>) 一致，如果空闲表的前后相邻区域在物理上连续，就合并为更大的空闲区，以减少碎片。

### 3.4.2. 空闲链表法

空闲链表法是系统 **在磁盘的每个空闲块中设置一个指针**，指向下一个磁盘空闲块，使所有的空闲物理块拉成一条空闲链表，即*磁盘的空闲块链*。

![400](image/4-文件管理%20-%20操作系统/空闲链表法示例.png)

**一个空闲块首指针指向第一个空闲块，链表最后一个空闲块中的指针标明为NULL，指示空闲块链结束。**

### 3.4.3. 位示图法

位示图是 **反映整个存储空间分配情况的数据结构**。
位示图中，用一个 **二进制位** 来反映一个物理块的分配情况：
- `1` 表示已分配；
- `0` 表示空闲。

![500](image/4-文件管理%20-%20操作系统/位示图法示例.png)
> **注意**：Linux 文件系统采用位图方式管理空闲空间，不仅用于数据块的空闲管理，还用于 `inode` 的空闲管理（*因为 `inode` 也以数组形式存储在磁盘中*）。
  位示图通常组织为 $m \times n$ 的矩阵，其中 $m \times n$ 等于*磁盘总块数*。

**优点**：占用空间小，可以保存在主存中，因此空间的分配和回收较快；
**缺点**：对于大容量的磁盘来说，要把整个位示图装入内存很耗费存储空间。

#### （一） 盘块的分配

1. 系统顺序扫描位示图，查找一个(组)值为 `0` 的二进制位；
2. 根据公式转换得到 **盘块地址**(*公式非必须记，利用枚举法可求得*)：
   $盘块号 = 行号 \times 每行二进制位数 + 列号$ 
3. 修改位示图，**将相应位置 `1`**。

#### （二） 盘块的回收

1. 将回收的盘块号转化成行号和列号：
   $行号 = 盘块号 / 每行二进制位数$ 
   $列号 = 盘块号 \% 每行二进制位数$ 
2. 修改位示图，**将相应位清 `0`**。

### 3.4.4. 成组链接法

对于大型的文件系统而言，*空闲表法和空闲链表法* 存在空闲表或空闲链表过长的问题。
为此结合 **索引分配** 的思想，将空闲块分成多个组，每个组有一个 *索引块*，用于指向下一组。

![500](image/4-文件管理%20-%20操作系统/成组链接法示例1.png)

在实现索引的基础上，加入 **栈的功能**。

![500](image/4-文件管理%20-%20操作系统/成组链接法示例2.png)

如：索引表1 中记录了第一组 *盘块的总数N* 以及 *所有的盘块号*。
同时，用一个栈保存 *所有的盘块号*，空闲盘块号数N兼做栈顶指针。

![500](image/4-文件管理%20-%20操作系统/成组链接法示例3.png)

此时，索引表2 中记录了第二组 *盘块的总数N* 以及 *所有的盘块号*。
同时，用一个栈保存 *所有的盘块号*，空闲盘块号数N兼做栈顶指针(*栈顶元素下标为`N-1`*)。

![500](image/4-文件管理%20-%20操作系统/成组链接法示例4.png)

成组链接法的本质就是 **分组 + 索引表 + 栈**。

除了最后一组外，每组的**第一个盘块用作索引块**；
记录最后一组盘块号情况的栈中，栈底指针为 `0`，用来表明盘块链的结束；
第一个索引表被称为 **空闲盘块栈**。

![500](image/4-文件管理%20-%20操作系统/成组链接法示例5.png)

> **注意**：成组链接法是 UNIX 系统中常用的空闲盘块管理方法。

#### （一） 盘块的分配

1. 检查空闲盘块号栈是否上锁，若未上锁，则从栈顶取出一个空闲盘块号，分配给用户，栈顶指针下移一格。
2. 若该盘块号已是栈底(`S.free(0)`)，说明是当前组最后一个空闲块：
	- 将该块中记录的下一组空闲盘块信息读入栈中；
	- 将该块分配出去。

#### （二） 盘块的回收

1. 将回收的盘块号压入空闲盘块号栈顶，栈中空闲块数加 1。
2. 若栈中空闲块数已达 100(组满)：
	- 将栈中全部盘块号写入待回收的盘块中；
	- 将该盘块号作为新栈底，重新开始记录下一组。
> **关键**：栈是临界资源，分配/回收时需**上锁保护**。


## 3.5. 虚拟文件系统(VFS)

**目的**：为用户程序提供了文件系统操作的统一接口，屏蔽了不同文件系统差异和操作细节。

**特性**：
- 能提高系统性能；
- 不是一种实际的文件系统；
- 只存在于内存中，不存在于任何外存空间中；
- 在系统启动时建立，在系统关闭时消亡。

**VFS的数据结构**：
- 超级块对象；
- 索引节点对象；
- 目录项对象；
- 文件对象。

## 3.6. 分区和安装

一个磁盘可划分为多个区，每个分区都可以创建单独的文件系统，每个分区都可包含不同的操作系统；
文件在使用前必须先安装(*挂载*)。
